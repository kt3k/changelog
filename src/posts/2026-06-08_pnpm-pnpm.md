### **Deterministic peer-dependent deduplication** (29a496a)
`deduplicateDepPaths` now breaks ties on dep path, not importer resolution order, when collapsing peer-suffixed variants. That removes a source of machine-dependent lockfiles and makes `pnpm dedupe --check` stable across platforms.

### **Walk-ancestor peer suffixes now preserve the full peer chain** (bafcfba)
Peer resolution no longer truncates suffixes when a walk-ancestor provider is still in progress, so nested peer IDs keep the same shape pnpm would emit. This fixes cases where the collapsed suffix changed the final depPath and could alter how peers are matched and rendered.

### **Workspace self-dependencies render as bare `link:`** (7006bfa)
A workspace package depending on itself now keeps the relative path empty instead of normalizing it to `.`. That matches pnpm's `path.relative(projectDir, projectDir) === ''` behavior and fixes incorrect `link:.` output.

### **Global virtual store toggle is now detected** (97e1982)
`enableGlobalVirtualStore` is included in workspace-state change detection, so installs no longer incorrectly report “Already up to date” after the setting flips. This forces a full reinstall when the virtual store location changes.

### **Bare `--color` no longer eats the next flag** (027196b)
CLI parsing now treats `--color` as a boolean-capable option, so it doesn't consume the following argument as a value. This fixes shorthand expansion and `pnpm --color with current <command>` dispatch.

### **Catalog snapshots now include npm-aliased deps** (55a4035)
Lockfile generation now reads aliased catalog versions via the peer-aware version accessor, so `npm:`-aliased catalog entries are no longer dropped from the `catalogs:` section. That keeps the lockfile faithful for aliased catalog dependencies.

### **`$` override references are now deprecated with a warning** (894ea6a)
Using `$`-style version references in `overrides` still works, but pnpm now warns and points users toward catalogs instead. This nudges workspace version pinning toward the newer `catalog:` flow without breaking existing configs.

### **Store and security docs were clarified** (c74d4e1, e4d2fe0)
The repo tightened its documentation around pnpm's trust boundary and the content-addressable store's integrity guarantees. This is primarily guidance, but it helps set expectations for what the project considers in-scope security issues.
