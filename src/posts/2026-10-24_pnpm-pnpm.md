### **Global installs now use the global virtual store** (0aebd66)
Global `pnpm add -g` installs now share dependencies through the global virtual store instead of forcing it off per group. The group config also re-derives its virtual store path and sets `NODE_PATH` for the group's own `node_modules`, so lifecycle scripts resolve the right hoisted deps.

### **`pnpm login` writes tokens back to `auth.ini`** (7aebc70)
Login tokens are no longer stored under the global `_auth` setting, which could accidentally redirect unrelated projects to a newly logged-in registry. The command now records credentials in `auth.ini` again and cleans up any older `_auth` entry it replaces.

### **`pnpm deploy` preserves symlinks into undeployed dependencies** (9d361bf)
Deploy now keeps internal symlinks even when their targets are not part of the deployed file set, which fixes links into `node_modules` and similar project-internal paths. That avoids silently dropping dependency links during deployment.

### **Custom pnpmfile fetchers can use the built-in directory fetcher** (506f33d)
`fetchers.directory(...)` is now wired through properly for custom fetchers, instead of failing with a `TypeError`. pnpm also rejects directory/git fetches when the lockfile pins an archive integrity, matching the intended fetcher semantics.

### **`pnpm add`/`remove`/`update` now refuse incompatible `node_modules`** (f2b319c)
Mutating commands now fail if `node_modules` was created with a different store, virtual store, linker, or incompatible layout instead of silently purging and reinstalling it. This closes a class of surprising state resets and makes `pnpm install` the explicit recovery path.

### **Resolver now prefers each project's own direct dependency range** (f8a3459)
When `autoDedupe` is off, workspace projects resolve direct deps from their own manifests rather than being constrained by other projects' narrower ranges. That fixes cases where one workspace package could unintentionally hold another back; `dedupe` and `autoDedupe` keep the broader shared behavior.

### **pnpr metrics now require an explicit metrics config** (bf878a9)
pnpr no longer exposes Prometheus metrics by default. Metrics are only mounted when configured, and can be protected with a bearer token or moved to a separate listener, reducing accidental exposure of operational data.

### **Remote libsql auth lookups now reuse connections** (9cc9587)
pnpr's remote libsql auth backend now keeps connections open instead of opening a fresh TCP/TLS connection per lookup. That should cut connection churn and improve auth lookup latency, especially against Turso.

### **pnpm and pnpr now sign with a fixed `p256`** (d35a295)
The workspace bumped `p256` to 0.14 to avoid the `crypto-bigint` 0.5 timing advisory in signing code used for shared artifacts, OCI tokens, and OIDC state. The dependency policy was updated to keep the vulnerable stack confined to read-only verification paths.
