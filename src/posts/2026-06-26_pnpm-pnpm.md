### **Rust pnpm now ships as `pnpm` and `@pnpm/exe`** (a33eeec)
The Rust port is now published under the real `pnpm` name as well as `@pnpm/exe`, with releases going out on `next-12` instead of `latest`. The release workflow and CLI metadata were updated so the new binary behaves like pnpm v12 end to end, while leaving the TypeScript v11 line on the production tag.

### **`pnpm deploy` arrives with safety checks** (f38e696)
The Rust CLI now ports pnpm’s deploy command, including workspace selection, deploy target validation, shared-lockfile output, and install-mode wiring. It also hardens `deploy --force` against unsafe destinations like workspace roots, parent directories, out-of-workspace paths, and symlinked parents.

### **Dynamic shell completion support is in** (aea6ace)
`pacquet` now exposes both static completion generation and a hidden completion server used by generated shell scripts. This enables richer, runtime-aware completion behavior instead of relying only on precomputed shell snippets.

### **`pnpm docs` / `pnpm home` can open package homepages** (6bd7ba8)
A new docs/home command fetches package metadata, validates homepage URLs, and launches them in the system browser, with a fallback to npmx.dev when no usable homepage is present. It also adds the Windows shell features needed to open the browser correctly on that platform.

### **`pnpm ping` now checks registry connectivity** (ec76ca3)
The Rust CLI gained a registry ping command that mirrors pnpm’s `/-/ping` behavior, including auth header handling and pnpm-style reporting. This is a useful low-latency diagnostic for registry reachability and auth issues.

### **Resolver config interning is now memory-capped** (de3ee84)
`pnpr`’s resolver used to leak one static config per distinct client configuration, which an authenticated caller could exploit to grow memory without bound. The new cap limits both the number and size of interned configs, turning that into a bounded resource usage issue instead of an exhaustion vector.

### **Misc packaging and lockfile correctness fixes** (8b1b537, 96da7c5, 103b99b, b98cbf8, 6beda88)
- Nested peer-group filenames now match pnpm’s `__` boundary convention.
- node-gyp’s gyp entrypoints are now packed executable so native builds can regenerate correctly.
- pacquet/pnpr binaries are now installed as native placeholders that relink on install to avoid Node startup overhead.
- Version, dependency, and workflow pins were updated, including a tighter oz-agent checkout configuration.
