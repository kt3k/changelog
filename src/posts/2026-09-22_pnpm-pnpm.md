### **`pnpm add --save-types` now saves matching `@types` packages** (3235190)
`pnpm add` can now discover and add available `@types/*` packages to `devDependencies`, with workspace-level `saveTypes: true` to enable it by default. This expands dependency authoring support while skipping packages that already bundle their own TypeScript types.

### **`pnpm install` now honors root `preinstall` before linking deps** (1d4bdd1)
The root project's `preinstall` runs before dependency resolution and linking, so guards like `npx only-allow yarn` can stop an install before `node_modules` is populated. That closes a long-standing lifecycle ordering bug and changes install behavior in a user-visible way.

### **`pnpm remove` now runs uninstall lifecycle scripts** (719f466)
Removal now triggers the project's `preuninstall`, `uninstall`, and `postuninstall` hooks in the expected order, with failures aborting the unlink step. This brings remove in line with package lifecycle expectations and can affect real project teardown logic.

### **Install and update behavior got several correctness fixes**
Multiple fixes tighten core package management behavior: optional peers are now handled correctly during removals, excluded direct dependencies are pruned even without a lockfile, frozen installs correctly tolerate unresolved optional deps, and updates preserve override semantics and range shape. These are the kinds of bugs that can silently produce wrong lockfiles or surprising dependency trees.

### **Command execution and bin resolution were hardened**
`pnpm exec`, `pnpm dlx`, and related lifecycle paths now set package-manager environment variables consistently, respect custom `modulesDir`, and avoid duplicating inherited `PATH` entries in nested scripts. Bin linking also skips redundant chmods and preserves executable source permissions, reducing permission-related failures and making custom layouts work more reliably.

### **Repository and resolver correctness improved**
`pnpm install` now fetches committed Git submodules, peer resolution handles local tarball versions and workspace build metadata more accurately, `pnpm outdated` validates selectors before querying, and `pnpm version` / `pnpm init` now recognize `package.yaml`. These fixes remove several edge-case footguns around manifests, peers, and source types.

### **macOS backup exclusions and config handling were added**
The install path can now opt newly created directories out of Time Machine on macOS, and `pnpm config set` now validates the structured `macosBackup` setting instead of accepting malformed values. This is a practical platform-specific feature with configuration safeguards.
