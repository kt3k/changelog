### **Reject invalid `overrides` values** (6d7903a)
`pnpm` now throws a clear error when `overrides` is not an object or contains non-string values. This prevents malformed config from being silently accepted and makes config mistakes easier to diagnose.

### **`pnpm dlx` now prompts for ignored builds** (f6bc1db)
`dlx`/`pnpx`/`pnx`/`pnpm create` now follow the same build-approval flow as `pnpm add -g` when transitive deps have install scripts. That avoids hard failures under the v11 `strictDepBuilds` default and lets users approve needed builds interactively instead of retrying command-by-command.

### **Restore peer-issue details on strict peer errors** (0b2f86e)
When `strictPeerDependencies: true` triggers `ERR_PNPM_PEER_DEP_ISSUES`, pnpm now renders the actual peer dependency problems inline again, using the same format as `pnpm peers check`. This makes the failure actionable in CI and for tooling like Renovate without requiring a second command.

### **Fix `pnpm -g ls --json` / `--parseable`** (72629fc)
Global listing now honors machine-readable output flags again and preserves pnpm 10-style JSON structure. It also tightens `--depth>0` behavior for isolated global installs, refusing to merge incompatible trees across multiple install dirs.

### **Respect `publishConfig.registry` in publish** (2b8932d)
Non-recursive publish now gives `package.json`'s `publishConfig.registry` precedence over configured registries. That restores the pre-v11 behavior and prevents packages from being published to the wrong registry.

### **Make WARN/error labels readable without color** (cd87c16)
Reporter output now wraps WARN and error labels in brackets so they remain visible in no-color, piped, or dumb-terminal output. It’s a UX fix, but it materially improves readability for common CLI workflows.

### **Drop the broken darwin-x64 SEA artifact** (47b100e)
The Intel macOS `@pnpm/macos-x64` / `pnpm-darwin-x64` artifact is removed because the SEA-built binary segfaults on startup due to an upstream Node bug. The release pipeline now avoids publishing a broken binary and points Intel Mac users to safer install options.

### **Release provenance attestation for artifacts** (4f52bef)
GitHub release artifacts are now signed with Sigstore-backed build provenance, making it possible to verify they came from the release workflow. That strengthens supply-chain trust for published tarballs and zips.
