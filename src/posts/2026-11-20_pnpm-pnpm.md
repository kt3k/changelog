### **`pnpm catalog migrate` lands in the CLI** (884a2d1)
Adds a new command that moves shared workspace dependency specifiers into the default catalog and rewrites them to `catalog:` when it can do so safely. This gives teams a one-shot way to normalize catalog usage across a workspace and makes the command discoverable in docs and help output.

### **`pnpm publish` now reads `access` from config, and `otp` is never file-based** (a07908a)
Publish auth/config handling got stricter and more flexible at the same time: `access` is now a real setting, while `otp` is explicitly not accepted from file-based config. That matters because it closes a config-path inconsistency and aligns publish behavior with the intended security model.

### **`pnpm dlx`/`create` are isolated from local workspace settings** (292c17b)
`dlx`, `pnx`, and `create` now ignore untrusted local workspace hooks, layout, and resolution settings while still honoring the user's global config. The same work also separates caches for script-skipping runs and improves handling of local directories, tarballs, and git/URL package specs.

### **`pnpm install` gains `--minimum-release-age` flags** (e3763af)
Two new one-off CLI flags let users set minimum release age policy for a single install, add, update, or dlx invocation. This makes the anti-supply-chain policy much easier to apply ad hoc without changing permanent config.

### **`pnpm list -g` and `pnpm why -g` now stay truly global** (ea27f0e)
Global commands are now isolated from the current directory's hooks and workspace config, and global listing no longer accidentally reads the local project's lockfile. It also fixes `why -g` so it inspects globally installed packages instead of the local workspace view.

### **`pnpm update --latest` now moves governing overrides** (172eb31)
When a dependency is pinned by an override, `update --latest` now updates the override itself instead of fighting it. This keeps the manifest and lockfile in sync and preserves the override's range shape, which is a meaningful behavior change for anyone using overrides heavily.

### **`pnpm audit` now covers tarball, git, and named-registry deps** (2b95804)
Audit and signature checks now include dependency sources that were previously skipped, so transitive tarball, `file:` tarball, git, and named-registry packages are no longer invisible to security reporting. That closes a real correctness gap in vulnerability detection.

### **`pnpr` gets serious security and cache hardening** (b81ab83)
The pnpr resolver now scopes cached verdicts by private-route footprint and invalidates them when grants change, preventing stale cached access decisions from surviving policy updates. It also tightens lockfile verification around private routes, which is a meaningful security fix for the server-side resolver.

### **`pnpr` rejects unsafe local specifiers on the server** (e39788f)
The server-side resolve endpoint now refuses to evaluate client-local `file:`, `link:`, `git+file:`, bare local paths, or escaping `workspace:` specs against the server filesystem. That prevents a whole class of accidental or malicious path confusion and falls back cleanly to local resolution when needed.

### **`pnpr` routes split-domain tarballs through registry aliases** (d7b811a)
Private registries that serve tarballs from a separate CDN/blob host now get those tarballs rewritten through the proper `/~alias/` registry route everywhere they matter: resolved lockfiles, frozen prefetch frames, and verification paths. This avoids leaking raw CDN URLs and keeps registry metadata consistent.

### **`pnpm install` now shows available-version hints again** (9650b11)
The install summary once again shows the `(<version> is available)` note for direct dependencies when pnpm can see a newer dist-tag. This is a small UX fix, but it restores a helpful signal that had regressed in v11.

### **`pnpm remove` supports glob selectors** (d87b59e)
Removal can now target dependency patterns like `*`, `?`, and negated selectors, with validation and manifest edits applied after expansion. That makes bulk dependency cleanup much more ergonomic.

### **`package.json5` edits now preserve formatting in place** (44c4f61)
Saving JSON5 manifests now rewrites only the changed values instead of reserializing the whole file. Comments, quoting style, number spellings, and surrounding layout are preserved, which is a nice quality-of-life improvement for hand-edited manifests.
