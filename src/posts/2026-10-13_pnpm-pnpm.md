### **Install no longer waits on the daily update check** (535b44b)
`pnpm install` and `pnpm add` now let the update notice run alongside the command instead of holding the install open. That avoids minutes-long stalls when the registry accepts a connection but never responds, and adds trace logging to explain why the repeat-install fast path was or wasn’t taken.

### **Store verification now overlaps resolution** (7612b22)
Store-only installs now verify packages while dependency resolution is still running, instead of doing it afterward in a separate serial phase. On large workspaces with network-backed storage, that removes a major post-resolution pause and parallelizes per-package file checks.

### **Repeat-install warm-up skips lockfile-reused subtrees** (6f25c38)
The speculative dependency-tree warm-up now avoids fetching metadata for subtrees that the existing lockfile will reuse unchanged. That trims thousands of needless registry lookups on repeat installs of large workspaces.

### **Git ref lookups are memoized for the whole install** (76d448d)
Git dependencies shared across many workspace projects now resolve their branch/tag once per install instead of once per project. This removes repeated `git ls-remote` calls and makes re-resolving installs with `linkWorkspacePackages` much faster.

### **Hoisted `link:` dependencies are fully removed on uninstall** (931d626)
Removing a `link:` dependency now also unlinks its symlink from `node_modules` when using the hoisted linker. This fixes stale links that could survive removal and keeps frozen installs from recreating deleted links.

### **Optional peers that are also dependencies now resolve correctly** (08d5424)
A package that declares something both as a dependency and an optional peer now keeps that edge instead of dropping it in some multi-path graphs. The shallowest path now decides whether it is treated as a dependency or a peer, fixing missing imports in affected installs.

### **Store index file reads no longer serialize under the shared lock** (534234a)
With `storeIndexFormat: files`, shared store-index lookups release the mutex before reading the entry file. Concurrent resolution and prefetch reads can now overlap instead of taking turns on network round trips.

### **Python resolution handles read-ahead failures correctly and faster** (40b05f5)
Python index pages and metadata are now processed in parallel, and an unreadable read-ahead page reports its own error instead of being masked by an empty cached entry. This both speeds up resolution and makes failures much more precise.
