**Login now stores tokens in config.yaml** (42156fe)
`pnpm login` and `pnpm adduser` now persist credentials in the global `config.yaml` instead of `auth.ini`, with scope routing recorded alongside them. `pnpm logout` removes both the new entries and any legacy `auth.ini` data, which makes auth state visible to `pnpm config` and aligns storage with the rest of pnpm's global config.

**Global update no longer downgrades packages or pnpm itself** (e9ab4fc)
`pnpm update -g --latest` now compares the installed version with the resolved target instead of blindly reinstalling whatever the `latest` tag points at, preventing accidental downgrades. It also stops using global update to relink pnpm itself and points users to `pnpm self-update` for that path.

**Shared-artifact protocol was generalized for tasks** (75f7a1f)
The experimental artifact payload now uses a discriminated subject instead of hard-coding package identity at the top level, so it can represent both dependency side effects and workspace task artifacts. This is a breaking protocol change: pnpr clients and servers need matching versions.

**macOS and Windows shared build artifacts are supported** (e972cb5)
Remote shared build artifacts now recognize Darwin and Windows compatibility tags, expanding artifact restoration and publishing beyond Linux. That broadens cache reuse across platforms and makes the feature practical for x64 and arm64 builders on macOS and Windows.

**Recursive `run`/`exec` can resume from persisted task state** (7a1b7b1)
`pnpm -r run` and `pnpm -r exec` now journal completed recursive tasks so `--resume-from` can skip exactly the work that already finished in a matching interrupted run. The state is versioned and guarded against stale or torn reuse, which makes resumptions much more precise than the old graph-only behavior.

**Installability checks now overlap with store prefetching** (414c4ae)
The frozen install path starts the `node --version` host probe earlier and runs it concurrently with warm-cache store reads instead of serializing the two. That cuts roughly a couple hundred milliseconds off rebuilds from an up-to-date lockfile.

**Direct dependency linking and post-build relinking got faster** (ef6e932, 986e6e2, 4b1a90e)
pnpm parallelized importer direct-dependency linking, and then trimmed two expensive relink passes that were re-walking importers even when nothing needed rebuilding. Together these changes reduce filesystem churn on large workspaces, especially warm installs and hoisted workspace-bin setups.

**Config, auth, and dlx behavior were corrected** (bdf3bd9, fc0c282, 498ba39, 8ee8c8c, 4b0d1ca, 77bcc3d, 4d28db4, 2fb1d7a, f73a1a6, 5ef5004, bd64e68, 76d2a95)
Several user-facing bugs were fixed: config auth routes no longer override declared registries, `_auth` values are decoded and re-encoded canonically, `pnpm login` only trusts scope settings from safe sources, `pnpm dlx` resolves catalog specs against the caller's workspace, JSON handling in `view/info` is fixed, OTP prompts no longer print a double colon, Windows consoles get ANSI processing, ESM pnpmfiles load correctly from mjs file URLs, symlinked modules are protected during install, bundled dependency trees are preserved, git dependencies receive patches, and install-setting flags are accepted again.
