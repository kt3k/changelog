### **Platform variants are now first-class in pack, publish, and install** (402d996, 44d8b85, 5cb819f, ee533f7, bd4bf4f, ba06009)
`pnpm pack` and `pnpm publish` now understand `publishConfig.variants`, producing and selecting per-platform archives instead of treating a package as a single tarball. The install side was updated to read supportedArchitectures as platform tags, fetch the needed variants into the store, and handle versions that ship only variants without a generic `any` archive.

### **pnpr gets variant publishing, provenance, and batch commit support** (caf8e3b, a385484, 765a67c, 710c129, 633debb, 5cb819f)
pnpr can now stage/upload variant archives from multiple machines, commit them in batch, and enforce that provenance statements name every archive a version publishes. This also includes the storage/auth plumbing needed for workload credentials and the new variant-aware release records.

### **Install and run fast paths were made variant- and record-aware** (84bf292, 50669d3, 0eae2c2, f9271d3, 2eeffc2, 8c054c8, 34e09e9, f1e6e43)
Several correctness fixes tighten how pnpm decides whether it can skip a full install: per-project lockfiles now resolve from the right root, injected workspace type peers are verified correctly, and root overrides/catalog paths stay anchored to the workspace root. The repeat-install and verify-deps gates also now rely on recorded manifests more consistently, which should reduce unnecessary filesystem reads and avoid false rejections.

### **Peer deduplication and resolver behavior got a substantive fix** (2d81350, 074578e)
Peer resolution now settles child variants before deduplication, preventing incompatible child/parent combinations from producing duplicate dependency instances. pnpm also starts warning when deduplication reuses required peer providers outside a project's declared dependency scope, giving users clearer diagnostics without changing strict install behavior.

### **pnpr’s metadata backend was simplified to SQL only** (25d0d38)
The documents metadata backend was removed, leaving SQLite/libSQL as the only metadata path. That’s a breaking architectural simplification for pnpr storage and migration flows.
