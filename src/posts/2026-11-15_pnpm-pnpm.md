### **`pnpm doctor` now catches fresh-env and link-capability issues** (c9269b7)
`pnpm doctor` no longer falsely reports write failures on fresh installs just because cache/store/bin dirs do not exist yet. It also probes whether hardlinks or reflinks work from the store into the project, which helps surface slower or unsupported filesystem setups.

### **Python add/update now preserve markers and accept direct URLs** (a7362e3)
`pnpm add` for `pypi:` deps now respects distinct PEP 508 environment markers instead of overwriting unrelated entries, and it can accept direct URL requirements like `pypi:pkg @ https://...`. Shared-workspace `pnpm update` also gets smarter about updating member manifests and the shared `pylock.toml` when there is no root `[project]` table.

### **`pnpm ci` validates earlier and `clean` respects filters and lockfile dirs** (e159677)
`pnpm ci` now checks lockfile validity before removing `node_modules`, avoiding destructive cleanup when the install state is already broken. The cleanup path also honors workspace filters and custom lockfile locations, and it can remove root `node_modules` even in workspaces without a root `package.json`.

### **CLI parsing got more consistent across `pm`, `with current`, and `create`** (a67df14)
The pre-command argv scanner now shares boundary rules across more entry points, so `pnpm pm` works after flags like `--dir` and `pnpm with current` accepts subcommand-style boolean flags. `pnpm create` also forwards flags that appear after the starter name instead of swallowing them.

### **`pnpm list` preserves aliased local file refs** (9b98c36)
`pnpm list` and `pnpm list --json` now keep full `<name>@file:<path>` references for aliased local directory deps instead of collapsing them into bare `file:` paths. That fixes spurious `npm:` prefixes and keeps parseable output aligned with the actual dependency identity.

### **`pnpm update -g --latest` and `pnpm env` got runtime/version fixes** (0de359e)
Global updates now upgrade `node`, `deno`, `bun`, and `npm:`-aliased packages across major versions, and `pnpm env` accepts Node specifiers with a leading `v`, including prereleases. Hook validation also got stricter, so bad `.pnpmfile.cjs` returns now fail loudly instead of being silently ignored.

### **`pnpm deploy --prod` now works with pruned v13 peer keys** (4e6aa3d)
Deploying from a pruned experimental v13 lockfile now rebuilds peer keys before the round-trip guard runs, which fixes production deploys when an optional peer is only provided by dev dependencies. The deployed lockfile now normalizes correctly instead of failing validation.

### **JSON/parseable commands keep stdout clean** (58563aa)
Several structured-output commands now route warnings and progress to stderr so JSON and parseable stdout stay machine-readable. This covers `stage --json`, `pipeline --dry-run --json`, `outdated --json`, and related reporting paths.

### Other misc changes
- Moved repo config and style files into `.config/`.
- Updated docs to point at the new config locations.
- Released `get-pnpm` 0.0.12 and associated changesets.
- Updated dependencies, Node.js, pnpm, and GitHub Actions.
- Fixed cargo manifest lints and related workspace metadata.
- Adjusted release automation so GitHub "Latest" tracks npm `latest`.
