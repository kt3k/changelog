### **pnpm-style visual reporter lands as the default** (2b81344)
Pacquet now ships a new `pacquet-default-reporter` and makes it the default output mode, aiming to match pnpm’s install/add/update/remove terminal UI: live progress, package diffs, lifecycle logs, and the final `Done in ...` footer. The fast-path install flow was also updated so the footer still appears when an install exits early.

### **`add <name>@<spec>` now records a resolved version, not the raw spec** (25ba90e)
Adding an explicit version/range now resolves to a concrete version and writes the correct saved range/operator into `package.json`, matching pnpm’s behavior instead of preserving the input verbatim. This fixes cases like explicit ranges, dist-tags, re-adding existing deps, npm aliases, and non-registry specifiers.

### **Warm reinstalls now restore cached side effects** (214bd1a)
A warm `sideEffectsCache` reinstall now reapplies the cached added/deleted overlay instead of only materializing the pristine tarball contents. That preserves build outputs created by lifecycle scripts on packages approved via `allowBuilds`, preventing broken reinstalls after cache hits.

### **`add` preserves existing ranges when re-adding an existing dep** (b6826b7)
Re-adding a dependency without an explicit version no longer rewrites its manifest entry to a newly fetched latest version. The existing specifier is now kept intact, which avoids silently changing declared ranges during routine re-adds.

### **`update --latest` keeps catalog references and updates catalog entries** (62bb228)
Catalog-backed dependencies are now handled consistently across catalog modes: `--latest` keeps the `catalog:` reference in `package.json` and bumps the workspace catalog entry instead of overwriting the manifest with a direct version. That preserves catalog-driven dependency management while still advancing the resolved version.

### **Partial virtual-store directories are now repaired instead of skipped** (3d610e6)
Imports no longer treat a leftover directory as complete just because it exists. Pacquet now checks for the completion marker and, if it’s missing, re-runs the non-destructive import so interrupted virtual-store entries can be healed.

### **`update --latest` preserves the existing semver operator** (f659ee4)
`pnpm update --latest` semantics are now mirrored more closely: a tilde stays a tilde, an exact pin stays exact, and only specifiers without a recoverable pin fall back to the configured default operator. This prevents `--latest` from widening ranges unexpectedly.

### **`--save-prefix` support added to `pacquet add`** (826f213)
The add command now supports `--save-prefix`, letting users choose `^`, `~`, or an exact pin for newly added dependencies. This also consolidates prefix handling with `--save-exact`, matching pnpm’s pinned-version logic.

### **Catalog update policy is preserved for named catalogs** (29ab905)
A version-like catalog name no longer causes `pnpm update` to misread the catalog reference as a pinned version and override the range policy. The catalog entry’s own prefix is now preserved, fixing incorrect update behavior for named catalogs.

### **Support for WSL Windows binaries in sh shims** (cd8348c)
Shell shims were updated to better handle Windows-native executables from Cygwin/MSYS/WSL2 environments, including `basedir_win` handling and runtime-specific `/C` fallback behavior. This should make generated shims more reliable across mixed Windows shell setups.
