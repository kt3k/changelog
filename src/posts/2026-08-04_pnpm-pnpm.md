### **Install pipeline split into dedicated phases** (74bf5dd)
`package-manager`’s install implementation was decomposed into focused internal modules for orchestration, lockfile freshness, materialization, lifecycle execution, modules-state handling, and workspace-state updates. This is a large maintainability refactor that reduces the size and coupling of the old monolith without changing install behavior.

### **Headless installs now inherit the correct hoisted bins** (df3a09a)
A `--frozen-lockfile` install now creates command shims for publicly hoisted workspace package bins, matching the normal install path. The same work also fixes a correctness edge where a stray non-directory entry in `node_modules` could fail an install instead of being skipped.

### **Directory `file:` dependencies are recopied when sources change** (a540b24)
`file:` dependencies are copied into the store rather than symlinked, and this patch fixes installs that were incorrectly treating an unchanged lockfile as proof that a mutable source tree was still current. The result is that editing a local directory dependency and rerunning install now refreshes the copied contents as expected.

### **`pnpm fetch` and virtual-store-only installs stop writing `.pnp.cjs`** (d4a9248)
When `nodeLinker: pnp` is configured, fetch-style and `virtualStoreOnly` installs now avoid emitting a project-level PnP loader. That keeps these no-link installs from claiming the project resolves through a loader even though they only populate the virtual store.

### **Fresh install path split into phase modules** (3fb4ea7)
`InstallWithFreshLockfile::run` was broken into smaller internal modules for setup, resolution, linking, and materialization. This is another big readability and code-organization refactor, and it also aligns the frozen and fresh install paths more closely.

### **Frozen install code extracted into a dedicated crate** (e719786)
The frozen-lockfile installer and its shared dependency-prep primitives moved into a new internal `pacquet-deps-restorer` crate. That reduces churn in `package-manager` and makes the shared install machinery reusable across install modes.

### **Store-index helpers centralized** (0238477)
Shared store-index open/drain logic was moved into `pacquet-store-dir`, replacing repeated call-site plumbing. This is mostly an internal cleanup, but it trims duplicated setup/teardown code across install paths.
