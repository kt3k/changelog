### **Config flags now reliably win over pnpmfile hooks** (2604b6f)
Command-line settings such as `--registry`, `--store-dir`, and dotted `--config.<key>=<value>` overrides now take precedence over `updateConfig` hooks in `.pnpmfile.cjs`. This closes a class of cases where explicit user input could be silently rewritten or dropped.

### **`pnpm run` now passes Windows script args correctly** (266cbd9)
On Windows, arguments after the script name are now quoted so `cmd` does not expand `%VAR%` or mangle backslashes before they reach the target process. This fixes long-standing script-arg corruption and makes the printed command line consistent across platforms.

### **Offline installs now choose versions actually present in the store** (9e5b64b)
`pnpm install --offline` and `pnpm add --offline` now resolve a range to the newest matching version whose tarball is already stored locally, instead of picking a newer metadata entry and failing. That makes offline installs far more reliable when the cache and metadata are out of sync.

### **Shared-store permissions are preserved instead of being weakened** (91ff168)
Files and directories created in a shared store now keep group-write and setgid behavior, and existing store ownership/mode are left intact. This fixes multi-user stores where the next user could previously lose write access to new shards or `index.db` sidecars.

### **Scripts now see `npm_command`, matching npm and pnpm 11** (9468af1)
Lifecycle scripts regain the `npm_command` environment variable, with values that match npm's command naming rules. Tools that branch on this variable will now take the same path under pnpm 12 as they did under npm and pnpm 11.

### **Injected dependencies now update while scripts are running** (1cb40c7)
When `syncInjectedDepsAfterScripts` is enabled, edits are copied into injected packages during the script run instead of only after it exits. That lets watchers and dev servers observe source changes immediately, which is the behavior users expect for HMR-style workflows.

### **`pnpm add ../pkg` now warns when peers will be unresolved** (2ed46d4)
Adding a local directory as `link:` now emits the same peer-dependency warning that `pnpm link` already produced. The warning steers users toward `file:` when they actually need peers resolved from the project they are installing into.

### **`pnpm run` no longer drops `dependsOn` for RegExp task selectors** (01e7232)
Recursive runs that select tasks with a RegExp now seed one task per matched script, so each task inherits its own `dependsOn` graph. This fixes missing prerequisite execution in task pipelines that select multiple scripts by pattern.

### **Side-effects cache now restores symlinks created by builds** (511d68a)
Build outputs that include symlinks are now cached and restored as symlinks instead of being flattened into copies of their targets. pnpm will rebuild packages once after upgrading, but warm installs should preserve these outputs going forward.

### **Global package migration moved to `update -g`** (4c2ee96)
pnpm can now migrate legacy global layouts during `pnpm update --global`, including removing the old directory and old pnpm 10 bins. This keeps the migration tied to an explicit global-package operation instead of an unattended setup path.

### Other misc changes
- Fixed `pnpx --version` / `dlx` option handling and version reporting.
- More resolver fixes: peer range intersection, release-age checks, locked-manifest handling, and cause preservation.
- Workspace/install fixes around dot-directory pruning, hoisted repeat installs, filtered installs, publish layout, and Windows env-path expansion.
- Several store, publish, and CI/test-only adjustments, plus dependency/version pin bumps and docs/chore updates.
