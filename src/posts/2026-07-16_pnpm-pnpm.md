### **`pnpm add` now installs multiple selectors in one go** (27646a0)
`pnpm add` previously forwarded only the first package selector; it now carries the full selector list through regular, global, and config-dependency flows. The fix also validates all `--config` selectors before any install state is initialized, preventing partial filesystem changes on invalid input.

### **Native `pnpm owner`/`owners` command lands in Rust** (b0456c6)
A full Rust implementation of the registry owner management command is now wired into the CLI, including `ls`/`list`/`add`/`rm`, `--otp`, scoped registry resolution, and auth handling. This replaces a gap in the native CLI and brings parity with the TypeScript path.

### **Fresh installs now enforce engine constraints correctly** (33532b6)
Fresh isolated installs now apply strict engine validation to required dependencies as well, instead of only checking packages with optional/platform constraints. That closes a loophole where incompatible `engines.node` ranges could slip through under `engineStrict`.

### **Strict minimumReleaseAge can now prompt for approval** (1f5a097)
The install flow now mirrors the interactive approval path from the TS CLI: immature packages can be approved, excluded versions are persisted before writes begin, and noninteractive installs still fail closed with the full violation list. The reporter was also updated so prompts don't get overwritten by live progress output.

### **Workspace installs now detect stale importer manifests** (d8dfa85)
Frozen and prefer-frozen installs now compare every workspace project manifest against its matching lockfile importer before proceeding. That makes stale workspace members fail fast instead of being silently accepted, and normal installs will refresh them when they drift.

### **Self-update verifies the installed pnpm actually runs** (f15d67c)
`pnpm self-update` now executes the newly installed CLI before switching it into place, discarding releases that install successfully but cannot run. This prevents a broken download from replacing a working pnpm and leaving the user stranded.

### **Version switching rejects known-broken releases too** (e4d7a4a)
The same broken-release guard used by self-update is now applied when switching CLI versions from `packageManager` or `devEngines.packageManager`. That means a bad pinned release fails with a targeted error before the installer ever takes over.

### **Release notes now come from pending changelog data** (6d2030e)
The GitHub release workflow now generates notes from the pending registry-mode changelog rather than the committed `CHANGELOG.md`, and it creates draft releases first so the published body can be verified exactly. If generation fails, it writes a diagnostic fallback body with a workflow link instead of blocking publication.

### **In-flight npm metadata is now shared across callers** (94bc420)
Concurrent metadata fetches now keep the raw response body available to every caller sharing the in-flight request, avoiding repeated re-serialization and a cold-cache memory spike. The memoization logic was also tightened so cache clearing and retry races can't resurrect stale entries.

### Other misc changes
- User-facing CLI text now says `pnpm` instead of the internal `pacquet` name (3 commits)
- `.modules.yaml` now records the correct `pnpm@<release>` packageManager string (1 commit)
- CI/release workflow and tarball packaging tweaks (3 commits)
- Comment/test-only lockfile freshness note fix (1 commit)
