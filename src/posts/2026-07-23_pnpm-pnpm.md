### **Native `pnpm ci` lands in Rust** (3b1c181)
`ci` is now implemented in the Rust CLI, matching the TypeScript clean-install flow: it runs a clean step first, then performs a frozen-lockfile install. The command adds native aliases and completion support, bringing parity for a core install path.

### **GitHub Actions update checks are now configurable and opt-in** (80c4162)
`outdated` and `update` can now target a non-GitHub.com server via `update.githubActionsServer`, defaulting to `GITHUB_SERVER_URL` or `https://github.com`. Failures to read refs for individual actions no longer abort the command; they’re skipped with warnings, and GitHub Actions checking is now gated by explicit opt-in.

### **`pnpm update --latest` now handles `npm:` aliases correctly** (d07810f)
Update-latest previously resolved alias names themselves on the registry, which broke catalog entries and direct `npm:` aliases when the alias package name didn’t exist. The fix preserves the alias prefix while resolving the underlying package, so alias-based dependencies can be bumped safely.

### **`pnpm publish` retries provenance signing and honors fetch timeouts** (cb68cb0)
The provenance signing flow now retries transient sigstore failures and is bounded by the configured fetch timeout. This prevents one dropped signing request from failing an otherwise successful publish run.

### **`pnpm unpublish` is implemented natively** (b75b579)
The CLI now supports unpublishing packages and specific version ranges from the registry, including the full unpublish flow that requires `--force`. The implementation handles packument updates, dist-tag cleanup, and error mapping, making a previously missing command available in pacquet.

### **`pnpm version` gains `from-git` support** (2c6d294)
Versioning can now derive the next version from the latest matching Git tag, while respecting `tag-version-prefix`. This closes a notable gap in release tooling parity.

### **Web auth is hardened against malicious registries** (62236cb)
The token poll no longer reads large or unnecessary response bodies, capping reads at 64 KiB and skipping bodies for pending/error responses. QR-code generation failures also become non-fatal, falling back to showing the login URL so authentication can continue.

### **Workspace package payload verification is restored and tightened** (a1ae5b8, 77cd515, 5819fc6, d1d53e4, 6fb1095)
Release now verifies packed package payloads before publish, builds only publishable projects for that check, and removes older bundling workarounds that were masking packing regressions. The packing logic itself was also fixed so `files` allowlists override workspace-root ignore rules, preventing nearly-empty tarballs from slipping out again.

### **`pnpm add` gets more CLI parity** (842f6d5)
`add` now accepts `--allow-build`, `--registry` is accepted globally, and `--dir` / `-C` is position-independent. The new allow-build handling also rejects attempts to override packages explicitly blocked by the root workspace config.

### **`pnpm install --no-runtime` works on fresh installs** (aacdcee)
Fresh installs now honor `--no-runtime` instead of rejecting the command when no lockfile is present. This fixes a real setup-action parity gap that previously broke workspace bootstrapping.

### **Other misc changes**
- GitHub triage workflow now times out hung Oz runs after 20 minutes instead of waiting 6 hours.
- Update-lockfile workflow switched to the `pnpm/update` action.
- GitHub Actions dependency checks became fully opt-in in interactive update flows.
- Fixes for colored `outdated` table alignment, pnpr catalog resolution, and workspace/link/file update-latest behavior.
- Release prep and dependency bumps, including pnpm v12 alpha 20 and pacquet 12.0.0-alpha.19.
