### **Security: block rebuild path traversal from lockfile names** (bc57f40)
`pnpm rebuild` now rejects lockfile package names that contain traversal segments instead of joining them into a path outside the virtual store. This closes the reported escape vector and fails with `ERR_PNPM_INVALID_DEPENDENCY_NAME` before lifecycle scripts or bin linking can run.

### **Fix: read CRLF or BOM-prefixed combined lockfiles** (ee3bb4b)
Lockfile loading now normalizes combined YAML more robustly so Windows checkouts with CRLF or a UTF-8 BOM no longer trigger `multiple YAML documents detected`. That prevents `pnpm install` from discarding a valid lockfile and re-resolving dependencies from the registry.

### **Fix: stop pinning `@pnpm/exe` for pnpm v12 env installs** (51b43ed)
The env installer now only pins `pnpm` for version 12+ instead of trying to resolve `@pnpm/exe`, which is no longer published for those releases. The engine identity check was updated to verify whichever package actually ships the native binary, restoring meaningful verification.

### **Fix: proxy config now treats empty values as unset** (88728f1)
Empty proxy settings from `.npmrc`, workspace YAML, env vars, or CLI input no longer abort installs with `ERR_PNPM_INVALID_PROXY`. This also fixes precedence so an empty high-priority proxy value no longer masks lower-priority settings.

### **Fix: login/adduser honor configured scope** (37b387f)
`pnpm login` and `pnpm adduser` now read `scope` from workspace and global config as well as `PNPM_CONFIG_SCOPE`, not just `--scope`. That brings the Rust CLI in line with pnpm’s config resolution and ensures tokens are keyed to the intended scope.

### **Fix: make release tags signed and verifiable** (290bb5b)
The release pipeline was reworked to require signed annotated tags instead of lightweight CI-created tags. This restores `git verify-tag` compatibility for downstream builders and adds explicit guidance for maintainer-signed release tagging.
