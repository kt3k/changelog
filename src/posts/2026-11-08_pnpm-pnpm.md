### **Shell completion now returns paths for value-taking options** (4090815)
pnpm’s tab completion now recognizes path-valued options like `-C/--dir`, `--prefix`, `--store-dir`, `--state-dir`, `--env-file`, `--npmrc-auth-file`, and `--registry` instead of suggesting subcommands or shell names. The completion engine now tracks the pending argument more precisely and uses clap’s value hints so file and directory options complete as paths.

### **`pnpm store add` can ingest tarball directories and runs faster** (4936c98)
`pnpm store add` now accepts directories and recursively adds local `.tgz`, `.tar.gz`, and `.tar` files inside them. The ingest path was also reworked to reduce repeated archive reads and process additions concurrently, which should noticeably improve bulk local-tarball workflows.

### **pnpr gains shared SQL schema migration plumbing for metadata and auth** (6d1bf4e)
pnpr now uses a single forward-only migration system and shared `schema_migrations` tracking for both metadata and auth databases. The SQL adapter layer moved into `pnpr-sql`, consolidating schema management across the storage and auth stacks and setting up support for shared database backends.

### **pnpr adds PostgreSQL and MySQL metadata databases** (dad931d)
pnpr can now store package metadata in PostgreSQL and MySQL, not just its existing backend set. This is a major expansion of the storage layer, with per-dialect schema checks, transactional behavior, and dedicated CI coverage to keep the new database backends honest.

### **pnpr fixes deadline handling and MySQL auth compatibility** (9e44e87)
This tightens startup/request deadline handling in the SQL backends and fixes MySQL-backed auth behavior around case-sensitive usernames. It also improves connection and initialization flow so schema setup and request execution don’t interfere with each other’s timeouts.

### **pnpr invalidates OCI publish replay after manifest deletion** (96a5de4)
Deleting an OCI manifest by digest now invalidates saved batch-publish outcomes that include it, while tag-only deletions still replay normally. That closes a consistency gap where deleted manifests could keep replaying from cached publication results.

### **pnpr unifies metadata timestamps around the application clock** (29af70b)
Metadata writes now use one timestamp path based on the application clock across publications, notes, tags, blobs, reclaims, and related records. This removes a bunch of ad hoc timestamp handling and makes storage behavior more consistent across backends.

### **pnpr keeps cyclic peer variants distinct across projects** (91df94e)
When cyclic peer dependencies collapse to a shared dep path, pnpm now preserves project-specific variants instead of merging them across workspace projects. That prevents one project from inheriting peer resolution state that only existed in another project.

### **pnpr trims unused metadata indexes and note history** (c7ff639)
Unused metadata indexes were removed, along with note history writes that no reader consumed. The schema is slimmer and write paths are cheaper, while the old history data is deferred until there’s a defined retention story.

### **pnpr indexes publication outcomes by commit time** (e8d9e2c)
`publication_outcomes` now has an index on `committed_at`, making the retention sweep use a range scan instead of a full-table scan under the write lock. That should reduce contention during cleanup and improve retention performance.

### Other misc changes
- Fixed UTF-8 BOM handling in ignore-file parsing.
- pnpr now preserves scoped URLs in logs.
- pnpr now drops foreign key constraints from its metadata schema.
- pnpm records a hoisted project’s `modulesDir` correctly.
- pnpr server tests now capture logged errors; one conformance test was limited to SQLite.
- Misc CI/build/test updates and docs tweaks.
