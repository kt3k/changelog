### **Process lifetime now matches command semantics** (d25d8c8)
pnpm’s script/execution process handling was reworked so children outlive pnpm only when they would also outlive the same command run without pnpm. The update also changes bail/interrupt behavior across Unix and Windows, which is a significant behavioral contract shift for exec and recursive runs.

### **`workspace:` and `link:` dependencies are relinked when missing** (39bb7b9)
A repeat install no longer treats a deleted direct link as healthy, so `pnpm install` will relink missing workspace dependencies instead of reporting “Already up to date.” This fixes a real correctness hole where the lockfile and workspace state stayed fresh even though `node_modules` was broken.

### **Repeat-install now notices hook-added and injected local deps** (bcf44db)
The repeat-install freshness check now records local tarballs/directories introduced by `readPackage` hooks and injected dependencies, so edits to those inputs invalidate the fast path. That prevents stale lockfiles and “already up to date” false positives for projects whose manifests are augmented at install time.

### **Node `latest` now prefers the newest stable release** (4cb926c)
The Node runtime resolver now resolves `latest` to the newest stable version in the index instead of blindly taking the first entry. On prerelease-only mirrors it still falls back to the first entry, preserving nightly/rc resolution.

### **`.cmd` shims now work when MSYS path conversion is disabled** (253a95e)
The Windows shell shim no longer depends on MSYS rewriting `//C` back into `/C`, which fixed `.cmd`/`.bat` binaries hanging in an interactive cmd prompt under Git Bash/Cygwin with path conversion off. It also propagates the necessary MSYS exclusion so the switch reaches `cmd.exe` intact.

### **`pnpm --env-file` now matches Node’s parser behavior** (1264fc0)
pnpm switched from `dotenvy` to Node-compatible parsing for `--env-file`, so values are no longer expanded, invalid content is accepted the same way Node does, and the feature behaves much closer to `node --env-file`. That makes environment-file support more predictable and compatible for real-world configs.

### **Global virtual store hashes dependency cycles as a unit** (710a831)
A dependency-cycle member changing now causes the whole cycle to move to new virtual-store slots, preventing mixed old/new copies of the same package from being loaded. This is a correctness fix for a subtle cache/layout bug in the global virtual store.

### **Outdated/update now include runtime and package manager deps** (436fbed)
`pnpm outdated` and `pnpm update` gained support for runtime and package-manager dependencies declared in engine-like fields, expanding what the CLI can inspect and update. This is a broad feature addition touching resolver wiring and manifest handling.

### **`gitTagVersion` is honored again for `pnpm version`** (1aeca4f)
Versioning now respects the `gitTagVersion` setting, so disabling it stops pnpm from creating the commit and tag. That restores parity with pnpm 11 and fixes a behavior regression in v12.

### **`supportedArchitectures` no longer suppresses the host pnpm binary** (1e40188)
Engine install now always considers the host’s `@pnpm/exe` when installing pnpm itself, even if the project targets other platforms. This avoids falling back to the currently running pnpm version when a pinned one is available.

### **TLS settings flags and parse errors are accepted correctly** (cdb74a3)
The config parser now accepts TLS-related CLI flags and handles their parse errors properly. This is a smaller but user-visible config correctness fix.
