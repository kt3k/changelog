### **Pacquet gains runtime resolvers for Node, Deno, and Bun** (df990fd)
Ported the runtime version resolvers and their shared SHASUMS helper into pacquet, then wired them into the default resolver chain. This lets `node@runtime:…`, `deno@runtime:…`, and `bun@runtime:…` resolve through pacquet the same way they already do in pnpm.

### **Peer-dependency auto-install now mirrors pnpm** (ee8fd0d)
Replaced the placeholder peer-folding behavior with pnpm's `hoistPeers` algorithm, so missing required peers are hoisted to the importer's direct deps and re-resolved until the graph stabilizes. This is a substantial correctness fix for installs with peer dependencies, and it also adds the preferred-versions machinery that guides optional-peer selection.

### **Named registries are now part of the install chain** (e2791ab)
Pacquet now understands `<alias>:` registry specifiers from `namedRegistries` in workspace config, including proper parsing and routing for scoped and unscoped alias targets. That enables packages like private GitHub/Nexus-style aliases to resolve against the intended registry instead of falling back to defaults or leaking the local scope.

### **Lockfile reader now accepts non-semver version slots** (998ea4c)
The lockfile parser now tolerates version slots that are URLs or git refs instead of rejecting anything that isn't semver or `file:`. That fixes a class of lockfiles that pacquet previously couldn't read at all, including tarball and git-based dependencies.

### **Patching no longer mutates the shared store** (4b25d60)
Fixed patch application so concurrent snapshots don't corrupt each other when they hardlink or reflink the same store file. This prevents spurious patch failures during install and makes patched-package handling safe under shared-content store layouts.

### **Local path resolution is now wired into installs** (a8a8cbc)
Ported pnpm's local resolver for `file:`, `link:`, and workspace-style path specs and added it to the install chain. This closes a major gap for filesystem-based dependencies, including the subtle handling around absolute paths and injected directories.

### **Tarball URL resolution is now supported** (606ff8f)
Added a tarball resolver that claims `http://` and `https://` specs, normalizes and preflights redirects, and preserves immutable redirected URLs in the resolution. This brings direct URL dependencies into the pacquet install flow.

### **Git dependency resolution is now supported** (35d5440)
Ported pnpm's git resolver and connected it to installs, covering hosted shortcuts and full `git+ssh`, `git+https`, and `ssh` forms. It resolves refs via `git ls-remote` so git dependencies can be pinned to commits and installed reliably.

### **Peer graph resolution stage landed** (a1f91e1)
Introduced a dedicated peer-resolution stage and the new dep-path helpers it needs, replacing flat `(name, version)` keying with depPath-based graph tracking. This is foundational plumbing for correct peer-aware virtual store layout and install ordering.

### **JSR specifiers now resolve through npm resolver plumbing** (f807f6d)
Added a JSR specifier parser and wired it into the npm resolver so `jsr:` dependencies can be recognized and resolved with pnpm-compatible errors. This expands the set of package specifiers pacquet can handle without falling back to unknown-input failures.

### **Virtual store dirnames are shortened to avoid ENAMETOOLONG** (c068720)
Fixed pacquet's virtual-store naming so peer-heavy packages no longer exceed filesystem filename limits on platforms like macOS. This prevents installs from failing before unpacking when dep-path names get too long.

### **Install path now handles pre-resolved registry results correctly** (097983f)
The npm install path was adjusted to rely on structured `name@version` resolution data, which avoids ambiguity when converting a resolution into virtual-store layout. This was part of the larger resolver refactor, but it also closes a correctness hole in package-from-registry handling.
