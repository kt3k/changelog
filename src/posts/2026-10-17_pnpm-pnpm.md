### **pnpr now blocks reserved usernames and adds auth schema migrations** (6737c4a, 0ee3439)
Self-registration now rejects reserved admin, OIDC, and workload-binding usernames, closing a privilege-squatting gap and adding an admin bootstrap path. pnpr’s auth store also gained schema version tracking, migrations, token scope/kind support, and MySQL-specific case handling.

### **pnpm can install tar registries with zstd content coding** (8b69106)
pnpm now handles tarball responses from tar registries over zstd as well as gzip, including decoding, hashing the decoded body, and the registry-specific URL shape. This unblocks installs from pnpr-backed tar registries and adds dedicated coverage for the new path.

### **Peer and injected-package lockfile handling was tightened** (0133bee, cf4b620, 5856d37, 5b68320, 13d7ca3)
Several fixes make lockfiles and freshness checks agree with the resolver for peers, injected workspace packages, remote tarball deps, and workspace-relative overrides. Together they prevent frozen installs from missing bound peers, misreading injected children, or resolving `workspace:` overrides from the wrong base.

### **pnpm’s dependency-status checks now use content digests** (9204d64, 1124edb, 086165d)
The verify-deps / repeat-install path now records what each install actually proved, so edited manifests, lockfiles, and patch files are caught even when mtimes don’t change. It also fixes the filtered-install edge cases where later `run`/`exec` commands could skip reinstalling or miss projects that were left out earlier.

### **The npm resolver got a major metadata-cache and release-age cleanup** (c8353ae, b27ec88, 474df98, 06afcf6, 7ece06e, 4636eac)
Metadata fetching and mirror policy were consolidated so release-age upgrades, revalidation, and cache writes follow one shared policy instead of several copies. That reduces duplicate requests, fixes stale/incorrect mirror behavior, and aligns the stable-range shortcuts with pnpm v12 semantics.

### **Workspace installs and pnpmfile execution were brought into line** (2c01cc5, cf6770e, 7151c3e, 5306455, 753896e, a4414d8, c79f475)
Dedicated workspace installs are now bounded and faster, while per-project installs with their own lockfiles correctly run the workspace root pnpmfile too. The resolver and lockfile code also saw broad refactors to centralize peer handling, cache-hit logic, and mirror-routing decisions with no intended behavior change.

### **pnpm’s pre-command/version/pin flow was reworked** (00deeb1, 1c8f75b, 4255419, 94d5ca6, cef4179, 906a16a, 2bdf8de)
The CLI now decides pnpm switching from only the settings that matter, reads bootstrap flags through a clap-derived path, and uses the same pin lookup for `self-update` and version reporting. It also fixes trust-policy handling for pinned versions and avoids recording a pin when nothing actually switched.

### **pnpr’s production config and deployment docs were expanded** (198cc7f, 157994e, 6beecb0, 9d3b6c5, 1fcbf30)
pnpr gained a production-safe default config, Docker Alpine images, and much fuller deployment/auth docs, including reverse proxy, TLS, webhooks, and lifecycle guidance. OIDC token exchange also now preserves registry path prefixes during publishing and dist-tag operations.
