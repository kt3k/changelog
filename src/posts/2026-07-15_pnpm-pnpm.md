### **Release workflow now verifies tarballs before publish** (124f2a5)
pnpm’s release pipeline adds a dedicated verification job that packs every release artifact, checks declared payload files against the built sources, and smoke-tests the shipped CLIs before the trusted-publishing step runs. This reduces the risk of publishing broken tarballs or missing native/executable payloads.

### **Windows junction and symlink handling got tougher** (c7060ba, 7f57469, 0f19557, aef537b)
Multiple filesystem fixes landed for Windows installs: concurrent junction creation is now safer under contention, dangling parent junctions are repaired before linking, and cached store `links/` reparse points are no longer restored from CI cache. A follow-up refactor flattened the junction-creation logic into smaller helpers, making the recovery paths clearer and easier to maintain.

### **`pnpm clean`/`purge` shipped in Rust** (d02da20)
A new native implementation of `clean` and `purge` arrived with workspace support, optional lockfile removal, and protection against deleting virtual-store directories outside the project root. That’s a real user-facing command addition, not just an internal rewrite.

### **Native setup and global add behavior was fixed** (43be121)
`pnpm setup` now installs the native CLI globally correctly by propagating script flags through the add pipeline and resolving aliasless `file:` directories to the package name before global install. This unblocks the bootstrap flow for native CLI users.

### **Packlist/tarball output now matches npm more closely** (d768a84, 4c3d0ed, 9685e3a)
`pnpm pack`/`publish` fixed ignore-file precedence when `files` is set, preventing empty or missing platform-package tarballs, and `@pnpm/exe` metadata links were corrected after the repo reorg. These changes directly affect published package contents and correctness.

### **Reporter prompts stay visible during installs** (d919e52)
The default reporter now pauses redraws while interactive approval prompts are open, instead of erasing the question mid-install. That fixes a real usability bug where users could get stuck on an invisible prompt.
