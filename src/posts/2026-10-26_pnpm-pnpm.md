**Install now re-resolves scope-routed packages when registries move** (4f83ee2)
`pnpm install` now records which registry routes were used to resolve the lockfile and uses that state to decide when plain lockfile keys need a fresh resolve. This fixes cases where a scope is rerouted to a different registry and pnpm would otherwise reuse stale versions or integrity from the old registry.

**Store prune now preserves packages a project still uses** (a582bb1)
`pnpm store prune` now looks at installed lockfiles and keeps store files for packages that were copied or cloned into `node_modules`, including patched and built packages. That prevents prune from deleting content a later install would otherwise need to redownload.

**Workspace bin shims are now removed when bins disappear** (c8590fc)
Installs now track which workspace bin commands were linked and remove stale `.bin` shims when a package renames or drops a `bin` entry. This fixes lingering commands in dependent projects and at the workspace root under hoisted workspace package setups.

**Repeat-install now records more settings that affect reuse** (740a49c)
The repeat-install fast path now accounts for additional install-shaping settings such as `virtualStoreDirMaxLength`, `dangerouslyAllowAllBuilds`, `trustLockfile`, and `globalVirtualStoreDir`. That closes gaps where the fast path could incorrectly reuse state after a settings change.

**Filtered installs now refuse layout drift instead of breaking skipped projects** (96513c9)
A filtered install no longer recreates `node_modules` when the current layout differs from what was installed, because that could strand unselected workspace projects without dependencies. The command now fails with a modules-breaking-change error unless the whole workspace is installed.

**pnpm bootstrap and Corepack downloads now honor pnpm proxy config** (3b71594)
The self-update and pinned-binary download flows now read proxy settings from the same pnpm config layers as regular registry traffic, including global `config.yaml`, `PNPM_CONFIG_*`, and user `.npmrc`. This fixes bootstrap/download behavior in environments where proxy settings were previously ignored.

**Worker pools now respect container CPU quotas** (316ec14)
`pnpm install` now sizes its worker pool by cgroup CPU quota when that quota is lower than the host CPU count. That prevents containerized runs from spawning far too many workers and exhausting memory.

**Hoisted installs no longer trust half-replaced packages after failures** (4d625be)
If a hoisted install stops after replacing a package but before completing `.modules.yaml`, pnpm now forgets that hoisted location before the next run. This avoids reusing an interrupted replacement on the subsequent install.

**pnpr storage layout and canonicalization were overhauled** (c6520ac)
pnpr now stores team rosters, rule overrides, tombstones, and several internal directories under the new unversioned path layout, and canonical package names now preserve the ecosystem they came from when loaded from storage. This is a broad storage migration/refactor that changes how pnpr organizes and interprets persisted state.

### Other misc changes
- Release/changelog updates for pnpm, pacquet, pnpr, and get-pnpm.
- Fix stale symlink retargeting on filesystems that keep reporting removed entries.
- Improve repeat-install oracle/test coverage and patch-gap fixes.
- Preserve peer variants correctly in hoisted workspaces.
- Include files from symlinked publish directories in packlists.
- Read legacy proxy keys and placeholder syntax during bootstrap.
- Fix stale `.bin` cleanup for workspace bins and related test coverage.
- Keep loader runtime in git dependencies; store/index and SQLite initialization fixes.
- Reject ambiguous `-T` on `pnpm add`.
- pnpr auth/libsql connection cleanup and registry-alias delegation fixes.
- Various docs, test, CI, dependency, and release-metadata updates.
