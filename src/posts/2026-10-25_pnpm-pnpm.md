### **pnpr gets readable storage paths and per-ecosystem namespaces** (57c9cc7, 22fcb2f)
pnpr’s storage layout was overhauled: packages now live under readable scope/version paths instead of escaped segments, and hosted storage is split by ecosystem so registries no longer collide across ecosystems. This is a substantial on-disk format change with migration implications, and the same work also changes how package names and namespace mappings are derived.

### **pnpr tarball URLs and revision routes were rewritten** (23a3f89, dc66bbd)
`.tgz` registries now serve `dist.tarball` URLs as `<name>@<version>`, and patch revision tarballs move to `<name>@<version>+r<revision>`. That simplifies routing, drops digest-addressed revision paths, and changes how pnpr and the lockfile resolve and validate tarball references.

### **Lockfiles now key packages by registry and pnpr server type is recognized** (6761624, f22a72b)
Packages resolved from a registry are now keyed by the registry they came from, preventing duplicate installs when the same package is reachable through different routes. In the same area, the config/CLI now understands `serverType: pnpr`, so pnpm can rebuild the right tarball URLs for pnpr-backed registries instead of writing host-specific ones.

### **Audit fix flows now reject conflicting ignore flags and preserve exit codes** (2f725d5, cbf9de2)
`pnpm audit --fix` now errors if combined with `--ignore` or `--ignore-unfixable`, instead of silently dropping those flags. Separately, `--ignore` and `--ignore-unfixable` now still fail the command when unignored vulnerabilities remain, which closes a CI escape hatch.

### **Dependency resolution avoids `--depth` blowups and reuses peer scans** (2377441, be80bcd)
The update walker no longer scales memory and stack usage with large `--depth` values on cyclic graphs, fixing crashes and OOMs on deep updates. A related resolver optimization now shares locked-peer computation for importers missing from the lockfile, avoiding repeated whole-lockfile scans.

### **Install and hook behavior fixes land across pnpm** (60b73b9, 7bffa4d, 6175c32, 0131bcc, caea6d9, c6b73fb, 8c1f7b4, d6cb3e8, f236f11)
Notable fixes include: `preResolution` hook mutations now take effect, `pnpm ci --lockfile` stops deleting the lockfile, changed workspace bins relink on repeat installs, `verify-deps-before-run` respects `dedupePeers`, `--global` rejects conflicting workspace/layout settings, project registry links are written as absolute paths, and skill/peer variant resolution is stabilized. pnpm also now trusts `.npmrc` CA settings when downloading its native binary and can write symlinked lockfiles into allowed target directories.

### Other misc changes
- Test updates and fixture adjustments for pnpr registry/storage changes, tarball routing, and audit/install behavior.
- `scriptsPrependNodePath` was removed as a no-op refactor.
- `get-pnpm` was moved into the workspace and release/signing automation was updated.
- Dependency, Node.js, and GitHub Actions bumps.
