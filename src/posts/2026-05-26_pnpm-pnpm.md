### **Registry config now matches Verdaccio shapes** (f03dc2d)
pnpm-registry’s config was reshaped around Verdaccio’s `config.yaml` model, with `storage`, `uplinks`, `packages`, and ignored unsupported fields instead of a single `upstream` setting. That makes the same config usable across both servers and reduces the gap between the mock registry and real-world deployments.

### **Lockfile tarball entries now require integrity** (e55f4b5)
Remote tarball resolutions without an `integrity` field are now rejected at read time, closing a path where a tampered lockfile could download attacker-controlled bytes and mint a fresh hash from them. The check preserves file tarballs and git-hosted tarballs, and the error now fails closed under frozen installs too.

### **Git fetcher rejects non-SHA commit values** (90d1ce6)
`git`-based resolutions are now validated before any fetch/checkout happens, so lockfile-controlled values starting with `-` can’t be treated as options. This blocks a lockfile injection path that could otherwise turn a malicious commit string into command execution during install.

### **Dependency aliases can’t escape `node_modules`** (ad84fff)
Alias validation and symlink creation now reject path-traversal forms like `@x/../../...` instead of joining them directly into the modules directory. This closes a symlink escape that could place files outside the intended install tree.

### **Workspace and runtime config behavior tightened** (35d2355, a662de4, f578281, a1f6f32)
`devEngines.runtime`/`engines.runtime` now validate `node`, `deno`, and `bun` ranges for `warn` and `error` modes, `pnpm runtime set` writes to `devEngines.runtime` by default, and pacquet gained `--recursive` plus `--workspace-concurrency`. The workspace-state builder was also fixed to derive projects from the project list instead of the lockfile, restoring correct state on fresh installs.

### **pnpr got a bundled config, docs, and npm release workflow** (c42f69f, c12681f, f107b1e)
`@pnpm/pnpr` now ships with a Verdaccio-shaped default config, better README coverage, and a manual GitHub release workflow that builds per-platform artifacts and publishes them to npm. CI was updated to install the published package instead of rebuilding it on every test run.
