### **`pnpm publish` can now bump versions inline** (3154abb)
`pnpm publish` gained `--new-version`, letting you write the manifest version before the package is checked, packed, and published. That removes the old two-step `version` + `publish` flow, and recursive publish now applies the same version bump across selected workspace packages.

### **`pnpm update` now supports dist-tag targeting** (647f60a)
`pnpm update --tag <tag>` now rewrites dependencies to the version behind any dist-tag, not just `latest`, and it works in interactive and global update flows too. This is a meaningful workflow expansion for users who need to track channels like `next` or similar release tags.

### **`pnpm audit --fix` can skip release-age exclusions** (29cdf57)
A new `--no-add-release-age-exclusions` option prevents audit remediation from automatically adding packages to `minimumReleaseAgeExclude`. That gives teams tighter manual control over vulnerability fix policy without disabling the rest of the pruning behavior.

### **`pnpm view` now reveals the registry source** (6582973)
`pnpm view <pkg>` now prints a final `registry:` line showing which registry the metadata came from, while stripping credentials and other unsafe URL parts. It’s a useful debugging aid for stale mirrors and other registry-routing surprises, and it leaves `--json` and field-specific output unchanged.

### **`pnpm update --interactive` gains trust context** (ea59f19)
The interactive updater now shows a `Trust` column and uses the same trust-policy filtering as install when choosing candidates. That makes it much easier to see why a version is or isn’t offered under `trustPolicy: no-downgrade`.

### **Security audit routing and OSV handling were hardened in pnpr** (ef49c3d, 309f7f2, 73aaea3)
`pnpr`’s security audit endpoints were overhauled to partition requests by registry route, keep hosted packages local, accept gzipped audit payloads, and consult local OSV data when enabled. Separate fixes also improved OSV advisory translation so versions, range bounds, CVSS severity, and URLs are preserved more accurately.

### **OCI upload sessions are now tied to the initiating user** (73aaea3)
Continuation requests for OCI uploads now re-check current repository publish permissions and require the same caller that opened the session. That closes a privilege gap in hosted registries where upload continuations previously relied on looser ownership checks.

### **Windows network-share installs now choose an openable link type** (38500a4)
On Windows network shares, `pnpm install` now picks the kind of node_modules link that can actually be opened from the share, trying junctions and symlinks with share-aware detection. This fixes installs that previously finished successfully but produced links that could not be traversed.
