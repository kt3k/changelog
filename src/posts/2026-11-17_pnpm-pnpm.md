### **pnpr switches to instance-wide grants and teams** (9bcd959, bc5406b)
pnpr’s authorization model was reworked so grants and teams now live in database tables instead of being embedded per registry. That changes the access API, removes several legacy registry fields/endpoints, and requires resetting existing alpha deployments.

### **`pnpm why` can now show declared ranges** (4f66d96)
A new `pnpm why --ranges` mode lists the version range each direct dependent declares for a package, and `--json` now carries declared ranges in a `requires` field. This makes dependency attribution much more precise without changing lockfile format.

### **Install/runtime checks now use the linked Node.js runtime** (5bda082)
Project `engines.node` validation now prefers the runtime pnpm is actually linking for the install, using the lockfile’s recorded runtime when available. That aligns engine checks with the real install target and avoids false failures in runtime-dependent workspaces.

### **Audit now reports advisories with string IDs** (da288c5)
The audit pipeline previously dropped advisories whose IDs were strings, which could make some registries look clean and exit 0 incorrectly. It now accepts numeric or string advisory IDs end to end, preserving the registry’s original type.

### **Hoisted peer resolution and removal logic were hardened** (1a15675, 82bb51c, 698ec00, 5eed369)
Several correctness fixes landed in the hoist and peer-resolution paths: deduping transitive peer bindings, bounding peer traversal costs, and avoiding overcounting missing hoisted orphans. Together these reduce wrong layouts, stack-overflow risk, and spurious removals in hoisted installs.

### **pnpr serves newly published versions sooner** (aefe2f5)
If pnpr has a cached packument but it doesn’t list a requested version, it now refetches before returning 404 for the package, tarball, or manifest route. That closes a stale-cache hole that could block fresh publishes until `packumentTtl` expired.

### **Unknown shorthand options are now reported as typed** (9ab10b6)
CLI parsing now attributes unknown options back to the shorthand the user actually entered, including grouped shorthands. The error message and suggestion logic are therefore less confusing, especially for commands with overlapping short flags.

### **Dependency-free workspace importers are now written** (c0bef3f)
pnpm install now writes lockfile importer entries even for new workspace projects that have no dependencies. That keeps workspace package discovery consistent and prevents `pnpm-lock.yaml` from silently omitting empty projects.
