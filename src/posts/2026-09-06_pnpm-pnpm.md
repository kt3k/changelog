### **pnpm 11.26.0 ships a broad feature release** (f00e768)
This release bundles a lot of high-impact work at once, including the new `pnpm pipeline` command, pnpr support for Cargo and Python registries, and several install/publish/lockfile fixes. It’s a meaningful expansion of pnpm’s ecosystem and CI orchestration surface.

### **Add `pnpm pipeline` with task graph, caching, and run reporting** (39dcf56)
`pnpm pipeline` now installs frozen dependencies, selects affected projects, and executes workspace task graphs with support for `outputs`, `inputs`, `env`, and cache replay. The same work also adds Cargo build-state reuse and pnpr run-report storage/reporting, making it a major CI/workflow feature rather than a small command tweak.

### **Teach pnpr to serve Cargo and Python registries** (1e83fc5)
pnpr now exposes Cargo and Python registry protocols alongside npm, reusing the same hosted-document, blob, auth, and caching infrastructure. This turns pnpr into a true multi-ecosystem registry server and lays the groundwork for the later resolve/publish work.

### **Resolve Cargo dependencies through pnpr** (614936e)
`pnpm install` can now resolve Cargo dependencies via the configured `pnprServer` instead of fetching sparse-index data locally. That cuts client-side network work and makes remote resolution the default when the server supports it.

### **Resolve Python dependencies through pnpr** (f99d19d)
Python dependency resolution now also runs through pnpr when available, instead of requiring the client to download wheels just to inspect metadata. If the server does not provide Python resolution, pnpm falls back to local resolution.

### **Publish multiple ecosystems in one transaction** (09b546a)
pnpr can now publish npm, Cargo, and Python artifacts together in a single crash-safe transaction. A failed batch publishes nothing, and interrupted publishes are recovered on startup, which is a significant correctness improvement for multi-ecosystem release workflows.

### **Share Cargo compilation caches through pnpr** (6ba99fb)
The new compiler-cache support lets sccache store and retrieve Cargo build artifacts via pnpr, with access control, immutability, and quota enforcement. This can materially reduce CI and developer build times for Rust-heavy projects.

### **Fix workspace discovery to normalize directory patterns** (965a600)
Workspace directory patterns are now normalized consistently before glob matching, fixing cases where installs or recursive commands missed projects or matched excluded ones. This is a user-visible correctness fix for workspace selection across platforms.

### **Fix protocol-prefixed package selectors in `pnpm add`** (091740e)
Selectors like `jsr:@scope/pkg` are now parsed by protocol instead of being misread as invalid package names. That restores the intended semantics for protocol-prefixed add requests, including version pinning behavior.

### **Fix `pnpm import` when `lockfileDir` is configured** (ae7f6b)
Import cleanup and replacement now respect the configured lockfile directory instead of deleting or restoring the wrong file. That prevents data loss and makes imports behave correctly in non-default lockfile layouts.

### **Fix audit summaries to match ignored advisories** (21dab07)
`pnpm audit` now reports vulnerability counts after ignore filters are applied, matching the exit code and the rendered tables. This removes confusing false alarms where the summary claimed unresolved issues that had already been suppressed.

### **Fix npm-surface routing to use explicit routes** (3d1036b)
pnpr’s npm surface now routes explicit paths directly instead of relying on catch-all segment counting and re-parsing. That simplifies routing behavior and makes 404/405 handling more precise.

### **Fix `pnpm setup` symlink escape handling on Windows** (7796262)
The directory fetcher now confines symlinked source directories to their real paths, avoiding false `path escape` failures during global setup on Windows. This removes a Windows-specific bootstrap blocker for globally installed pnpm.

### **Fix package-manager pin recording and version-switching behavior** (fc84749, 46f2140, b444394)
Several commits tighten how pnpm records the package-manager pin, especially when version switching is disabled or pipeline pin flags are present. Together they prevent inconsistent lockfile writes and make pin handling more predictable across commands.
