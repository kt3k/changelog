### **Global agent skills now install and approve from home directories** (92a5af2)
Global installs can now link approved agent skills into per-user skill directories, and approval decisions are stored in the global config. This is a broad permission-model addition for pnpm’s Rust CLI, covering global skill discovery, linking, pruning, and interactive approval flows.

### **`pnpm audit` gains engines and deprecations modes** (70bad47, 180df81)
Two new audit commands list incompatible packages: `pnpm audit engines` reports packages that don’t support the current Node.js version or platform, and `pnpm audit deprecations` surfaces deprecated installed packages and their origins. Both fill gaps left by install-time warnings, which only show a truncated subset.

### **`pnpm approve` can now choose permissions interactively** (3d90afb)
When approving a package with no pending request, pnpm now prompts for exactly which permissions to grant instead of assuming all capabilities. This makes advance approval more granular and changes the command’s interactive workflow in a user-visible way.

### **Version bumps now tolerate excluded untracked files** (bd06ec2)
A single-package version command can proceed when Git reports only unstaged edits and untracked files inside the package, as long as those files are excluded from the tarball. That removes an overly strict working-tree check while still blocking staged changes and other risky modifications.

### **Install output gets shorter and less noisy** (7713087, 13c342d, 954cd24, 3a446c1, 796ae2e)
Several reporter changes reduce install chatter: progress output drops redundant path prefixes, finished progress lines are replaced with compact stats, and script output plus unsupported engine/platform warnings move into the checks footer. `pnpm install --lockfile-only` now also reports progress again instead of appearing silent.

### **Lockfile, deploy, and package-usage edge cases are fixed** (e4ddee8, db05875, 631a411, ce20a91)
These fixes tighten a few correctness paths: offline lockfile verification reuses prior registry verdicts after workspace discovery, legacy deploy checks patch usage against deployed package names, patched global slots relink bins correctly, and SBOM generation now follows optional children of dev dependencies. Each is a targeted bug fix, but together they close several real workflow regressions.

### **Unix launcher preserves the native PID for signals** (1d2fe34)
The Corepack launcher on Unix now preserves the native binary’s PID when possible, so supervisors can signal the actual command directly. That improves signal handling behavior for wrapped pnpm executions without changing Windows or older-Node fallback paths.

### Other misc changes
- Documentation update for native addon build flags.
- Test coverage added for global workspace env isolation.
- Removed an obsolete audit ignore entry.
- Updated dependencies, Node.js, pnpm, and GitHub Actions pins.
- Lint hardening against direct process spawns.
- Miscellaneous approval, deploy, and reporter test updates.
