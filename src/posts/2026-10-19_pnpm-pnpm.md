### **Deploy now writes self-contained settings and preserves workspace resolutions** (78943e0)
`pnpm deploy` now carries its workspace settings into the deployed tree instead of relying on the source workspace, which fixes `--frozen-lockfile` and `verifyDepsBeforeRun` inside deployed directories. It also prunes unused `patchedDependencies` and keeps workspace-level dependency resolutions for deployed directory deps.

### **Filtered hoisted installs keep unselected dependency groups and re-check freshness** (7de0195)
`pnpm install --filter` with `nodeLinker: hoisted` now preserves previously installed dependency groups for workspace projects that were not selected, instead of collapsing them away. Repeat installs also re-resolve when transitive injected workspace deps or linked deps change, closing a freshness hole that could leave stale hoisted state behind.

### **Peer suffix reuse and hashed peer recovery were tightened** (b51fb2b, 3e56c29, bc3caf0, ca18902, 26980c1)
Several commits landed to make peer binding reuse more precise across install, dedupe, and deploy flows: hashed peer suffixes can now be recovered from lockfile snapshots, peer-provider ownership is used consistently when deciding reuse, and sibling projects no longer borrow peers from another project’s subtree. These fixes address cases where optional peers, own dependencies, or direct-dep updates were previously misclassified and could produce stale or duplicate peer placements.

### **Packlist rules were unified for pack/publish file selection** (0186076)
`pnpm pack` now uses a single rule compiler for `files` selection, nested ignore behavior, and explicit file handling, instead of the older Gitignore-based path. That also removes the unused `ignore` dependency, improves symlink safety, and makes nested lockfiles follow the package’s file-selection rules.

### **Directory-manifest lookup and local-spec freshness are now consistent** (d6a5e02)
Local resolver and freshness checks now share the same directory publish-manifest lookup and local spec agreement logic. That fixes mismatches for `file:` directory deps outside the workspace root and makes optimistic repeat-installs agree with the resolver.

### **pnpr gained secret hardening, schema validation, and protocol/versioning work** (e01508f, 85cd31b)
The pnpr config/server stack grew stricter: unresolved secret env refs now fail fast, cache and OCI secrets can be rotated independently, and persisted documents now carry format versions. The same area also added stricter config validation, a `pnpr serve` subcommand, and client/server protocol versioning so newer behavior can be negotiated safely.

### **Cargo repeat installs skip already-complete store slots** (d37c6d9)
Cargo workspace installs now avoid reprocessing crates whose store slots already have a completion marker, skipping the expensive materialization path for no-op runs. On large workspaces this cuts most of the time previously spent re-validating already complete crates.

### **Import-side swap locking was simplified** (2e734a6)
The importer now takes one swap lock per install rather than one per target, reducing lock-file churn and avoiding a permanent held lock file for each forced replacement. The change also covers the rename path for absent targets so stalled imports are less likely.
