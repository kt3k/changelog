### **pnpm pack now preserves bundled dependencies** (219854f)
`pnpm pack` was silently dropping packages listed in `bundleDependencies` / `bundledDependencies` after the npm-packlist v10 upgrade. This fix rebuilds the packlist tree with dependency edges populated so bundled `node_modules/<dep>` files make it into the tarball again.

### **GitLab-hosted installs now use a safe tarball URL** (39e4266)
pnpm now overrides GitLab tarball generation to use the `/-/archive/` URL instead of the API endpoint that encoded the project slash as `%2F`. That avoids both GitLab 406 responses and broken virtual-store paths that Node refuses to import.

### **`--prefix` is honored when locating the workspace root** (164221c)
Workspace detection now considers renamed CLI options before resolving the workspace directory, so `pnpm --prefix=<dir> install` sees the workspace manifest in the prefix directory. This prevents workspace settings from being missed and then overwritten by auto-populated defaults.

### **pnpm prints the Node version error before loading the bundle** (2b267a7)
The CLI bootstrap switched from a static import to `await import()` so the Node.js version check can run first. On unsupported Node versions, pnpm now fails with the intended “requires Node.js v22.13” message instead of a syntax crash.

### **Config reader restores `NPM_CONFIG_USERCONFIG` compatibility** (6925be3)
The config reader again treats `NPM_CONFIG_USERCONFIG` and `npm_config_userconfig` as a low-priority fallback for the user `.npmrc`, matching npm-style environments such as `actions/setup-node`. Empty values are now ignored instead of short-circuiting the fallback chain.
