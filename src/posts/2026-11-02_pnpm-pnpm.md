**pnpr gains atomic SQLite metadata storage** (15273f5, edb1c1f)
pnpr can now store hosted package metadata in SQLite, with atomic publish transactions, idempotency keys, tag history, and stronger unpublish behavior. This changes how publishes are recorded and served, and adds a new metadata backend option for hosted registries.

**pnpr now serves split package documents and release notes** (1d5fbe4, fef57ba)
pnpr learned to serve its own compact package document format plus per-version release records, reducing metadata transfer for pnpr-aware clients. It also adds first-class release notes storage and routes, letting publishers attach, edit, list, and delete notes for versions and publications.

**Registry publish verification now checks manifests against archives** (2e27cd2)
pnpr now rejects publishes when the package.json in the uploaded archive disagrees with the submitted manifest, covering dependencies, bins, platform fields, and install scripts. That hardens the registry against malformed or tampered publishes and aligns accepted rewrites with npm's publish-time normalization.

**Release records and transparency-log primitives are added** (eaff1a9, 69b5ac2)
Two new trust crates land: one for release-record identities, DSSE statements, TUF policy, and package URLs, and one for C2SP transparency-log checkpoints, tiles, proofs, and witness support. These are the building blocks for verifiable pnpr release records and log-backed trust workflows.

**Custom fetchers can now use native git/tarball/binary fetches** (f2a63e2)
Hooks gain native callbacks for `fetchers.gitHostedTarball`, `fetchers.git`, and `fetchers.binary`, letting custom pnpmfile logic reuse pnpm's verified fetch paths instead of fabricating content. That preserves locked integrity and reduces the chance of hooks smuggling in unverified files.

**pnpm install/link/deploy correctness fixes across edge cases** (a479258, c439360, ffe26bc, 14342ae, 3d55360, 01a74d6, 6f4bb39)
Several user-facing bugs were fixed: deploy now preserves dangling internal links, link resolution uses the current directory and writes to the current workspace project, `--no-runtime` cleans up linked runtimes, lone-project version bumps no longer trigger false dependency drift, the default store is anchored to the workspace, and agent-skills installs can proceed without target directories. These are all behavior fixes that remove sharp edges in common workflows.

### Other misc changes
- CI/test updates for Rust, TS scope filtering, and Windows dump capture.
- Store/CAS/internal refactors to simplify file-mode, file-map, and write-result handling.
- Cargo dependency bumps, docs clarifications, and typo/lint config tweaks.
