### **Shared task results now work across machines** (e5988d1)
`pnpm pipeline` can now use a remote cache server in addition to local cache, storing signed task results as shared artifacts and restoring them with the same trust checks. The change also introduces remote side-effects caching and new `remoteCache`/organization settings, making cache hits portable between CI runs and machines.

### **`pnpm deploy` now binds peers more like injected installs** (a156c4e)
Deploy no longer fails with ambiguous-peer errors when a linked workspace package’s peer has multiple possible resolutions in the deployed graph. It now prefers what the parent provides, matching injected install behavior and fixing a class of workspace deploy failures.

### **Config dependencies now save and update like normal deps** (5804cae)
`pnpm add --config` now records a version range instead of freezing a one-off version, and `pnpm update` can update those config dependencies within their ranges or to latest. This closes a correctness gap where config packages could get stuck on stale versions.

### **`addMissingPeerTypes` becomes a first-class install option** (c4b31a4)
A new setting links matching `@types/*` packages next to peer-dependent dependencies so TypeScript can resolve peer types with a global virtual store. The N-API bindings and pnpr request flow were updated to carry the new option through.

### **Remote config now survives older pnpm versions and pinned switches** (4206fe2)
pnpm now skips unknown `_auth` fields with a warning instead of aborting, and it can still switch to a project-pinned pnpm version even when parts of the config are unreadable. That makes version switching more resilient in the face of newer configs or partially invalid workspace settings.

### **Injected workspace repeat installs stop re-resolving** (e565dba)
Repeat installs through the Node-API path now compare injected projects against their `dependencyManifest` instead of the in-memory importer manifest. That prevents needless re-resolution when the injected view intentionally differs from the on-disk project metadata.

### **`workspace:` peers are handled correctly on legacy deploy** (a793a29)
Legacy deploy now preserves `workspace:` peer ranges instead of stripping the protocol and producing invalid bare ranges. That fixes a resolver failure for workspace packages whose peers are only satisfied through the workspace itself.

### **`Infinity` works for `--depth` in update and why** (c8ec1cd)
`pnpm update` and `pnpm why` now accept `Infinity` the same way `pnpm list` already did. This removes a user-facing parser mismatch for deep dependency inspection.

### **Rust libsql backends now connect over TLS** (7a349e3)
The pnpr auth backend for libsql/Turso now uses its own TLS connector instead of crashing at startup when `backend.libsql` is configured. It verifies certificates against the system trust store and only allows plain HTTP for loopback, fixing a hard startup blocker for that backend.

### **Rust CI cache sharing and formatter CI fixes** (27be1a9, 474066e)
Clippy/docs pipeline jobs now reuse Vercel Remote Cache in merge-queue and main runs, reducing redundant Rust CI work. Separately, rustfmt now builds with the pinned nightly compiler instead of picking up the wrong `rustc` from PATH, fixing a CI breakage.

### **Workspace discovery and injected installs get faster** (a0f89f8, c60133d)
Workspace discovery now prunes excluded subtrees earlier, and frozen injected installs skip unnecessary replacement work when hardlinks already match the source. Both changes target real install-time hot paths and should reduce large-workspace latency.
