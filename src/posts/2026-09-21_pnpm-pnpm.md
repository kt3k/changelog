### **Automatic deduplication is now available** (17690da)
pnpm can now deduplicate compatible dependency versions during install via `autoDedupe`, exposed in workspace config and as `--auto-dedupe` on `install` and `add`. Frozen installs keep the lockfile unchanged, so this adds a new optimization without altering reproducibility.

### **Workspace projects now hoist on every install** (d929b50)
Workspace packages selected by `hoistPattern` or `publicHoistPattern` are hoisted even when an install has no registry dependency graph to materialize. This fixes cases where newly added workspace projects or registry-free workspaces failed to get their expected symlinks until a full reinstall.

### **`pnpm update --peer` now updates peerDependencies** (ee0b8e3)
`pnpm update` gains a `--peer` flag so peer dependency entries can be updated in place, including `--latest` behavior for forcing newest versions. That fills a long-standing gap where peer deps were silently skipped.

### **`pnpm run` now preserves global options in script shortcuts** (449e0fa)
Script shortcuts are now protected before clap parses them, so global flags no longer get swallowed by the shortcut target. This fixes a subtle CLI routing bug across `test`, `start`, and `stop` shortcuts.

### **Lifecycle scripts can now read `package.yaml` roots** (f7c9d1e)
The executor now looks for `package.yaml` when `package.json` is absent at the project root, while still preferring `package.json` when both exist. This makes root lifecycle hooks work in YAML-only projects and improves manifest error reporting.

### **Custom resolvers can recover archive manifests** (6ce8324)
Custom fetchers now handle local and git-hosted tarballs that do not include a manifest by recovering it from the archive contents. That unblocks installs for resolver delegates that point at subdirectories or differently packaged archives.

### **`pnpm outdated` and updates now respect named registries** (eb68671)
Registry-qualified versions are now handled correctly in outdated queries and latest-version updates, preserving the registry prefix through resolution. This fixes mismatches for packages installed from named registries.

### **Workspace filter completions now include package names** (238a92a)
Completion for `--filter` and `-F` now offers workspace package names instead of falling back to command suggestions. The completion servers also keep workspace-pattern behavior without loading full install config.

### **`pnpm version` now honors configured tag prefixes** (403ebd2)
The resolved `tagVersionPrefix` from workspace config is now applied when creating and reading Git tags, while preserving explicit CLI overrides and empty prefixes. That restores expected tag behavior for version workflows.

### **`pnpm install` preserves CRLF line endings in manifests** (7a99e14)
Editing `package.json`, `package.json5`, or `package.yaml` now keeps Windows CRLF newlines intact instead of rewriting them to LF. The change is mirrored in both Rust and TypeScript manifest writers.

### **Git dependencies now fail fast on hidden SSH prompts** (5b1431c)
Git fetches now run SSH in batch mode so passphrase or host-key prompts do not hang installs behind the reporter. This makes SSH credential problems surface immediately instead of appearing as a stalled install.

### **Waiting concurrency-group tasks now start in arrival order** (93a68d9)
Task scheduling for concurrency groups was overhauled so waiters take slots in arrival order, with priority still winning where applicable. The new `pnpm tasks status` view also reports running and waiting tasks with elapsed times.

### **Hoisted-linker summaries now report skipped dependencies correctly** (6194004)
The install summary now compares hoisted-linker state against each install's own skip set, so dependencies that stopped being supported are no longer silently omitted from change reporting. This makes linker drift easier to spot.

### **Global `readPackage` hooks now invalidate lockfile reuse** (e25dc5d)
When a global pnpmfile changes or is removed, pnpm now notices even though that file is excluded from the normal checksum. Existing lockfiles are re-evaluated so subtree reuse and fast-update paths no longer stale-cache hook effects.

### **`pnpm install` now reuses in-flight tarball reads** (9839985)
Tarball resolution now parks on an extraction already in progress instead of fetching the same archive twice. That reduces redundant work and fixes racey resolution paths that needed the manifest from an in-flight download.

### **Windows lifecycle and global-store path handling improved** (8169881, 3fd0bbe)
Windows lifecycle scripts now try shorter verified working-directory spellings when the original path is too long, and scoped global-store paths are normalized more consistently. These fixes reduce `ERROR_DIRECTORY` and path-shape bugs on Windows installs.

### **`pnpm store prune` now cleans dlx cache correctly** (7ba5d7d)
Store pruning once again reclaims expired `pnpm dlx` cache entries, while avoiding symlink and junction roots during cleanup. Windows junction-based dlx caches are also now reused correctly.

### **`pnpm install` now skips stale workspace importers** (e45f033)
Frozen materialization now uses discovered importer IDs as the default root set, instead of retaining stale workspace importers. That keeps the installed closure aligned with the current workspace selection.

### **`pnpm remove` now fails on missing recursive targets** (5959c07)
Recursive removal now validates requested package names against the actual eligible dependencies before mutating manifests, and both Rust and TypeScript CLIs share the same missing-package diagnostics. This prevents partial removals when some targets do not exist.
