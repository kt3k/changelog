### **Install can now preserve stale hoists and nested-project resolution correctly** (a119f48, 484082c)
pnpm fixed two hoisted-layout bugs: isolated installs now remove stale private hoist links that would otherwise point at the wrong version, and nested projects inside another project no longer resolve dependencies through the enclosing project's `node_modules`. These changes matter for correctness in real workspaces where hoisted installs previously picked up the wrong package version.

### **Plug'n'Play resolution and loader discovery were repaired** (efd0c13)
PnP installs now honor package exports and `require.resolve()` lookup paths, combine export conditions from `NODE_OPTIONS` and CLI flags, and find the loader/package map when `lockfileDir` is set. It also fixes local `file:` directory dependency resolution and recreates a missing `.pnp.cjs` loader, which closes several cases where PnP projects could break after install or execution.

### **Cargo dependency handling now matches Cargo more closely** (791fb1b)
The Cargo integration now includes path dependencies outside the workspace, respects `[target.<cfg>.dependencies]`, and tightens frozen-lockfile checks so missing or mismatched path/git entries fail correctly. That brings `install`, `outdated`, `update`, and `add` behavior closer to Cargo's own rules, especially for non-trivial workspaces.

### **Python workspace installs and wheel metadata handling were expanded** (36d16a8)
Python support gained fixes for legacy wheel metadata, whitespace and interpreter options in entry points and shebangs, normalized dependency-group matching, and better handling of requirements-only workspace members. This also improves `pnpm add`/`pnpm update` flows in shared Python workspaces and makes `pnpm exec` locate the right environment in tool-only projects.

### **Publish/pack/unpublish now respect published names and manifest transforms** (6a8a63f)
Packing and publishing now use `publishConfig.name` when building registry specifiers, validate and normalize `beforePacking` output, and handle alternate manifest formats like `package.yaml` and `package.json5`. `pnpm unpublish` also prefers the highest remaining stable version when `latest` is removed, which makes release behavior more predictable.

### **Tarball and registry fetches were hardened** (4e01fd7)
Remote tarball handling now reuses the download response directly, avoids pinning failed redirects in the lockfile, and only sends credentials over secure destinations or loopback HTTP. Preflight requests also use configured auth and retry settings, reducing both wasted requests and credential leakage risk.

### **Verification and lockfile scanning got speed and correctness work** (a94353e, 963e5e1, f69b1c5)
Lockfile local-containment verification now scans only snapshots that can affect the result, which should cut down a costly full-graph walk on large lockfiles. Release binaries are stripped again with a new CI gate to reject unstripped artifacts, and store pruning now keeps in-use Python wheels and refuses pruning a frozen store.

### Other misc changes
- Docs updates for TypeScript resolution, docs preview workflows, store/prune behavior, and CLI guidance.
- CI/release workflow fixes for executable verification, release gating, and dependency pin refreshes.
- PR template cleanup and other small internal refactors/tests.
