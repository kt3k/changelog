### **GitHub Actions are now first-class in outdated and update** (fca6565)
`pnpm outdated` and interactive `pnpm update` now discover GitHub Actions dependencies in workflow files and referenced local action definitions. Non-interactive updates can include them too, keeping action pins and package updates aligned with the same selection, filtering, and save/lockfile behavior.

### **Recursive outdated queries now work across workspaces** (031fafd)
`pnpm outdated` now supports recursive workspace runs instead of being limited to the active project. It reuses workspace discovery and groups equivalent findings across projects, so list/ll and outdated behave more like the TypeScript CLI in monorepos.

### **pnpm update can generate changesets** (15c21aa)
`pnpm update` gained a `--changeset` mode, a workspace default, and a `--no-changeset` override. After an update, pnpm can emit a `.changeset/...md` file for every workspace package whose dependency contract changed, which helps keep release notes in sync with catalog-driven updates.

### **Workspace config now has dedicated update and audit sections** (7763777)
`pnpm-workspace.yaml` now supports `update:` and `audit:` blocks, replacing the older `updateConfig`, `auditConfig`, and top-level `auditLevel` settings. The new shape is clearer, takes precedence when both forms are present, and is recognized by both the Rust and TypeScript config readers.

### **`pnpm view` lands in pacquet** (2e2c322)
The registry metadata command is now implemented, including aliases like `info`, `show`, and `v`. It supports formatted output, JSON, and field selection, and can infer the package name from the nearest manifest when none is provided.

### **`pnpm version` now supports npm-style bumps** (fd33859)
The version command now accepts semver bump keywords and exact versions, plus recursive mode and common npm-style flags like `--preid`, `--message`, and `--no-git-tag-version`. That closes a major CLI parity gap and makes pacquet’s versioning flow behave much closer to npm/pnpm expectations.

### **Lockfile churn from partial installs is fixed** (23978d2)
A deps-resolver bug that could rewrite unrelated `pnpm-lock.yaml` entries after small manifest changes is fixed. The resolver now reuses still-satisfied entries more reliably, preventing noisy and potentially destabilizing lockfile drift.

### **Global bin dir creation and silent shorthands match pnpm** (2d05d96)
Fresh `PNPM_HOME` setups no longer fail on the first global command just because the global bin directory doesn’t exist yet. The CLI also accepts the universal `--silent` / `-s` shorthand again, restoring a couple of useful parity behaviors.

### **Peer dependency precedence is corrected for current specifiers** (b080184)
When a package appears in both `peerDependencies` and a non-peer dependency group, the non-peer entry now wins while computing current specifiers. That fixes cases where `pnpm add --save-exact` or `pnpm update` could incorrectly write peer-range prefixes instead of the requested version.

### Other misc changes
- Re-enabled a dylint rule and updated code to satisfy it.
- Removed a dead `concurrently` dev dependency.
- Updated a small Rust dependency version.
- Minor CLI/test/internal refactors and parity cleanup.
