### **Adds the `tool:` protocol for runtime-managed tools** (24e198b)
pnpm now accepts `tool:` wherever it previously accepted `runtime:` for Node.js, Bun, Deno, and Yarn provisioning, and treats the two spellings as lockfile-equivalent. It also reserves `tool` as a registry name, so this is a real protocol expansion with resolver and CLI impact.

### **Enables OIDC for dist-tag management** (4265135)
`pnpm dist-tag add`, `rm`, and `ls` can now use CI-issued OIDC tokens, falling back to stored credentials when OIDC is unavailable or rejected. This removes the need for a long-lived npm token in trusted publishing flows and tightens registry-audience checks for `pnpm publish`.

### **Fixes macOS atomic writes on virtiofs/SMB shares** (c3d4af9)
pnpm now falls back from `F_FULLFSYNC` to plain `fsync` when Apple platforms reject the stronger sync call, unblocking lockfile and other atomic writes on network/shared filesystems. This resolves a class of install failures that surfaced as `ERR_PNPM_LOCKFILE_WRITE_FILE`.

### **Makes `pnpm setup` follow symlinks to the real executable** (8c47795)
When pnpm was launched through an npm/Homebrew-style symlink, setup previously used the symlink path and built a broken global launcher. Canonicalizing the executable path fixes setup on macOS and npm-installed pnpm builds.

### **Corrects rebuild caching for empty side-effects rows** (5d90a8b)
`rebuild()` with `skipIfHasSideEffectsCache` now skips packages whose cached build changed nothing inside the package instead of rerunning their scripts every time. That closes a noisy rebuild inefficiency without changing normal install behavior.
