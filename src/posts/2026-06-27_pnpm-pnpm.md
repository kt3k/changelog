### **Pacquet CLI gains self-update support** (f8e5a0d)
Ported pnpm’s self-update flow into the Rust CLI, including trusted registry resolution, minimum release age/trust policy checks, corepack refusal, and in-place manifest pin updates when the project declares a package manager. This is a major UX and maintenance feature: it lets pacquet update itself safely without relying on the older TypeScript path.

### **`pnpm setup` now bootstraps global usage** (e96c2ef)
Added the setup command to install the CLI globally, create the `pn`, `pnpx`, and `pnx` aliases, and persist `PNPM_HOME` plus its bin path in shell or Windows environment config. That makes pacquet usable as a system-wide pnpm replacement rather than only as a directly invoked binary.

### **`pnpm with` is now available for one-off engine switching** (c00400d)
Added the `with` command to resolve and install a requested pnpm engine, then run the remaining args with package-manager checks disabled. This enables targeted version pinning for a single invocation without changing global state or project metadata.

### **Registry logout command lands in pacquet** (66c531e)
Introduced `pacquet logout` to revoke auth tokens server-side and remove them from the local auth store, mirroring pnpm’s behavior around ownership and error handling. This is a notable auth/registry workflow addition that closes the loop with login/token management.

### **CLI argument handling was split into focused modules** (4e18e44)
Refactored the large `cli_args.rs` module into submodules for command definitions, dispatch, pipelines, package-manager parsing, and reporter wiring. The change is mostly structural, but it should reduce merge conflicts and make future command additions easier to maintain.

### Other misc changes
- Dependency bumps: `tower-http` 0.6.11 → 0.7.0
- Dependency bumps: `bytes` 1.11.1 → 1.12.0
