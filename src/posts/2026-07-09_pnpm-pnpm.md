**Security: lockfile, manifest, and package-name traversal containment** (51300fd)
pnpm and pacquet now reject crafted names and path segments that could escape the virtual store or `node_modules` tree. This closes multiple traversal vectors, including lockfile-derived aliases, manifest package names from tarballs, and the global virtual store version segment.

**Security: block env expansion in untrusted proxy fields** (5a4daec)
`pnpm-workspace.yaml` proxy settings no longer expand `${...}` placeholders, matching the existing trust boundary for other repository-controlled config fields. That prevents a malicious repo from exfiltrating secrets via attacker-controlled proxy URLs.

**Security: fix git build-approval matching by repository** (c70e33e)
Git-hosted `allowBuilds` entries can now match the repository portion of a git dependency before the resolved commit hash. This avoids forcing users to add a new hash-qualified approval every time a trusted branch moves.

**Fix resolver peer-context leakage for self-contained closures** (fecfe83)
When `autoInstallPeers` is on, peer providers reused at the root are no longer peer-resolved a second time in the root context. That prevents packages inside a closure from binding to an incompatible root-level peer version.

**Fix optional dependency lockfile entries on resolution failure** (14332f0)
Optional deps that fail re-resolution now error instead of being silently dropped from the lockfile. This makes installs deterministic across machines and prevents frozen installs from losing the locked entries they need.

**Native `search` command lands in Rust** (abb6f41)
`pacquet` now implements `search`/`s`/`se`/`find`, including registry lookup, formatted output, and `--json` support. It brings the Rust CLI closer to feature parity with the TypeScript command set.

**Native `access` command lands in pnpm and pacquet** (508b8c2)
The new `pnpm access` flow supports listing packages and collaborators, reading and changing access status, configuring MFA requirements, and granting/revoking team access. This is a substantial registry-management addition rather than a thin wrapper.

**Fix global registry config support** (9318a11)
`registries` and `namedRegistries` are now allowed in global `config.yaml` and accepted by `pnpm config set --global`. That unblocks named-registry setups for global installs.

**Fix completion generation for the `pn` alias** (a8ad82d)
Generated shell completions now register the `pn` binary alias alongside `pnpm` across supported shells. Users who invoke the shorter alias will now get completion support too.

**Fix npm resolver memory retention during large resolutions** (3067e4f)
The memoized fetch cache no longer holds onto raw registry response bodies for the entire resolution phase. That should significantly reduce memory use on large cold-cache graphs with full metadata fetching enabled.

**Fix resolver and DLX tests to avoid GitHub flakiness** (d2ed60a)
Tests now keep the mocked GitHub-facing resolver helpers in place instead of restoring the real implementations in `beforeEach`. This removes a source of CI-only failures caused by throttled GitHub requests.
