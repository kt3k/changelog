### **Forward `--config.*` flags into verify-deps installs** (88d67fe)
`pnpm run` and `pnpm exec` now pass command-line `--config.<key>=<value>` options through to the install spawned by `verifyDepsBeforeRun`. This fixes cases where install-time settings like `--config.lockfile-dir` were silently lost and the child wrote to the wrong place.

### **Required peers now follow the provider they’re hoisted with** (3c6a942)
When pnpm auto-installs a required peer, it now prefers the version resolved in the current run instead of sticking to an older version only present in the wanted lockfile. That prevents duplicate peer copies from lingering in the lockfile after providers move, and brings `dedupe` along with it.

### **`pnpm run` no longer reports Ctrl+C as a lifecycle failure** (a6224e3)
Interrupting a script now stops the noisy `[ELIFECYCLE] Command failed ...` message from appearing after the user pressed Ctrl+C. pnpm still exits with the underlying shell’s interrupt status, but the interruption is no longer treated as an ordinary script failure.

### **`pnpm unpublish` now deletes tarballs under registry path prefixes** (fd09bcb)
Tarball deletes are now built against the normalized registry URL, so registries mounted under a path — such as Gitea’s npm registry — get the DELETE sent to the right endpoint. Before this, pnpm could report success while leaving the version published because the tarball delete hit the host root and 404’d.

### **Windows self-update no longer reruns when replacing old cmd shims** (40488db)
`pnpm self-update` now handles older `pnpm.cmd` shims without causing cmd.exe to keep reading into the replaced file and invoke the new pnpm a second time. This fixes a Windows-only update bug that could print a spurious “not recognized” error and rerun the update path.

### **Pinned pnpm commands skip the shell shim** (83943ba)
Commands in projects that pin a different pnpm version now launch that version’s native binary directly instead of going through the shell wrapper first. That trims process startup overhead, especially on POSIX and Windows where the shim previously added extra shell hops.

### **Symlink relinking avoids pointless create attempts** (5dd715f)
Install-time symlink reuse is faster because pnpm now checks whether an existing link already points at the right target before trying to recreate it. That removes a costly failed `symlink()` path on macOS and speeds up large workspace relinks.

### **`failIfNoMatch` now works from workspace config** (c4bd72d)
The selector setting is no longer CLI-only: pnpm reads `failIfNoMatch` from `pnpm-workspace.yaml` and environment config too, with a new `--no-fail-if-no-match` override for one-off commands. Unmatched filtered commands now exit 1 when the setting is enabled as intended.

### **Other misc changes**
- Linux release builds drop forced unwind tables for the CLI to reduce binary size (fca2d32)
- `pnpm runtime --help` now names the `set` subcommand (5dbff2e)
- `pnpm pack` links only the root collation data, shrinking the bundle (a1424c6)
- WASI host shutdown fixes for `wasi-threads` 2.1 compatibility (e9d57c2)
- Internal package-manager refactor around repeat-install verdict handling (d6018b2)
