**Preserve cyclic peer providers in lockfile resolution** (46a23fc)
Peer-provider differences are now retained across collapsed cyclic peer slots, instead of being flattened into one shared context. That keeps dependent packages anchored to the right versions when cycle members differ, fixing a class of incorrect peer resolution and lockfile-writing behavior.

**Clean up pnpr config keys before they freeze** (9485e2e)
This renames and regroups several pnpr settings, including TTL, byte-size, secret, proxy, and logging-related keys. It is a broad config API cleanup that changes how deployments express storage, secrets, and limits.

**Normalize publication route errors in pnpr** (79106d4)
Publication endpoints now go through the same JSON error normalization as the rest of pnpr. That makes method and query rejections consistent, while preserving the expected HTTP headers like `Allow`.

**Normalize the default lockfile directory** (e777efd)
An explicit `lockfileDir` that points at the default location now behaves like the implicit default. This fixes path anchoring for installs and for config hooks that rewrite `lockfileDir`, preventing surprising layout changes.

**Add reduced embedded engine profiles and size reports** (c9aef4b)
pnpm now has automated size reporting for embedded engine builds and new Cargo features for reduced embedded profiles. This helps control binary size without changing default pnpm behavior.

**Rebuild deploy peer contexts after relocating local references** (a45a77a)
Deploy now reconstructs peer contexts after moving local references so snapshot keys, nested bindings, and importer references stay consistent. This fixes retained peer bindings and an injected self-link edge case during deploy-related lockfile conversion.

**Support PowerShell on Linux and macOS during setup** (768896e)
`pnpm setup` no longer rejects `pwsh` on POSIX systems. It now writes the PowerShell profile block used to set `PNPM_HOME` and adjust `PATH`, matching the behavior of the other supported shells.

**Read retained bindings for locked peer pins** (afcaed1)
Locked peer-pin recovery now uses the exact retained provider groups, including aliases and duplicate groups, instead of reconstructing them loosely. That makes pinned peer recovery more stable for hashed snapshot keys and transitive peers.

**Bound pnpr resolver concurrency, deadlines, and frame sizes** (770a0c3)
pnpr now caps request bodies, queued/concurrent work, and streamed response sizes for resolve and verify-lockfile. This is a major safety and resource-control change for the server and client path, preventing oversized graphs and unbounded streaming work.

**Scope pnpr's dependency-confusion guarantee to routers** (d968da3)
The docs now clarify that the dependency-confusion guarantee applies when clients resolve through a router, not every registry URL directly. This tightens the contract and avoids overstating the protection.

**Ignore requirements.txt beside a virtual uv workspace root** (7e923ce)
Python discovery now avoids treating an adjacent `requirements.txt` as a project when the `pyproject.toml` is only a virtual uv workspace root. That prevents unmanaged-environment failures for workspace roots that keep tooling requirements nearby.

**Retain fresh hashed peer bindings in lockfiles** (2cff2c9)
Fresh v13 lockfile writes now preserve retained hashed peer bindings through graph-to-lockfile conversion and peer-deduplication renames. This fixes writes that previously lost enough peer/child split data to fail recovery.

**Unify registry error JSON and expose stable error codes** (253752b)
pnpr and pnpr-client now centralize registry error JSON and derive stable error codes from log kinds. This removes shape differences between npm and resolver responses and standardizes error handling across the stack.

**Make pnpr shutdown drain configurable and fail readiness first** (1e7aa90)
A new top-level `shutdownTimeout` lets deployments tune graceful shutdown drain time, with a default sized for Kubernetes termination windows. Readiness now flips to unhealthy as soon as shutdown begins, so traffic stops earlier and draining is more predictable.

**Preserve recorded peer bindings when reading v13 lockfiles** (8d0790b)
The v13 reader now keeps the provider groups used to reconstruct hashed snapshot keys, rather than rediscovering them by subset search. That fixes valid lockfiles whose peer/child split exceeds the legacy recovery budget.

**Negotiate lockfile format and resolution settings with clients** (3cbb73b)
pnpr now rejects unknown request fields, reports the lockfile format in resolve responses, and negotiates settings more explicitly with clients. This makes version skew visible instead of silently dropping newer client fields.

**Read implicit lockfile keys longer than 1024 characters** (6881a7a)
The lockfile parser now accepts long implicit YAML keys by relaxing the simple-key lookahead limit. That restores compatibility with edited lockfiles that pnpm itself would write in explicit-key form.

**Deduplicate identical resolved peers during install** (c81b326)
Install now avoids duplicate copies when a package’s resolved peers are identical, even if an ancestor depends on a different version of one of those peers. This fixes a concrete duplication bug in the hoist/absorption path.

**Read only the start of bin files when generating shims** (fbdc395)
The cmd-shim implementation now inspects just the first 512 bytes to detect a shebang instead of reading entire binaries into memory. That removes a costly per-shim overhead for large executable packages.

**Add default and maximum token lifetimes** (cffb5d2)
pnpr token issuance now has a configurable default lifetime and optional maximum lifetime cap. That closes off effectively perpetual tokens unless explicitly configured otherwise.

**Consolidate account status and token schema in pnpr** (e08ff1f)
pnpr’s auth storage now uses explicit account status/credential fields, prefixes personal tokens, drops token scopes, and sweeps expired tokens. This is a major auth schema migration that changes how accounts and bearer tokens are represented and maintained.

**Stabilize peer changes and concurrent script cleanup** (4739cf9)
This tightens peer-change detection for frozen installs and makes watchdog/script cleanup safer under concurrency. It also refines the peer-binding freshness checks used by lockfile and install workflows.

**Bind package mutation and publish authorization to storage transactions** (0c4dc6a)
Authorization for tags, maintainers, version removal, unpublish, and publishing now rechecks against the transaction’s committed storage state. That prevents cross-replica race conditions from bypassing ownership checks during concurrent mutations.

**Key admin user routes by immutable id and add user creation** (f21389d)
Admin user management now separates account creation from password resets and keys updates by user id instead of mutable login name. This is an API-level change that makes admin operations safer and less ambiguous.

**Refactor SQL dialect handling and enable experimental MySQL support** (b33dcba)
The storage layer now uses per-dialect SQL statements instead of broad string rewriting, and MySQL support is marked experimental. This is a substantial internal refactor that changes how SQL is generated and translated across backends.

**Bind SCIM subjects and unify access checks** (46bac77)
OIDC/SCIM identities are now bound through the directory when SCIM login is enabled, with ambiguity checks and synchronized session changes. The access-control path also got broader unification for hosted team references and deletion guards.
