### **`pnpm add -g` now isolates packages per argument** (4b25a3d)
Space-separated globals are now installed into separate isolated directories by default, so removing one package no longer wipes out the others. Comma-separated selectors still bundle into the same isolated install when you want shared dependencies.

### **Lifecycle scripts and build policy land in pacquet** (d685005)
This adds lifecycle script execution, build sequencing, and the new `allowBuilds` policy, matching pnpm 11’s default-deny behavior with an escape hatch for trusted builds. It’s a major engine-level feature that wires lifecycle handling into frozen-lockfile installs and ports the needed sequencing logic.

### **`pnpm publish` now respects proxy settings during web auth polling** (20e7aff)
The publish flow’s `doneUrl` polling now uses a fetch bound to the configured dispatcher, so proxy/TLS settings are carried through the whole web-authentication sequence. This fixes hangs and 403s seen when the initial publish request went through a proxy but the follow-up poll did not.

### **`pnpm --version` no longer leaves worker pools hanging** (91b0e64)
The CLI now drains workers from its top-level `finally`, covering short-circuit exits like `--version` and `--help` that previously bypassed cleanup. That prevents the process from staying alive after printing the version in workspace/version-switch scenarios.

### **`pnpm view` now shows publish age and publisher details** (8543b89)
`pnpm view` output now includes relative publish time and, when available, publisher attribution, bringing it closer to `npm view` and making `minimumReleaseAge` checks easier to reason about. The output formatting was also polished with clearer colorized metadata.

### **`pnpm runtime set` works from a workspace root** (a575dd2)
Runtime installation now skips the workspace-root safety check for non-global runs, which fixes `pnpm runtime set <name> <version>` in the root of a multi-package workspace. This treats runtime setup as workspace-wide config instead of a forbidden root install.

### **`verify-deps-before-run` stops warning on workspace engine checks** (02e9cf5)
Status scanning now uses the no-check workspace project reader, avoiding redundant installability validation and the spurious "Unsupported engine" warnings it produced from PATH Node detection. The actual install path still validates engines; this change فقط removes the extra warning from status checks.

The release commit bumps version metadata and rolls changelog files forward for the 11.1.0 cut.
