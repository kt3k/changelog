### **Wildcard package filters now support `?`** (0097f4c)
`pnpm` and the Rust matcher now treat `?` as a single-character wildcard in package-name filters. That closes a long-standing gap in filter matching and keeps the TypeScript and Rust implementations aligned.

### **Per-registry network concurrency lands** (93c6dc2)
Registries can now cap their own in-flight request count with `networkConcurrency`, keyed by origin rather than proxy target. This gives operators finer-grained control over hot registries without lowering concurrency for unrelated downloads.

### **Hoisted filtered installs stop dropping other projects’ packages** (26e2683)
Filtered installs under `nodeLinker: hoisted` now preserve packages that earlier installs placed in the shared `node_modules`, instead of pruning them away. It also fixes the follow-up `run`/`exec` preinstall path so filtered commands no longer erase dependencies needed by unselected workspace projects.

### **Frozen installs keep direct dependency aliases intact** (6183391)
The hoister now receives non-link direct dependency aliases from the wanted lockfile, so frozen installs don’t lose the alias that points to an external direct dependency. This prevents workspace hoisting from accidentally replacing or deleting the recorded link target.

### **`pnpm` reuses the right pinned binary when Node majors differ** (9c616cb)
The engine now looks up already-downloaded `pnpm` versions using the configured `nodeVersion` major, not just the `node` on PATH. That fixes repeated re-downloads and offline failures when the project’s Node major differs from the host runtime.

### **Recursive `run`/`exec` now verify workspace dependencies too** (e0597e4)
Filtered recursive commands now include transitive workspace dependencies in the dependency check, so a selected project won’t run against missing internal deps. When `verifyDepsBeforeRun: install` is enabled, pnpm will install those missing workspace dependencies before starting the command.

### **Watchdog handling for parallel scripts is much cheaper** (88bf5e4)
pnpm now uses one watchdog per command to monitor every script process group, instead of spawning an extra shell per group. That cuts process overhead in large recursive runs and reduces startup cost, especially on macOS.

### **NAPI hooks can now be tracked with a checksum** (50f09c2)
`install()` accepts a `readPackageHookChecksum`, allowing JS `readPackage` hooks to be treated as tracked instead of always forcing a full re-resolve. That enables lockfile reuse for custom npmfile logic when the hook content is unchanged.

### **Offline range resolution skips unrelated versions** (80d7b58)
When an offline range pick falls back to the store, pnpm now only inspects versions that actually satisfy the requested range. This avoids hydrating and probing the whole packument, speeding up offline and lockfile-only resolves.

### **Repeat lockfile-only installs can reuse deduped output** (4df1d1e)
After an `autoDedupe` lockfile-only run, pnpm can now recognize that the resulting lockfile is already converged and skip resolving the whole graph again. That removes a wasted re-resolve on no-op repeat runs.

### **`pkg get -r` no longer drops duplicate workspace names** (c82802b)
Recursive `pkg get` now keeps entries for workspaces that share a name by falling back to workspace-relative paths for ambiguous names. That makes the JSON output stable and complete instead of silently overwriting earlier projects.

### **Self-update handles more platform/version edge cases** (eeb3d24, b265df7)
Self-update now chooses the JS pnpm path correctly on x64 musl for older pre-v11 versions, and it can replace a standalone `pnpm.exe` left on PATH on Windows. Both fixes close upgrade paths that previously failed or left users running the old binary.

### **Deploy and install path handling gets several correctness fixes** (c61c504, 3cbcd34, 3cdea10, 446b26f, b67ff19)
Legacy deploy now re-anchors local/path dependencies correctly, deploy targets resolve against the real filesystem path, frozen installs can skip absent workspace directories again, and frozen installs continue after a failed pre-run dependency install. pnpm also accepts env-only lockfiles for empty projects, which is important for fresh repos and commands that write the env document before the first install.

### Other misc changes
- Performance: reuse cached resolver metadata when the lockfile already decides the range; build peer/child SCC tables once per hoist round; probe direct dependency links in parallel on repeat installs.
- Store/config/cleaning: register every installed project in the store, reuse config-dependency tarballs offline, and fix `pnpm clean` with custom global virtual store locations.
- Reporting/CLI fixes: report linked direct dependencies correctly, preserve `linkedFrom` in summaries, and improve `pnpm run` hints/options parsing.
- Misc refactors/docs/tests: several TypeScript size/shape refactors, deploy internals cleanup, matcher/fs refactors, and validation fixes for workspace settings.
