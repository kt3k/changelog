### **New `pnpm bugs` command opens package issue trackers** (0477da5)
`pnpm bugs` now resolves a package’s bug tracker URL and opens it in the browser, either from the current project manifest or from registry metadata for one or more package names. It falls back to `<repository>/issues` when `bugs` is missing, making the command npm-compatible and useful for quick support triage.

### **Git-hosted tarballs now pin integrity in lockfiles** (60fd205)
pnpm now records SHA-512 integrity for tarballs fetched from Git hosts and adds a `gitHosted` resolution flag so future installs can reliably distinguish them. That closes a supply-chain gap where a substituted Git tarball could otherwise be reinstalled without the lockfile noticing.

### **Trusted publishing now overrides static tokens on publish** (6a5156b)
`pnpm publish` now prefers an OIDC-derived token over a configured `_authToken`, matching npm CLI behavior. The change also lets CI systems forward an ID token through `NPM_ID_TOKEN`, broadening trusted publishing beyond just GitHub Actions and GitLab.

### **Windows exe aliases for `pn`, `pnpx`, and `pnx` are fixed** (997a8ca)
On Windows, `@pnpm/exe` now hardlinks `pn`, `pnpx`, and `pnx` to `.exe` binaries instead of `.cmd` wrappers, which fixes the Git Bash/MSYS2 failure mode where aliases would drop users into an interactive `cmd.exe` prompt. This restores the expected alias behavior for self-update and standalone exe installs.

### **`pnpm install` no longer recreates `node_modules` after `pnpm fetch`** (832d898)
`fetch` now marks the modules manifest as `virtualStoreOnly`, and the next install uses that marker to skip the hoist-pattern mismatch that was causing `node_modules` to be purged. This preserves the virtual store in place and lets the follow-up install finish linking instead of rebuilding the directory.

### **Scoped registry lookup is consistent across config and publish** (7bcfd97)
`pnpm config get @<scope>:registry` now reports the same registry URL used by publish and resolver code, including overrides from `pnpm-workspace.yaml`. That removes a subtle mismatch where `config get` could show one URL while `publish` silently targeted another.

### **`--pm-on-fail` now survives `--help` and `--version`** (bcd337f)
The CLI parser now preserves universal options when short-circuiting help/version output, so flags like `--pm-on-fail=ignore` keep working in those flows. This fixes a frustrating edge case where users couldn’t even read help in a package-manager-mismatch scenario.

### **Windows node-gyp shims regain execute permissions** (29c2e7a)
`@pnpm/exe` now packages the `node-gyp` shim files with the correct executable mode, fixing `Permission denied` failures in lifecycle scripts that invoke `node-gyp rebuild`. This is especially important for standalone exe usage on GitHub Actions and older system Node versions.
