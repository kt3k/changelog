### **Native workspace release management arrives** (826366b)
pnpm now has native release-intent and versioning flows: `pnpm change` records changeset-compatible intents, and `pnpm version -r` consumes them to bump workspace packages with dependency propagation, fixed groups, caps, filters, changelogs, and dry-run support. This is a substantial new capability that moves monorepo release management into the core CLI.

### **Registry team management is now built in** (411bbe8)
A new `team` command was added in both the TypeScript and Rust stacks for managing organization teams and memberships via the npm registry API, with create/destroy/add/rm/ls subcommands. The command also handles scoped registries, scoped credentials, retrying requests, and `--otp`/`--json`/`--parseable` output modes.

### **`pnpm cache delete` now clears every metadata cache dir** (b45c85a)
Cache deletion was widened so a package is removed from all metadata cache directories, not just the one implied by the current resolution mode. That fixes stale metadata being left behind in alternate cache layouts and makes delete behavior match how packages may have been fetched.

### **`runtime:` package saves now pin the resolved Node version** (f573900)
The Node runtime resolver now exposes a save-specifier path so `pnpm runtime set node 26` is written back as the concrete resolved version instead of the loose requested range. This also preserves the expected manifest formatting, fixing a mismatch between lockfile resolution and what gets saved to `package.json`.

### **Install-path microbenchmarks are split into finer sinks** (c6fd0b7)
The benchmark suite now isolates packument parsing and lockfile parsing in addition to the tarball path, making it easier to attribute performance changes to a specific stage. That improves the usefulness of future perf regressions and optimizations.

### Other misc changes
- CI/workflow runner migration tweaks across GitHub Actions.
- Cargo dependency bumps: `itertools`, `open`, and `sigstore-sign`.
- Minor workspace/test/support updates for the new release-management and team-command code paths.
