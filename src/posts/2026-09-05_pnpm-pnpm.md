### **Cargo installs and `pnpm add crate:` are now first-class** (5a18bfc)
pnpm can now resolve, lock, and materialize crates.io dependencies when Cargo support is enabled, and `pnpm add` accepts `crate:<name>` alongside npm packages. This adds a dedicated Cargo resolver, deterministic lockfile handling, and mixed-workspace install support.

### **Python ecosystem integration ships** (427bece)
pnpm now supports Python dependencies via `pypi:<package>`, `pyproject.toml`, `pylock.toml`, and managed `.venv` environments. Mixed installs, frozen/offline behavior, and `pnpm run` / `pnpm exec` integration make Python a real peer to npm, not just a test harness.

### **Versioning moves onto the release engine** (9440b51)
This replaces meta-updater hacks with proper `versioning.epics` and `versioning.fixed` rules in `pnpm-workspace.yaml`, then adds `pnpm change check` to catch drift in CI. It also tightens release behavior for pnpm, `@pnpm/exe`, and platform artifacts so they stay in lockstep.

### **Resolver fixes `<=` partial ranges correctly** (2b00298)
Ranges like `<=16` are now parsed as an X-range instead of a prerelease form that matched nothing on the target major line. That fixes peer dependency resolution failures and strict-peer install breakage for common semver patterns.

### **Warm restores avoid extra bin-linking syscalls** (5bc226c)
Bin linking during warm global-store restores no longer rereads dependency manifests the store index already knows about, cutting a lot of redundant filesystem work. The change targets large workspaces where repeated shim creation was dominating restore time.

### **Deploy reuses a workspace project index** (44cdaba)
Deploy now builds one normalized-path index for workspace metadata and reuses it while converting local deploy entries. On a large workspace this more than halved median deploy time, so it’s a meaningful performance improvement for big repos.

### **Cargo registry auth now honors pnpm credentials** (0af633d)
Cargo sparse-index and crate downloads now use pnpm’s URL-scoped auth map, and crates.io can also read `CARGO_REGISTRY_TOKEN` / Cargo credentials. That removes a common CI and private-registry pain point when fetching Rust dependencies.

### **Mixed `pnpm add` failures roll back cleanly** (3c1af78)
Failed adds that touch both ecosystems now restore the Node and Cargo manifests and lockfiles instead of leaving one side partially updated. This closes a nasty consistency bug in the new multi-ecosystem add flow.

### **Yarn release fetches use GitHub tokens** (c444995)
The Yarn releases lookup now authenticates with `GH_TOKEN` or `GITHUB_TOKEN` when available, avoiding anonymous rate-limit failures in CI. This makes Yarn provisioning much more reliable in shared runners.

### **Lockfile env writes are hardened against symlink races** (637e5ab)
Environment lockfile publication now uses the same atomic writer path as the main lockfile, re-checking the destination before rename. That closes a symlink-redirection window that could have published to the wrong path.

### **Patching now accepts CRLF patch files** (3e2aabe)
Updating `diffy` lets pnpm parse patch headers with CRLF line endings, which unblocks applying CRLF-encoded patch files to LF targets. A regression test covers the mixed-line-ending case.

### **Concurrent config caching is now atomic** (10acda7)
NAPI config instances are now interned through the cache entry API so concurrent callers converge on one entry per key. This fixes a race that could leak duplicate config objects under contention.

### **Slot-file imports handle clonefile’s macOS misreporting** (383236b)
The deps restorer now treats a macOS `clonefile` ENOENT on an occupied slot the way it should, instead of failing concurrent installs. That addresses an intermittent global virtual-store import bug on macOS.

### **Pack preserves lifecycle output and JSON errors** (3ef0167)
Packing no longer drops lifecycle output or JSON error details. That makes `pnpm pack` diagnostics much more usable when package scripts or structured errors fail.
