**Peer-hoist discovery now syncs incrementally from recent writes** (cc9e938)
Peer resolution no longer re-reads the entire workspace context on every hoist round; it refreshes its discovery view from what changed in that pass. That cuts repeated full-tree scans in large workspaces and should materially speed up peer-heavy installs.

**Peer-hoist candidates now come from the settled tree** (0d35c6c)
This fixes a nondeterministic peer-hoisting bug where concurrent walks could feed transient, interleaving-dependent version candidates into the picker. By deriving candidates from the settled tree, repeated installs stop rewriting the lockfile with different but valid peer providers.

**Peer dep-path finalization avoids repeated key string allocation** (d6a01f)
Node IDs are now ordered without formatting a fresh sort key string for every comparison. That trims allocation churn in the peer-resolution hot path, especially during final dep-path construction and cycle analysis.

**Registry metadata filtering and semver parsing are memoized** (0b4ebcf)
The resolver now filters package metadata once per packument instead of once per dependency edge when `minimumReleaseAge` is active, and it reuses parsed semver data rather than rebuilding it on every comparison. This is a broad resolution speedup for normal installs, not just a micro-optimization.

**`readConfig` now reports which settings were explicitly set** (12db10e)
The NAPI config reader now distinguishes user-provided network settings from defaults. That gives downstream consumers, like Bit, enough information to merge config without accidentally treating defaults as overrides.

**Lockfile-only installs now record tarball integrity hashes** (bd26366)
`--lockfile-only` now computes and writes an integrity hash even when the registry omits SRI metadata, including legacy `dist.shasum` fallback handling. This prevents later `--frozen-lockfile` installs from failing on lockfiles that previously lacked tarball integrity.

**Workspace-internal links are no longer remapped as external excludes** (4c02bbe)
A bug in `excludeLinksFromLockfile` could remap workspace-local links into `link:<modules_dir>/...`, which fed peer resolution the wrong node IDs and corrupted lockfile paths. The fix keeps internal links stable while still remapping only links outside the workspace.

**Peer-resolution and dependency-tree internals were split into focused modules** (4f15e2e, b7f81c9)
Two of the largest resolver files were broken apart into smaller modules for discovery, walking, reuse, finalization, workspace context, and manifest handling. This is mostly an internal maintainability refactor, but it also sets up the performance and correctness work that followed.

**Narrow fixes and benchmark updates around the resolver work** (edb5bf9, fea49c1, a98ff3e, 958d8a1, fa8d383, 5cf3a96, 3f900cd, e2f439b, d83eb4f, e706bbf)
