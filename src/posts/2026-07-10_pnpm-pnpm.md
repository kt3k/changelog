**Ported `pnpm stage` to the Rust CLI** (6a85968)
The Rust CLI now supports the full stage flow: publish, list, view, approve, reject, and download, with pnpm-compatible flags, endpoints, error codes, and output. The implementation also caps `stage list` pagination at 1000 pages and hardens tarball inspection against traversal tricks, so the command is both more complete and safer.

**Added Rust `login` / `adduser` parity with 2FA** (4627fa7)
Pacquet now supports interactive and web-based login, including the OTP/browser flows used by pnpm's auth path. Tokens are written back to `auth.ini` with safer parsing/serialization, which closes a potential config injection issue from malicious registry values.

**Fixed changed-packages filtering for `[<since>]` selectors** (2b02764)
The workspace filter now understands git-diff selectors like `...[origin/main]` instead of rejecting them as unsupported. That unblocks recursive discovery in PR workflows and also hardens ref handling around worktrees and option-like revision strings.

**Fixed self-update to reinstall the active version when needed** (a38adda)
Self-update no longer bails out just because the target version matches the currently running one; it first checks whether that version is actually installed globally. This fixes the case where a missing global install needs to be recreated from a local project copy.

**Added custom fetcher delegation from pnpmfile hooks** (a897ef7)
Custom fetchers can now return a delegated resolution envelope, letting pnpm rewrite the package and hand it back to the built-in fetcher. This brings pacquet closer to pnpm's hook model and unlocks more complex pnpmfile-based fetching behavior.

**Restored Bit workspace/capsule install behavior** (5333a25)
Pacquet's install path now preserves injected workspace mappings, materializes `link:` deps as symlinks, and fixes several related edge cases around no-range specs and workspace layouts. This is a broad parity fix for workspace installs that had been diverging from the v11 engine.

**Added `--store-dir` support in pacquet** (52b57ad)
Global `--store-dir` overrides now parse and apply with pnpm-like precedence, including relative-path handling from the workspace root and hook visibility for raw values. This makes store placement configurable in the Rust CLI without breaking existing config resolution.

### Other misc changes
- CI/release fixes: stage Rust release binary outside the repo root, draft GitHub release assets, stop bumping removed config deps, derive latest dist-tags from version input, trust pnpm publishes
- Small Rust CI/pre-push tweak: add typos checks
- Refactor: rename `pacquet/` directory to `pnpm/`
- Minor internal plumbing, tests, and dependency updates
