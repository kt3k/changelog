### **New N-API config reader for embedders** (53ba59e)
`@pnpm/napi` now exposes `readConfig(options)`, letting embedders resolve the same config cascade pnpm uses itself and get back registries, auth headers, proxy/TLS settings, and install behavior without a separate JS config reader. That’s a meaningful integration simplification for hosts that embed the engine.

### **Fixes for `pnpm install` on broken lockfiles** (e62e24b)
Regular installs now ignore a malformed `pnpm-lock.yaml`, warn, resolve from manifests, and rewrite the lockfile instead of failing outright. This restores the ability to recover from a broken regenerable lockfile while keeping `--frozen-lockfile` strict.

### **Peer resolution gets significantly faster in large workspaces** (3eec70f)
Peer resolution was reworked to avoid repeatedly re-walking converged importers, reduce unnecessary subtree revisits, and use faster hash maps internally. The commit notes a large multi-importer workspace dropping from about 77s to 36s, so this is a substantial performance win.

### **Workspace dependency links now survive partial re-resolution** (d36e0fd)
When a run re-resolves a workspace dependency that wasn’t directly targeted, pnpm now preserves its existing `link:` reference instead of rewriting it into a peer-suffixed `file:` entry. That prevents unnecessary lockfile churn and fixes a long-standing workspace dependency persistence bug.

### **Exact pins keep their `=` operator on update** (be871d7)
`pnpm update` now preserves `=3.5.1`-style pins as `=3.5.2` instead of dropping the explicit operator. The same change also broadens save-style handling, so exact-pinning semantics are now represented more accurately throughout the CLI.

### **Fresh installs stop prefetching unsupported optional deps** (59554be)
The dependency resolver no longer downloads platform-incompatible optional dependencies on fresh installs when publish-time metadata causes them to appear in both dependency maps. This trims wasted network work and avoids pulling packages that can never be used on the current platform.

### **`minimumReleaseAge` no longer advertises blocked latest versions** (9a4f51c)
The install summary now suppresses “X is available” when the registry’s `latest` tag is still too new to satisfy `minimumReleaseAge`. That keeps the user-facing hint aligned with the policy that just blocked the upgrade.

### **Git resolver no longer hangs on private repos** (b287582e)
`git ls-remote` now runs with `GIT_TERMINAL_PROMPT=0`, so private-repo resolution fails immediately instead of blocking on interactive credential prompts. This is a practical reliability fix for CI and unattended installs.

### **Lockfile YAML emission now handles huge dep-path keys** (18e5e4c)
Dependency-path keys longer than YAML’s simple-key limit are now emitted in explicit `? key` form. That keeps very large workspace lockfiles readable by the parser and avoids silent fallback re-linking on subsequent installs.
