### **pnpr can now pin missing tarball integrity** (a44e907)
`pnpr` now computes and caches a `dist.integrity` for upstream versions that are missing one or have an empty value, up to 64 versions per fetched packument. That unblocks installs from caching upstreams that previously could not be resolved, while still leaving per-version failures isolated.

### **Optional peers now follow the provider’s resolved version** (47d7d3c)
When a provider moves to a different exact version, `pnpm install` and `pnpm dedupe` now move the dependent optional peer with it instead of leaving behind a stale duplicate. This trims lockfile churn and fixes cases like `@vue/test-utils` keeping an old `@vue/server-renderer` copy.

### **Downgrades with autoDedupe now propagate to sibling projects** (26aeeb1)
If one workspace project downgrades a dependency, `autoDedupe` now pulls matching siblings onto that version too, instead of leaving the old version behind until a later dedupe. The fix also covers filtered adds, so the workspace converges more predictably after a downgrade.

### **Global legacy migration removes hard-linked executables** (6fd18fa)
`pnpm update --global` now recognizes hard-linked bin executables from the old global layout and removes them during migration, including Windows `.exe` paths. That closes a cleanup gap where stale binaries could survive alongside the new layout.

### **Deploy no longer copies the workspace package-manager pin** (2211354)
`pnpm deploy` stops inheriting the workspace root’s `packageManager` and `devEngines.packageManager` into the deployed manifest. This avoids breaking deploy targets that are run by a different package manager, such as plain npm in container images.

### **Publish now recognizes npm-style README filenames** (5a5de95)
`pnpm publish` now includes bare `README` files and other npm-compatible Markdown README names in published metadata, not just `README.md`. The selection logic is also made deterministic so README choice doesn’t depend on directory order.

### **Frozen installs now accept injected optional peers** (d2cb36c)
Frozen installs no longer reject injected packages whose resolved optional peers appear in the lockfile snapshot. This fixes a false freshness failure for metadata-only optional peers in fresh lockfiles.

### **Store index rows now handle msgpackr undefined correctly** (cd897a2)
The store index transcoder now writes `nil` for msgpackr’s `undefined`, fixing rows that were previously undecodable and could abort `pnpm store prune`. Prune also keeps its CAS cleanup safe when it encounters manifests-less tarballs.

### **Direct locked dependencies are preserved through workspace resolution** (0d01c2a)
`pnpm install` now keeps an unchanged project’s direct dependency on its current version even when a cyclic subtree forces re-resolution. This prevents unrelated workspace changes from silently nudging direct deps to a sibling’s pinned version.

### **Locked optional peer versions are no longer kept stale** (47d7d3c)
The hoist logic now drops a locked optional-peer version once it is no longer reachable in the current tree, rather than preserving a stale copy forever. That allows `pnpm dedupe` to remove dead duplicates after provider updates.

### **Range pins now respect minimumReleaseAge** (5f12327)
When a `devEngines.packageManager` range records the running pnpm, the recorded version now has to satisfy the project’s `minimumReleaseAge`. If it doesn’t, pnpm records the newest eligible version in the range instead.

### **CommonJS require-hook entry points are handled under `--import`** (d3613e5)
The ESM loader path now correctly classifies certain entry points as CommonJS when Node is launched through `--import`/`NODE_OPTIONS`, fixing `ERR_UNKNOWN_FILE_EXTENSION` for tools like `ts-node index.ts`. This closes a Node 20/ESM-loader regression that only looked fine on newer Node versions with native TypeScript stripping.

### **Concurrent store readers are coordinated more safely** (ffb2a5a)
Store index access now preserves compatibility for concurrent read-only readers and immutable-store mode, avoiding races around index access. The fix also tightens store tests and docs around what kinds of concurrent access are actually allowed.

### **CLI config dotted settings are now recorded as explicit** (3260f8d)
Settings passed via `--config.<setting>` are now written into the explicit-settings record, so `pnpm config get` and `pnpm config list` report what was actually provided. This fixes a mismatch where the value affected installs but didn’t show up as configured.

### **`--force` help text now matches platform behavior** (756ee2f)
The help text for `pnpm install` and `pnpm add` now says `--force` does not override platform-mismatched optional dependencies unless `forceIgnoresPlatform` is enabled. The wording now matches long-standing behavior and points users to the right flags.
