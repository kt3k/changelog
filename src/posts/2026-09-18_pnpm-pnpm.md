### **`pnpm add` now accepts Package URLs** (871ca5f)
`pnpm add` can take `pkg:` Package URLs and route them to npm, Cargo, or PyPI based on the URL type. That makes cross-ecosystem adds first-class, and also reserves `pkg` so it can’t be used as a registry name.

### **Project bin shims are now relocatable** (9c1e317)
On macOS and Linux, shims in `node_modules/.bin` now write relative paths when configured to stay within a project tree, so copied or moved projects keep resolving dependencies from the new location. This fixes a long-standing portability issue for project-local binaries and injected dependency relinking.

### **Python registry routing now targets explicit indexes** (b3da608)
Registry configuration gained an `ecosystem` field, letting npm, Cargo, and PyPI indexes be declared in one model instead of separate settings. For Python, resolution now follows explicitly claimed package prefixes and index order, which avoids ambiguous routing and makes lockfiles sensitive to route changes.

### **Python installs got broader discovery and release handling fixes** (6d11abf, d37ecba, caefaae)
Python project discovery now respects workspace boundaries more strictly, and interpreter selection can fall back across older published releases when an exact patch isn’t available. Historical release lookup and checksum fetching were also bounded and cached more carefully to avoid runaway scans and repeated network work.

### **Repeat installs and global updates became smarter** (2c82ea5, f2bbfcb, 4f37bb5, 919a2ec)
Several fast paths were repaired so pnpm can skip unnecessary reinstalls when the graph hasn’t changed, including global updates, repeat installs in deduped workspaces, and NAPI-backed in-memory installs. The install pipeline now avoids unnecessary re-imports and preserves the user-facing “Already up to date” behavior where appropriate.

### **`pnpm` script resolution now prefers package scripts for built-ins** (7e7b899)
Commands like `deploy`, `rebuild`, `rb`, and `setup` now run same-named `package.json` scripts by default, matching documented behavior. The built-in command still wins under `pnpm pm <name>`, but the dispatch logic now consistently honors script overrides.

### **Recursive `pnpm list` JSON output was fixed** (aaf1e11)
Recursive listing now keeps per-project results intact until the final render step, instead of concatenating independently serialized arrays. That prevents invalid JSON when workspaces have separate lockfile roots.

### Other misc changes
- Audit `--fix=update` no longer prompts twice.
- Cargo ancestor config lookup now handles symlinked configs above the checkout.
- `pnpm-workspace.yaml` task settings compatibility improved for older pnpm.
- Python wheel, metadata, and dependency validation follow-up fixes.
- Dependency, release, CI, and formatting chore commits (7 commits).
