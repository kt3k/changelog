### **Install now honors lockfile inputs and repeat-install state** (d4bf2bd)
`pnpm install` and `fetch` were tightened so they respect the inputs that actually affect the materialized packages, including lockfile format and catalog-backed peers. That avoids stale repeat installs, preserves catalog entries across fast updates, and keeps warm installs rewriting the lockfile when the requested format changes.

### **pnpm’s N-API installer now respects its declared contracts** (9b3d6de)
The native installer stopped falling back to workspace walks when a project list is explicitly provided, and it now handles `ignorePackageManifest` with an empty root manifest instead of failing. It also hardens option validation so invalid linker, package import, and network settings fail instead of silently defaulting.

### **Workspace shims and injected bin links are refreshed correctly** (a9f59dd)
Bin refresh now uses the installer’s shim options, carries workspace patterns into discovery, and resolves module directories correctly for scoped copies and `directories.bin` commands. This fixes missing or stale shims in workspace setups and aligns hidden-file and shebang handling across bin discovery paths.

### **pnpr now preserves release metadata and resolves registries more faithfully** (63ec86c)
Staged publication records now keep their evidence through approval and commit, with registry resolution based on the published package name and `publishConfig`. This closes gaps where staged notes, approver identity, or tarball selection could be lost or misrouted.

### **Hoisted installs no longer hang on peer-heavy workspaces** (691d13b)
The Rust hoister was ported closer to the upstream algorithm, fixing peer ordering and deduplication behavior that could explode memory usage on large `nodeLinker: hoisted` workspaces. It also now routes edges to the directory that actually serves a peer variant, which matters for agent skills and other collapsed peer cases.

### **Patch application and patch-commit are much more robust** (33845e6)
Patch parsing/applied behavior was fixed across both CLIs: CRLF hunks, mode-only changes, unified diffs without `diff --git`, and missing final-newline markers now behave correctly. `patch-commit` also rejects out-of-project patch directories instead of silently rewriting them inside the repo.

### **pnpr package mutation and registry auth rules were tightened** (8ce8195)
Owner/team/star mutations now follow the right authorization and revision checks, and the CLI now supports proper `owner`, `star`, and `team` output formats. This reduces stale-write bugs and makes pnpm-compatible registry APIs behave more like npm’s expected CLI surface.

### **Config reads now protect secrets and resolve TLS paths at the source** (c547393)
Protected auth settings are checked before lookup, and TLS file references are resolved using the source file’s directory so scoped settings behave predictably. The change also improves redaction/logging behavior around pipeline errors and enforces trust rules on config writes.

### **get-pnpm now scopes registry credentials correctly** (c5150d0)
The bootstrapper that downloads pnpm’s native binary now respects path-scoped credentials, reads `auth.ini`, and handles several first-run auth/config edge cases. That closes a potentially serious credential leak across paths on the same registry host.

### Other misc changes
- New `pnpm edit` command added
- `nodeLinker` gained object-style config for hoisting options
- `pnpm import` now respects workspace/lockfile boundaries better
- `pnpm why --exclude-peers` now actually excludes peer-only packages
- Release-age policy, build approvals, and global-package config fixes
- Docs updates, CI/workflow tweaks, and dependency bumps
