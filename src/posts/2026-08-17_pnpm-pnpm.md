### **Stream large tarballs into the store** (8efc4d9)
Installing big packages now uses a streaming extraction path once tarballs cross the size thresholds, avoiding the old peak-memory spike from holding both compressed and fully decompressed archives at once. This should materially reduce RAM usage and improve reliability for large installs.

### **Per-registry `time` support for metadata resolution** (46280ca)
`resolutionMode: time-based` can now decide per registry whether abbreviated metadata already includes `time`, instead of treating all registries the same. That lets pnpm avoid fetching full packuments where it is unnecessary, while still working correctly with registries that do not serve `time`.

### **`outdated` and interactive update now dereference `catalog:` specs** (83ac087)
`pnpm outdated` and `pnpm update --interactive` now resolve catalog-backed specifiers before querying the registry, which fixes failures on catalog aliases and makes compatibility checks use the catalog's actual range. This closes a real correctness gap where catalog entries could be queried under the wrong key or skipped entirely.

### **`preferWorkspacePackages` skips pointless registry requests** (ddb1094)
When workspace packages are preferred and a local copy already wins, pnpm now returns that result without making a registry request that cannot affect the outcome. This removes unnecessary latency on installs and avoids repeated 404s for workspace packages that were never published.

### **pnpr now forwards resolver settings from the client** (c5fadf1)
pnpr-backed installs now carry `autoInstallPeers`, `dedupePeers`, and `excludeLinksFromLockfile` from the client into the server-side resolve. That keeps pnpr installs aligned with the user's actual config instead of silently falling back to defaults.

### **Large install verification now reports what it actually did** (5f86490)
Store-integrity checks now surface when pnpm had to re-hash files to verify them, with messages that distinguish a small hashing cost from broader timestamp-driven revalidation. The change improves install diagnostics in both the Rust and TypeScript stacks.

### **`virtualStoreType` is now the canonical config spelling** (125e353)
pnpm now exposes `virtualStoreType: global | project` as the preferred setting name, while keeping `enableGlobalVirtualStore` working for compatibility. This makes the configuration clearer and better reflects that the option selects between two store modes rather than just toggling a boolean feature.

### **`pnpm change` exits cleanly on canceled prompts** (ac0157b)
Canceling any interactive prompt in `pnpm change` now exits successfully instead of bubbling an `ExitPromptError` to the top-level handler. That brings its behavior in line with other interactive commands and removes an unnecessary error stack trace.

### **`pnpm update -g --latest` preserves local package specs** (e5eb4cd)
Global updates no longer strip `link:`/`file:` specs down to bare package names before resolution. That prevents 404s for locally linked or private packages and keeps the global update loop from aborting the rest of the queue.

### **`catalog:` override drift is handled more safely** (5e55ab3)
Fast lockfile reuse now distinguishes harmless `catalog:`-backed override changes from real catalog drift, so unrelated override edits no longer force a full re-resolution. This reduces lockfile churn and prevents unexpected version movement from small override changes.

### **`why` and `list` preserve nested ANSI escape bytes** (3c61b51)
Color rendering for dependency trees now avoids stripping the escape byte from nested styled labels, which had been turning ANSI sequences into literal text in terminal output. The fix restores correct coloring for those commands.

### **`pnpm patch-commit` supports non-ASCII patch paths** (4359336)
Git diff generation now disables quoted path output so pnpm can parse patch headers for paths with non-ASCII characters. This fixes patch generation on internationalized file names in both the Rust and TypeScript implementations.

### **`pnpm install` over pnpr now keeps canceled changes clean** (ac0157b)
Interactive cancellation handling now covers the whole `pnpm change` flow, including package selection and version prompts, so aborted runs no longer look like failures. It now exits cleanly after the user cancels instead of emitting a stack trace.
