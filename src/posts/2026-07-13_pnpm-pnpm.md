### **Release flow overhaul: changelogs now compose at publish time** (0dfce95)
pnpm’s default changelog storage moved to `registry`, so `version -r` no longer commits `CHANGELOG.md`; instead it parks release notes under `.changeset/changelogs/` and composes them into the tarball at publish time. That changes how release intent is garbage-collected and makes release history depend on what’s actually published, not just what’s committed.

### **Native release flow is unified across TS, Rust, and pnpr** (d3e1383)
The repo consolidated the three release paths into one native versioning flow and dropped the `@changesets/cli` dependency. This is a major repo-wide refactor that also rewires release automation and package identity handling around the workspace directory.

### **Convergence overrides add exact-version pinning when compatible** (5b8b101)
A new override form, `"pkg@": "<exact version>"`, now rewrites only dependency edges whose declared range already admits that version. It gives maintainers a semver-safe way to converge compatible dependents while leaving incompatible ones untouched, and it warns when the chosen version has become stale.

### **Publish now sends README metadata again** (5bd0082)
`pnpm publish` once again includes the package README in registry metadata, matching npm and restoring package-page rendering on registries. The change also updates pack/export logic so the README is handled correctly across the Rust and TypeScript release paths.

### **macOS DNS resolution now respects scoped DNS setups** (bb31881)
On macOS, pnpm now falls back to native `getaddrinfo` resolution so VPN and supplemental resolver configurations work correctly. This fixes install-time failures where Hickory DNS ignored scoped DNS state and sent registry lookups to the wrong resolver.

### **Token helpers are now supported and enforced safely** (cbecd4a)
Global `auth.ini`-configured `tokenHelper` values are now accepted, and the helper path is protected with a 60-second timeout. That closes a real auth/config gap while keeping project-local `.npmrc` helpers blocked for safety.

### **Windows installs now create global store symlinks with native separators** (c03b2d)
A Windows-specific path handling bug in global virtual store link creation was fixed so forward slashes no longer reach `CreateSymbolicLinkW`. This prevents installs from failing when the global virtual store is enabled.

### **pnpr’s hosted packument writes are now conflict-safe** (806ff49)
Hosted packument updates now use conditional writes and detect write conflicts instead of allowing a stale replica to overwrite newer registry state. That’s important for multi-replica S3 deployments where publish and dist-tag operations can race.

### **Native deprecate/undeprecate and star/stars/unstar commands land** (b9fccc8, 0cdd988)
Several npm CLI commands were reimplemented in Rust, including package deprecation management and starring workflows. These are sizeable surface-area additions that expand the native CLI’s parity with the TypeScript implementation.

### **Installer and resolver correctness fixes**
Installer behavior was tightened in several places: repeat-install freshness now uses filesystem mtimes correctly, workspace/versionless package resolution was restored, injected workspace catalog resolution was fixed, and optional dependencies are now honored or skipped consistently based on flags. These are all user-visible correctness fixes that reduce stale or missing dependency edge cases.

### Other misc changes
- Release/version bumps and lockfile updates (multiple commits)
- CI runner and test-fixture adjustments
- Several test-only stability fixes for coarse-mtime and process-cleanup cases
- Minor packaging/docs tweaks for the release and publish flow
