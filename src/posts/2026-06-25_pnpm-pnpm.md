### **Pacquet now ports `audit` with fix and ignore flows** (6e45ce1)
Ported the full `pnpm audit` command into pacquet, including vulnerability reporting, `--fix` support, `--ignore`, `--ignore-unfixable`, and interactive selection. This is a major CLI feature because it turns pacquet from read-only security reporting into a tool that can actively remediate vulnerable dependencies.

### **`pack-app` lands in pacquet with standalone executable builds** (2c7369d)
Pacquet now supports `pack-app`, which packages a CommonJS entry into a standalone executable using Node’s SEA flow and target-platform selection. The port also reuses pacquet’s runtime resolution and install machinery, making executable builds a first-class CLI capability.

### **`config` command ported for set/get/delete/list** (6312916)
`pacquet config` now mirrors pnpm’s configuration subcommands, key validation, file routing, and value casting. That matters because it gives the Rust CLI parity for day-to-day config management instead of forcing users back to the TypeScript CLI.

### **Global package management arrives in pacquet** (be6505a)
The Rust CLI now supports global installs, removals, updates, outdated checks, and global listing. This is a big parity step for pacquet because global package workflows are one of the core pnpm use cases.

### **`dist-tag` support comes to the Rust CLI** (3d7d2d1)
Pacquet can now list, add, and remove registry dist-tags directly, with the same registry/auth handling and semver checks pnpm expects. That closes another important package-publishing gap in the Rust port.

### **`pack` is now implemented in pacquet** (159bd27)
Pacquet gained the ability to create reproducible package tarballs, run lifecycle scripts, and build the publish manifest. This is a foundational publishing feature and also pulled shared packlist logic into a dedicated crate.

### **Local and global `list`/`ls` support expands** (af58273)
The list command was extended beyond the earlier global-only path to cover local workspace/package inspection, plus aliases like `la` and `ll`. It also adds more pnpm-compatible filtering and flag handling, making package tree inspection much more usable.

### **`link`, `unlink`, `prune`, and `fetch` fill in more CLI gaps** (1a96a43, 208b692, 54c5c0e, a06591e)
Several common package-management commands were added to pacquet, rounding out install-time and workspace-maintenance workflows. These are important parity wins, even though they don’t change the repo’s core architecture the way the major ports do.

### **`pnpr` gets security and correctness hardening** (deb6d8e, 47685fd, 1f462ef, fff9043)
The registry implementation tightened publish/update behavior to reject version re-publishes, allow metadata-only deprecations, block integrity tampering in partial-unpublish PUTs, and time out stalled libsql auth reads. Together these fixes close real security and availability holes in the registry backend.

### **`audit signatures` and metadata retrying were added** (c50c6aa, 04f156e)
Pacquet gained signature verification for installed packages, and network fetches now retry body-read failures instead of failing immediately after a 200 response. Both are meaningful reliability/security improvements for install and audit flows.

### **Config/auth plumbing was expanded for safer registry auth** (3425e80)
A new structured `_auth` setting was added for registry authentication, with env/global support and stricter host scoping. This is a notable security-related config change because it avoids fragile per-host token env vars and makes credential routing more explicit.

### Other misc changes
- CI/workflow hardening: release environment gates, triage automation, and test-job disk usage tweaks.
- Docs/comment updates and shell script relocation.
- Test-only coverage additions across new and existing CLI paths.
