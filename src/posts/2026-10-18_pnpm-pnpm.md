**pnpr gets a new hosted-store layout** (85f7fa1)
pnpr now stores hosted packages with separate namespaces for orgs, documents, and blobs, and the on-disk layout matches S3. Existing stores need `pnpr upgrade-storage`, so this is a notable storage migration with operational impact.

**pnpr now prefixes every ecosystem and fixes URL handling** (430d892)
Every pnpr ecosystem now lives under its own path prefix, including npm at `/npm/` even when it is the only configured ecosystem. That avoids ambiguous root URLs and fixes registry/tarball addressing across metadata, metrics, and test fixtures.

**pnpr implements package ownership, maintainers, and tombstones** (2d94114)
pnpr now records maintainers on publish, supports `$owners` in access rules, and handles `npm owner` maintainer mutations. It also adds tombstones for deleted packages and versions to prevent squatting and version reuse.

**pnpr serves version tarballs from cache without packument fetches** (dfb72de)
The version-tarball route can now serve hosted blobs or cached upstream tarballs directly under the canonical filename, avoiding packument reads on warm hits. This should reduce latency and upstream metadata traffic for common package fetches.

**pnpm adds tarball-unpacked size limits for installs** (ae349ec)
`pnpm install` now fails once a package would unpack past `maxTarballUnpackedSize` (4 GiB by default), protecting against archive bombs that expand far beyond their download size. The limit applies to tarballs and zips and is wired through config and fetch/extraction code.

**pnpm now records tar hashes and drops registry revisions** (7b0d687)
Lockfile integrity can now target tar digests, making installs resilient to registry recompression or tar-serving mirrors. In the same change, registry revisions are removed, so revision-based metadata/specifiers now fail instead of being silently accepted.

**Resolver and install correctness improvements** (c6718a0, 0b82b33, cfae1ff, 9a09d43, 0cef240, b9e1749, ebbb1b3, 60bd977, 7821998, bc63262, 77fddc0, 1930cf1)
A cluster of fixes tightened lockfile reuse, injected-dependency dedupe, frozen-lockfile checks, peer handling, tarball/spec parsing, and workspace sync behavior. Several of these address real correctness bugs that could yield stale installs, mismatched lockfiles, or failed concurrent imports.
