### **Fix frozen installs rejecting out-of-range link targets** (492ef47)
Frozen install freshness checks now validate `link:` targets against the requested semver range instead of blindly accepting any linked version. This closes a case where a workspace link could drift outside the declared range and still pass freshness checks.

### **Make Windows auto imports prefer hardlinks first** (97ba6ed)
On Windows, `packageImportMethod: auto` now follows the Linux order and tries hardlinking before cloning. That improves warm-store installs on Dev Drive/ ReFS and avoids unnecessary clone work; it also falls back more gracefully when hardlinks are refused.

### **Report stale link removals once, with better version info** (ac6e638)
pnpm now suppresses repeated reports for the same deduped direct link removal and includes the package version when a `link:` dependency is removed. That makes install output less noisy and more precise across both linker stacks.

### **Rebase relative `workspace:` paths during legacy deploy** (d3c660e)
Legacy deploy now rebases relative `workspace:` specifiers the same way it already handles `file:`, `link:`, and bare paths. This fixes deploys that previously failed to resolve copied workspace dependencies from the deploy directory.

### **Invalidate publish replay after unpublishing in pnpr** (5052022)
pnpr now rechecks publication state before replaying an earlier publish result, so retries won’t resurrect a version that has since been removed. The change covers partial and full unpublishes and keeps the metadata transaction flow idempotent.

### **Add Python upload validation and file recovery APIs** (879f343)
Python publishes now verify archive metadata more strictly, rejecting duplicate or mismatched package identity and doing the archive checks on blocking workers. pnpr also gained file yank/delete management routes, letting publishers change file yank state and admins delete stored files while preserving archive bytes.

### **Offload and cache pnpr packument rendering** (f44657b)
Large metadata rendering moved off async request threads and now uses bounded worker capacity plus response-byte caching keyed by source bytes and rendering context. That reduces head-of-line blocking for unrelated registry traffic and makes repeated packument reads cheaper.

### **Fix deduped link pruning by comparing resolved targets** (e6b8c18)
Stale-link pruning now dedupes `link:` dependencies by their resolved target instead of raw lockfile text. This prevents valid links from being pruned just because two importers spell the same directory differently, and it improves reporting for hoisted link removals.

### **Name failed pinned-pnpm downloads when no native binary is found** (27d250a)
When a pinned pnpm’s platform binary fails to download, the CLI now records the skipped optional dependency even if the warning is filtered out. That makes the failure source visible instead of surfacing only a generic “no native binary found” error.

### **Resolve filtered installs against workspace projects missing from disk** (2d23527)
Filtered installs in sparse checkouts now include the missing projects’ dependencies when resolving peers and optionality. That keeps the lockfile aligned with a full checkout instead of changing peer resolution just because some workspace folders are absent.

### **Coordinate child process spawns across crates** (d20e71f)
The process watchdog and runtime command paths now share a coordinated spawning lock to avoid inheriting partially initialized pipes. This is a cross-crate fix for rare spawn races that could corrupt child process setup.

### **Keep rejected optional peers unbound through dedupe** (2b964ef)
If every candidate for an optional peer is rejected, dedupe now preserves that project’s unbound state instead of collapsing it into another variant that happened to resolve the peer. This avoids reintroducing peers the project explicitly could not accept.

### **Hash tarballs while writing their files** (6ac0f8b)
Tarball extraction now overlaps integrity hashing with file writes instead of doing the hash pass serially after extraction. That removes idle time from the eager extraction path and improves package install throughput.

### **Spend only one retry budget on a persistently failing archive** (54b47d3)
Failed prefetches no longer get retried again with a fresh full budget during install. A tarball that keeps failing now consumes the intended retry budget once, which shortens stalls and makes failure timing consistent.

### **Run more CLI installability checks across every workspace project** (11fd10a)
Install-time engine and platform compatibility checks now cover every discovered workspace project, not just the root. That means incompatible `engines`, `os`, `cpu`, or `libc` constraints are surfaced earlier and more consistently.

### **Fix optional peer selection when required peers are registry-resolved** (c1e507d)
Optional peer candidate checks now follow required peers even when those peers would be resolved from the registry rather than already-existing workspace nodes. That closes a hole where a candidate could look valid until its own dependencies were considered.

### **Add a safe worker cache policy for pnpr metadata** (6f8b2a7)
pnpr now has a dedicated Cloudflare Worker cache policy that separates representation selection, validation, and cache keying safely. It avoids incompatible cache hits and preserves registry-side freshness rules while still enabling caching.

### **Exclude response-body timeouts from circuit breaker failures** (9ba8331)
pnpr no longer counts slow response bodies as circuit-breaker failures once the response head has already arrived. That keeps the breaker focused on real upstream failures and improves the diagnostics returned on 503s.

### **Refactor deps-restorer link claiming and stale-shim pruning** (991b50c)
The deps-restorer now uses a single claimed-commands map and unified stale-shim pruning logic across linkers. This is a broad internal cleanup that removes divergence between isolated and hoisted behavior.

### **Reject os-only platform inference for optional deps** (d8ceeec)
Platform inference for optional dependencies now requires more than just an OS token when the package declares no platform fields. That prevents cross-platform packages from being incorrectly skipped due to name-only heuristics.

### **Share stale direct-dependency pruning between linkers** (40be929)
The hoisted linker now reuses the isolated linker’s stale-link diff instead of carrying its own forked copy. That fixes cases where hoisted installs missed removals or pruned the wrong links.

### **Deploy workspace packages from their publish directories** (2ca2fb4)
Deploy now correctly includes workspace packages that are published from a separate `publishConfig.directory`. This fixes shared-lockfile deploys that previously produced missing dependency entries and lockfile validation failures.

### **Accept unclean TLS closes in self-update signature checks** (2849366)
Self-update verification now tolerates a TLS-intercepting proxy that closes the connection without a clean shutdown alert. That aligns signature verification with the resolver’s more robust body handling and prevents false failures behind such proxies.

### **Warn on incompatible root engines during install** (ed02820)
Install now checks the root project’s `engines` more consistently, warning for incompatible Node versions and failing for incompatible `engines.pnpm`. The repeat-install fast path also now respects those checks before claiming everything is up to date.

### **Stop reporting lifecycle failures for Ctrl+C-interrupted scripts** (9f8c6bd)
`pnpm run` no longer treats a user-interrupted script as a lifecycle failure when Ctrl+C is the cause. That makes interrupt handling cleaner and removes a source of flaky signal-related tests.
