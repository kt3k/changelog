### **Loaded store install mode lands with GVS exclusions** (8aec506)
pnpm adds an opt-in CAS-based installer plus a synchronous Node.js module loader, wiring it through the CLI and store-pruning paths. It keeps ordinary GVS installs for materialized trees while loading compatible files directly from verified store blobs, which is a major new install mode.

### **Metadata resolution gets faster with an indexed mirror** (b065ea3)
The registry metadata cache moves to an indexed mirror layout with lazy version hydration, so resolution no longer has to parse every version manifest up front. pnpm also starts pruning legacy metadata caches from older versions, and the first install after upgrading will repopulate the cache.

### **Multiple security fixes harden install, fetch, and publish paths** (68445b2)
This day includes broad hardening for dependency verification and archive handling: config dependencies are verified before install, tar metadata and package entries get size bounds, and deploy/publish paths are constrained. The changes also add safer signature checks and reduce memory exposure when processing large tarballs.

### **Global virtual store path traversal is blocked** (6bfdae0)
pnpm now validates package versions and enforces slot containment in the global virtual store, preventing crafted versions from writing outside the store. That closes an important filesystem escape in installs that use `enableGlobalVirtualStore`.

### **Lockfile verification now checks variations wrappers** (f31a16f)
Verification now inspects the inner resolutions inside `variations` wrappers and rejects empty variations entries for registry-shaped keys. This closes a gap where malformed lockfiles could bypass registry validation in fresh environments.

### **Login-shell setup keeps PNPM_HOME first on PATH** (009521c)
`pnpm setup` now preserves `$PNPM_HOME/bin` at the front of PATH even in login shells that inherit and reorder PATH, like macOS VS Code terminals. That prevents another `node` from shadowing pnpm's global runtime shim.

### **Host socket scheduling favors metadata over queued downloads** (64dbbb1)
When `maxSockets` or a proxy caps per-origin connections, metadata requests no longer wait behind earlier tarball downloads on the same origin. This should improve large-install latency and cut down on noisy request-time warnings.

### **Install and resolver behavior is tightened across the board** (various)
Several fixes close correctness and safety gaps: pnpm now rejects invalid dependency specifiers, handles unsupported protocols more clearly, preserves empty `nodeOptions` overrides, and validates git repository arguments. Other fixes improve lockfile repair, audit/update behavior, config warning reporting, and Windows job-control cleanup.

### Other misc changes
- Documentation and security-policy updates, including SECURITY.md wording changes.
- CI/build/dependency maintenance and small refactors.
- Test-only coverage expansions for the fixes above.
- Miscellaneous CLI polish such as setup messaging, `dlx` error handling, and config output tweaks.
