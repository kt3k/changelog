### **Install now records the right inputs for dependency checks** (f459cd4)
Filtered and frozen installs now track the actual workspace manifests and settings they used, so dependency verification no longer mistakes stale state for freshness after registry or scope changes. The same work also preserves pruned exclusion policies and lockfile digests so later checks can reproduce what the install really did.

### **Fetched package names can no longer forge lockfile package IDs** (ac5607e)
pnpm now rejects tarball, git, and directory dependencies whose manifest name could be crafted into a registry-style package ID. This closes a lockfile integrity hole where a maliciously named package could be recorded under the wrong package entry and confuse later resolution.

### **Manifest-format handling is fixed for linked and local projects** (f472566, 5da3ff0, cb7a82f)
pnpm now consistently reads `package.yaml` and `package.json5` for workspace projects, local directory dependencies, frozen lockfile checks, and legacy deploy flows. That fixes several regressions where installs, bin linking, file copying, peer resolution, or deploy would fail or silently behave as if a manifest were missing.

### **Store prune now cleans up more of what installs leave behind** (9e9de77, 8f0da4c)
Store pruning now removes global virtual store slots after the last project is deleted, and also reclaims unused Python environments and Cargo crate slots. Installs now register the projects they use, so prune can safely distinguish live store data from leftovers instead of keeping everything forever.

### **pnpr now reports cache and routing metrics, and listens correctly on port zero** (32b2902, 5f4ec97, 735f3cc)
pnpr gained Prometheus counters for resolution cache hits, misses, stores, and tarball routing decisions, which makes operator debugging much easier. It also now advertises the real bound port when started with `--listen :0`, and maintenance commands log to stderr so exported YAML stays clean.

### **Environment writes are now checked for thread safety at the moment of write** (dc3a577)
The CLI now batches environment updates and applies them only after verifying the process is still effectively single-threaded. That makes the `SingleThreaded` safety guard enforceable instead of relying on a convention that callers could accidentally violate.

### **Peer and dependency verification got stricter and more accurate** (2533e92, 202ae59, 4a7099f)
pnpm now handles pruned exclusion settings correctly when verifying installed dependencies, and peer resolution drops optional peers once their last provider disappears. Additional tests lock in peer-convergence behavior across lockfile formats and install modes.

### **A scheduler/config refactor and a crate-layers tool landed** (3cf4d63, 9a16873, c569971)
These commits reduce transitive dependencies in the workspace/config stack and add a new `crate-layers` analysis tool for finding overlapping state decisions in Rust modules. They’re mostly internal architecture and developer-tooling work, but they support ongoing refactors across the repo.

### Other misc changes
- Cargo dependency bumps (`prost`, `rusqlite`)
- pnpm/update automation refreshed Node.js, pnpm, GitHub Actions, and lockfiles
- Minor test/workflow/config updates across the repo
