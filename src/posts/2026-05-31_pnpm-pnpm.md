### **Server-accelerated installs via `pnprServer`** (54d2b57)
pnpm now supports an opt-in `pnprServer` mode that offloads dependency resolution and local-store missing-file calculation to a `pnpr` server. The server streams back only what the client is missing, while `node_modules` is still linked locally from the server-produced lockfile, which should cut install latency without changing the final local materialization.

### **Fix inconsistent peer resolution through diamond dependencies** (1db05c6)
A peer-dependency bug was fixed where pnpm could reuse a hoisted instance of a shared peer that had been resolved in the wrong context when dependencies formed a diamond shape. This prevents mismatched peer resolution for packages like the `@typescript-eslint` stack and keeps the plugin/parser/type versions consistent.

- Added new `pnpr`/`pnpr-fixtures` license exceptions and clarify entries for cargo-deny
- Wired the new `pnpr-server` CLI/config plumbing into the install flow
- Added tests, fixtures, and changeset entries for the new install mode and peer-diamond fix
- Minor workspace/dependency manifest updates
