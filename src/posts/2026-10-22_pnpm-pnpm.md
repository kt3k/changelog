**pnpm add now locks the version you asked for** (2f4535c)
`pnpm add <pkg>@<tag>` and `pnpm add <pkg>@<range>` now preserve the concrete version that was resolved, even if the saved semver range would later admit a newer one. This fixes a subtle but user-visible drift where re-installing could lock a different release than the one originally selected.

**pnpr auth stops poisoning its libsql/Turso backend on interrupted requests** (26047ac, 30f6d58, ae47bbf, 79b4dd2, f880d91)
A cluster of fixes hardens pnpr’s remote auth storage: it now uses a connection pool instead of one shared libsql connection, bounds reads and writes correctly, and avoids leaving the database wedged after timeouts or disconnects. The embedded replica path also now works with Turso Cloud, and unique-constraint / baton / replica-sync edge cases are handled more reliably so logins and startup no longer fail spuriously.

**pnpm gains first-class `--env-file` support** (7e8e991)
The CLI can now load dotenv-style files before command execution, with later files overriding earlier ones while preserving already-set environment variables. That makes config interpolation and lifecycle scripts see the loaded values without needing an external wrapper.

**Git dependencies are built in every slot they’re linked into** (be4d6f5)
pnpm now rebuilds git-hosted dependencies whenever the same commit is linked into a new store slot or fresh `node_modules`, instead of only building the first time it was fetched. That closes a class of broken installs where later links could skip required build outputs.

**File mode handling no longer has a race window on Linux** (9c11ea9)
The Linux umask reader now avoids temporarily writing a different process-wide umask just to read it back. That removes a concurrency hazard that could briefly create files with broader permissions than intended.

**Standlone builds now embed a newer Node.js runtime** (5154bf8)
The standalone executable is updated to bundle Node.js 26.12.1 instead of 26.0.0. This matters because the older runtime predates the October 2026 CA distrust update.

**Signal handler chaining now preserves the expected handler form** (40fab6f)
The fs layer fixed signal forwarding so a replaced handler is invoked with the details its original registration expects. This prevents crashes or corrupted arguments when chaining through `sigaction` handlers installed with `SA_SIGINFO`.
