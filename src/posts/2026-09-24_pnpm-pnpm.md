### **`pnpm install` gains selective build-script approval** (7cada4b)
`pnpm install` now supports `--allow-build`, letting users approve or deny lifecycle build scripts per package and persist those decisions in `pnpm-workspace.yaml`. That’s a significant new control for supply-chain and reproducibility workflows.

### **`pnpm pack` / `publish` now include bundled deps with the isolated linker** (f2a7a8d)
Bundled dependencies are now resolved and packed correctly even when using the isolated linker, including workspace packages and nested bundled deps. This closes a packaging gap that could produce incomplete publish artifacts.

### **Filtered audit now only scans selected projects** (9860520)
`pnpm audit` and `pnpm audit signatures` now respect `--filter`, `--filter-prod`, and `--workspace-root` instead of auditing the whole workspace. That makes audit output match the requested scope and avoids noisy or misleading reports.

### **`pnpm publish` honors scoped `publishConfig` registries** (72ff479)
A package’s `publishConfig["@scope:registry"]` now takes precedence when publishing scoped packages. This fixes registry routing for scoped publishes and prevents accidentally sending a package to the wrong registry.

### **Workspace graph and filter selection got several correctness fixes** (e67cd11, e08c81d, 181de39, df5b57d, ff7c94c, b809cfd, a5cb55a)
Several workspace-selection bugs were fixed: npm aliases and catalog entries now produce the right graph edges, filter ordering with inclusions/exclusions is preserved, `[<since>]` compares against the merge base, moved files are detected across packages, and catalog version changes are now treated as workspace changes. These are high-impact because they directly affect recursive commands, filtering, and dependency ordering.

### **Install freshness and repeat-install checks became much stricter** (475b2d1, 58e95a7, 8e2e66c, 2ebf755, 79cdc66)
Repeat installs now relink dangling direct dependencies, frozen installs fail when a workspace project is missing, frozen installs reject drifting workspace deps, and `--ignore-pnpmfile` no longer trips false lockfile mismatches. A custom `modulesDir` also no longer breaks the fast path.

### **Windows and cross-platform filesystem handling saw major hardening** (798feff, 0543299, d970a6c, 96f014b, 8c5ac9d, e2b6a7c, 713bccf, 0603ce0)
This batch fixes several Windows and WSL pain points: SSL-policy probes no longer crash, locked node_modules now report a clear in-use error, file-lock retries work in WSL, temp files clean up on interrupt, setup avoids truncating busy alias scripts, PATH filtering in shims is safer, and path/filename normalization handles UNC shares and trailing dots/spaces.

### **Dependency resolution and fetch identity got multiple bug fixes** (393f31a, 4bdabad, 682dd77, 658af83, 159fea9, 0e96a30, 45b3a09, 7a11d4b, 3db39c7, f41c7c3, 475c869, 9ad0bd0)
The resolver and fetch pipeline got a broad correctness pass: custom fetchers/manifests are recovered consistently, identity lookup is aligned between resolution and install, pinned pnpm versions are fetched into the store, prerelease-to-stable transitions re-resolve properly, default-port tarball URLs are normalized, trust-downgraded releases fall back to older satisfiable versions, and several edge cases around package extensions, aliases, and catalog preferences were fixed.
