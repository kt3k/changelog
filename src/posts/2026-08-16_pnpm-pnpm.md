### **Global virtual store is now the default** (5b11d3a)
pnpm 12 now enables the shared virtual store everywhere, materializing packages once per machine and reusing them across projects instead of recreating them per-project. That cuts duplicate disk usage and install work, but it also changes how dependencies are resolved under the hood, so the old project-local layout is now an opt-out.

### **Script resolution keeps working with the shared store** (ae462e1)
When the global virtual store is on, pnpm now injects `NODE_PATH` and an ESM loader hook into spawned commands so both CommonJS and ESM scripts can still resolve hoisted and phantom dependencies. This closes a major compatibility gap for `run`, `exec`, `dlx`, and lifecycle scripts under the new default layout.

### **Cold installs should finish much faster** (494f21d)
Install work that used to happen serially now overlaps: lockfile verification runs alongside resolution/materialization, metadata fetches are queued more efficiently, and linking can proceed while downloads are still in flight. The practical effect is less idle time on cold-cache installs and fewer wasted re-fetches.

### **pnpr now declares registry details explicitly** (c9b8632)
pnpr resolve requests now carry full registry declarations keyed by URL, including scopes, prefixes, and registry server type, instead of only a prefix map. That lets pnpr resolve scoped packages from the correct registry, match tarball URL reconstruction more accurately, and avoid relying on stale per-install registry data.

### **Tarball URL canonicalization no longer strips encoded slashes off non-npm registries** (dabbb77)
pnpm now keeps percent-encoded scoped tarball URLs verbatim for registries other than `registry.npmjs.org`, preventing 404s on servers like GitHub Enterprise that only serve the encoded path. Public npm registry URLs still get the old canonicalization behavior where it is safe.

### **Worker shutdown no longer leaves the process hanging** (2d0d75c)
A late worker task arriving after `finishWorkers()` used to recreate a pool that was never torn down, which could keep `pnpm install` alive after it printed completion. The fix preserves the finished pool reference so straggler work can be handled without leaking a live thread.

### Other misc changes
- Registry config renames and cleanup across the Rust crates and workflows (fe8ec8f)
- Benchmark workflow now measures the shared virtual store layout (a6e8159)
- `.modules.yaml` no longer records registries; installs now trust config (c9b8632)
- Various tests and changesets updated for the new defaults and protocol shapes
