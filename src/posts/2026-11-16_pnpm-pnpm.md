### **pnpr PostgreSQL writes no longer stall in transaction pools** (4a116e8)
pnpr now takes its PostgreSQL schema/write lock inside the transaction instead of relying on session advisory locks. That fixes writes timing out behind PgBouncer transaction pooling and keeps the migration/locking model correct for pooled connections.

### **get-pnpm falls back when registries omit version docs** (cb960b6)
The native binary downloader now works with registries like Azure Artifacts that 404 on per-version documents and may strip npm signatures from package docs. It falls back to package metadata for the version entry and, when needed, fetches npm signatures from registry.npmjs.org so first-run installs still verify correctly.

### **Global packages get their own config section** (c40244a)
`globalPackagesConfig` is now treated as the home for settings that only apply to global installs, including build approvals and trust-policy exclusions. The change also tightens credential censoring/owner-only writes and adds warnings for settings that belong elsewhere.

### **Patch application preserves the last line in unterminated files** (7f41ed8)
`pnpm patch-commit` and related patch application paths no longer drop the final inserted line when appending to a file whose last line lacks a trailing newline. This fixes a subtle truncation bug in patched files.

### **verify-deps respects runtimeOnFail during manifest checks** (38e2a0b)
The before-run dependency gate now applies `runtimeOnFail` the same way install does, so it stops flagging freshly installed manifests as out of sync. Workspace-wide selection paths also propagate the override consistently, avoiding accidental runtime installs that the policy should block.

### **pnpr 1.0 schema is frozen and alpha databases are rejected** (a1884a7)
pnpr collapses its schema baseline to a clean 1.0 starting point and refuses older alpha databases unless they are wiped and recreated. The schema logic also normalizes PostgreSQL collations so ordering matches the other backends.

### **Fetch now handles dedicated workspace lockfiles per project** (e1b970f)
`pnpm -r fetch` now fetches each selected workspace project against its own lockfile when `sharedWorkspaceLockfile` is off. That makes recursive fetch behave correctly with per-project lockfiles and preserves explicit lockfile-directory overrides.

### **Lockfile conversion recovers hashed peer providers across cycle cuts** (880d5c4)
Converting older lockfiles to v13 now has a smarter fallback for hashed peer-provider recovery when dependency cycles cut off nested groups. This removes a conversion failure for a tricky peer/cycle combination that previously could not be represented.

### **pnpm update keeps engines.pnpm in sync with the packageManager pin** (5c0c4e2)
Updating pnpm now rewrites the `engines.pnpm` constraint along with the package manager pin, preventing the next install from failing its engines check. The fix is scoped to v12 behavior and closes an inconsistency between update and install.
