### **Workspace engine checks now follow the runtime pnpm downloads** (26524b4)
pnpm now validates a workspace project’s `engines.node` against the Node.js version it downloads via `devEngines.runtime`, instead of always using the shared Node.js. That avoids false `engineStrict` failures when a project actually runs on its own compatible runtime.

### **pnpr moves authoritative registry state into metadata storage** (7ca6d00)
pnpr now stores package ownership, tombstones, team rosters, rule overrides, SCIM users, and staged-publish metadata in the metadata database. This makes commit boundaries and backup/consistency semantics much cleaner, but it also changes the metadata schema and requires resetting existing alpha deployments.

### **Cancelled tarball work now releases waiting cache slots** (99f26bc)
A cancelled archive read or download could leave a tarball marked “in progress” forever, causing later callers to hang waiting on that key. The new claim guard ensures those slots are always released unless the operation fully settles, fixing a real install deadlock.

### **Hoisted filtered installs now drop workspace projects missing from disk** (ffe5663)
Under `nodeLinker: hoisted`, sparse checkouts and other missing-project cases no longer keep stale workspace importers around. pnpm now prunes packages that only belonged to the missing project instead of recreating its `node_modules` tree and polluting the shared root install.

### **Commands now resolve the correct modulesDir for each project** (e552011)
pnpm’s command-line entry points now find each project’s modules directory the same way the installer does, including `modulesDir` values outside the project tree. That fixes `pnpm bin`, `run`, `exec`, and `version` looking in the wrong place for workspace projects.

### **pnpr now redacts malformed URLs more safely** (66f784b)
URL redaction now treats `?` and `#` as potential secret boundaries before `@`, instead of stopping too early and leaking credentials in malformed URLs. This closes an easy logging leak in error paths.

### **OCI repository cleanup and blob-deletion errors are corrected** (100d5af)
When the last manifest is deleted, pnpr now removes the empty OCI repository record instead of leaving a dead image document behind. It also returns `403 DENIED` when blob deletion is refused because the blob is still referenced, matching the registry semantics more closely.

### **Publish retries now recover reclaimed archives** (f813957)
Publish requests that lose their selected archive incarnation to a reclaim can now retry from the original request, up to four times. This keeps publish behavior resilient under concurrent reclaim/unpublish activity without bypassing the existing validation and staging logic.

### **`modulesDir` symlink resolution now uses the real path** (c17d625)
When an absolute `modulesDir` points through a symlink, pnpm now computes relative `link:` targets from the real path instead of the spelled path. That fixes broken links and missing bins on setups like macOS paths that traverse `/var` symlinks.

### **pnpr logs archive removals when garbage collection deletes them** (55c382c)
Archive deletions from GC are now audited immediately after each successful removal, even if a later step fails. The logging now carries enough repository/namespace context to make the audit trail usable.

### **Cargo index responses now support conditional GETs** (e86ce00)
pnpr now generates ETags for sparse Cargo index content and honors conditional requests after it has resolved the source and checked access. That allows proper 304 responses and avoids unnecessary payload transfers for cacheable registry reads.

### **Windows link failures now explain broken network-share behavior** (c930aaa)
If link creation fails on a UNC path or mapped network drive, pnpm now wraps the error with a message explaining that the share may reject symlinks and junctions. This makes a common Windows failure mode much easier to diagnose.

### **npm package responses stop leaking storage metadata** (e0d8cc6)
pnpr now strips internal `formatVersion` and null access metadata at the npm response boundary while preserving the public package shape. That keeps storage details out of registry responses without changing the actual stored documents.

### **Every project’s bins now flow through one linking path** (1efbcc4)
The deps-restorer bin-linking paths were consolidated so `.bin` writes go through a single implementation. This reduces linker drift between install phases and makes bin selection rules consistent across direct, hoisted, and top-level cases.

### **Publish and unpublish errors are clarified and hardened** (40cf3ce)
pnpr now validates unpublish versions against the same semver rules used for publish before touching storage, and publish rejects build metadata earlier in the validation flow. Cloudflare Worker failures are also normalized into a clearer availability response.

### **Filtered install and modulesDir behavior are aligned across passes** (79fdba6)
The last install passes that build a project’s modules directory now use the same configured root modulesDir consistently, including hoisted-linker cleanup, loaded-linker shims, and lifecycle script bin wiring. This closes a class of mismatches where different passes derived different directories.

### **Cloudflare Worker docs now handle malformed paths correctly** (3a5ecaf)
The deployment guide’s Worker example now validates percent-encoded paths at the entry point and handles URI errors explicitly. The docs and example tests were updated to match the real runtime behavior.

### **Deps-restorer bin linking and entry-bin handling were simplified** (e4d3499)
The code now splits entry-bin linking into separate paths for symlinked and unsymlinked cases, removing an unnecessary lookup from the simpler branch. It’s a cleanup refactor that should make the logic easier to follow and maintain.

### **Importer modulesDir handling is now consistent across restore paths** (faa36a8)
The fresh-resolution and frozen-lockfile paths now agree on how each importer’s modules directory is derived, especially when `modulesDir` is absolute or relative outside the project. This is a broad linker/install refactor that fixes several downstream inconsistencies.

### **Account registration and team visibility were tightened** (e3eef48)
pnpr now applies stricter authorization and password-validation rules across account, team, and SCIM flows, while also enforcing confusable-username uniqueness. The identity model changes are substantial enough to require fresh state for some deployments.

### **Dist-tag mutations now validate targets and tag names properly** (3d4c592)
Tag writes now go through shared storage-side validation, including tag-name parsing and target existence checks inside the write transaction. That reduces the chance of accepting malformed or inconsistent tag state during registry mutations.

### **Registry writes that can trigger OTP now send `npm-command`** (24ff92a)
pnpm now includes `npm-command` on registry writes like access, owner, team, deprecate, and dist-tag operations so the registry can offer the correct auth flow. This fixes browser-based 2FA handling for security-key-only accounts.

### **Recursive runs now check every workspace project’s requirements** (b7fc6b3)
`pnpm run -r`, `pnpm exec -r`, and single-project workspace adds/removes/updates now check the engines and platform requirements of every workspace project, not just the ones being acted on. That closes a gap where incompatible workspace projects could be ignored until later.

### **Python core-metadata sidecars are now proxied correctly** (00ea942)
pnpr now serves and rewrites PyPI core-metadata sidecars through the registry’s own metadata handling instead of treating them as a special-case blob. That improves compatibility with pip and keeps sidecar resolution tied to the package’s origin.

### **Loaded linker now materializes builds automatically** (7767e8a)
Packages with build requirements can now be materialized from the store in `nodeLinker: loaded` without being manually listed in `nodeLinker.excluded`, as long as the side-effects cache is available. This makes the loaded linker much more practical for real projects and adds filesystem-import detection for automatic materialization.

### **Worker metadata cache reads are revalidated instead of going stale** (ba8a559)
The Cloudflare Worker example now rechecks cached metadata with the registry and merges 304 responses instead of trusting local cache invalidation alone. That avoids serving stale packuments across data centers and gives the example a more realistic cache strategy.

### **Junction staging now cleans up after failure** (fdfdbe8)
If creating a Windows junction fails after the staging directory has already been created, pnpm now removes that empty directory instead of leaking it. This fixes a small but annoying retry-time filesystem leak, especially on SMB shares.

### **Install diagnostics now report incompatible dependency engines** (7178252)
The installer now routes dependency compatibility warnings through the shared reporting channel, with clearer separation between warnings, optional skips, and hard failures. That makes engine/platform/libc mismatches much easier to surface and test consistently.

### **NetBSD x64 release binaries will be built natively** (ef7956b)
The release pipeline now boots a NetBSD 10.2 VM on GitHub-hosted infrastructure and builds the CLI inside it. That sidesteps the sysroot/tooling limitations that prevented cross-building NetBSD x64 artifacts reliably.
