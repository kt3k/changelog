### **Tarball installs now honor Cache-Control and stream large archives** (bdd8e8a, be38158)
`pnpm install` now reuses fresh HTTP(S) tarball responses from the store, revalidates stale ones with `If-None-Match`, and avoids refetching lockfile-less tarball deps unnecessarily. Large gzip tarballs are also decompressed as a stream once unpacked size crosses 64 MiB, cutting peak memory usage substantially during extraction.

### **Detached HEAD installs can read branch lockfiles again** (d069377)
With `gitBranchLockfile` enabled, frozen installs now fall back to the lockfiles for local and remote-tracking branches that contain the checked-out commit. That fixes CI-style detached HEAD checkouts that previously failed with no lockfile even though the branch lockfile existed.

### **pnpr now links workspace projects at their publish directory** (b079732)
Installs going through a `pnpr` server now forward `publishConfig.directory` so workspace projects are linked from the directory they actually publish, not from the repo root. That prevents incorrect lockfiles and mismatched source-vs-build installs, and the server now rejects out-of-tree publish directories.

### **Quiet installs now keep failed script diagnostics visible** (c4875bf)
At `--loglevel warn` and `error`, failed lifecycle scripts now keep their buffered stdout/stderr so the real failure context is visible. Successful lifecycle output stays hidden, while warnings like ignored builds and failed verification still surface at the right level.

### **Windows setup and cmd shims got several correctness fixes** (b46d819, 787cfd1, 12032cc, 60e30e8, 79e7bf5)
Setup now runs `chcp` in the same console as `reg`, stops writing PowerShell wrappers for `pn`, `pnpx`, and `pnx`, and reports the current `PNPM_HOME` value in path errors. Cmd shims also handle Unicode paths correctly on Windows, and the registry value type for `PNPM_HOME` is repaired when needed.

### **Hoisting, rebuilds, and deploys were tightened up** (0198e2d, 9f59179, be6c05d, d3108b7, 08e4f88, f588fa0)
The hoisted linker now applies patches only once per distinct directory, cleans up orphaned nested package directories after interrupted installs, and avoids stale junction/race issues on Windows. Rebuilds and deploys also got safer: global-store rebuilds are isolated from unrelated packages, failed optional deps are removed from their GVS slot, and `pnpm deploy` now copies workspace deps instead of hard-linking them back to source.

### **Network and config resolution became stricter and safer** (328ac69, 48b1e54, 6a532e3, 69777a7, b8f6664, 40846fd, 99c832, c4eeecf, 0c4cac3)
Proxy selection now respects explicit config/env settings over OS proxy state, agent caches key off effective settings, env replacement only treats string values as set, and registry metadata is revalidated when caching is forbidden. Several config and lockfile checks were also tightened, including global-bin hints, frozen-lockfile behavior, compatibility DB scoping, and lockfile verification policy messaging.
