### **Atomic global installs now switch over cleanly** (5571fa2)
Global `pnpm add -g` / `pnpm update -g` now activate a new install by moving a stable hash link instead of rewriting all shims in place. That makes the switch atomic, avoids PATH gaps during install, and keeps the previous version available if activation fails.

### **Dependency resolution is now deterministic under contention** (2f76f98)
The resolver now settles child ownership one level at a time instead of letting whichever concurrent walk finishes first decide the recorded children. This fixes lockfile nondeterminism for the same input and addresses the exponential walk behavior noted in prior issues.

### **`pnpm add` skips full resolution when the version is already locked** (f100948)
Adding a package at a version already present in `pnpm-lock.yaml` now reuses that locked version instead of resolving the whole graph again. This speeds up common add flows like promoting a transitive dependency to direct or adding the same version to another workspace package.

### **Catalog and override rewrites now compose with other lockfile drift** (1d5741b)
Catalog and override updates no longer have to be the only change in an install to be applied in place. The fast-update pipeline now absorbs them alongside other manifest drift, and fixes cases where catalog and override rewrites previously wrote stale versions.

### **Shared virtual-store slots are repaired in place** (e9a3ca3)
When an install finds an incomplete package directory that another importer may still be writing, it now repairs that target instead of deleting it. This avoids `ENOTEMPTY`-style failures and protects concurrent shared virtual-store installs from clobbering each other.

### **`syncInjectedDepsAfterScripts` now actually resyncs injected copies** (7a2a480)
The CLI now honors `syncInjectedDepsAfterScripts` after named scripts and updates injected dependency copies back to match their source package. That prevents hardlinked injected packages from staying stale after build scripts rewrite files.

### **`minimumReleaseAgeExcludePrune` and catalog pruning are added** (1c42ae2)
A new workspace setting prunes stale `minimumReleaseAgeExclude` entries after add/update/remove writes the lockfile, and `cleanupUnusedCatalogs` is renamed to `catalogPrune`. This keeps workspace policy sections aligned with what the lockfile still resolves.

### **Global installs accept `--ignore-pnpmfile`** (c4c7bd7)
The install-family CLI now exposes `--ignore-pnpmfile` consistently across add, update, dedupe, fetch, unlink, and install. Previously pacquet rejected the flag before the install began.

### **Git resolver now handles more URL forms and better errors** (5610fef, cd73c55)
SSH git URLs without user info and bracketed IPv6 authorities are parsed correctly, fixing crashes during dependency resolution. Failed git fetches now report a clearer pnpm error that names the dependency and suggests the underlying transport problem.

### **Deploy and SBOM generation are tightened up** (d25c634, 14d7ac7)
Deploy now drops excluded optional edges from the deployed lockfile, preventing snapshots from referencing packages they no longer define. SBOM generation also stops including platform-incompatible optional packages that can’t actually be installed on the current machine.
