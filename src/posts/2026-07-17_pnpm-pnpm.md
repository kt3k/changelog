### **pnpm add gets faster and more deterministic** (2719b33)
`pnpm add` now resolves multiple selectors concurrently instead of serially, which should cut latency for larger add commands. The implementation also shares packument cache state and preserves selector-ordered warnings/errors so the speedup does not change user-visible behavior.

### **Peer dependencies now accept scheme-carrying specifiers** (76f5886)
Peer dependency validation was broadened to accept registry-scoped, `npm:`, `file:`, git, and URL specifiers instead of rejecting anything outside plain semver/workspace/catalog ranges. This closes a real compatibility gap and required updates across peer matching, hoisting, and related tests in both Rust and TypeScript.

### **Git specifier freshness checks now treat equivalent URLs as equal** (8e3e5e7)
Frozen install freshness now recognizes equivalent git specifiers like `git+https://` and `git://` instead of flagging them as stale. That avoids unnecessary lockfile refreshes when the repo, ref, and host are the same but the manifest uses a different supported git form.

### **Resolver recovers when metadata cache disappears after 304s** (34c4bf3)
A 304 response with no surviving cached metadata is now treated as a recoverable race rather than a hard failure. pnpm retries without validators and persists the fresh response, which makes installs resilient to cache cleanup and antivirus interference.

### **Exact version pins survive `pnpm update`** (053fab2)
Update logic now correctly handles `=` ranges, preserving exact pins like `=3.5.1` instead of rewriting them into looser ranges. This fixes a manifest mutation bug that could silently loosen dependency constraints during update flows.

### **Git-hosted packages now resolve cleanly into lockfiles** (7794d31)
The git resolver now reads the package manifest from the checked-out repository so it can derive a proper package name before graph-to-lockfile conversion. That fixes a crash when installing git-hosted deps and prevents lockfile entries from being emitted in an unparsable form.

### **Symlinked lockfiles are readable again** (21c053a)
`pnpm-lock.yaml` may once again be read through a symlink, which matters for sandboxed environments like Bazel and Nix. The write path still refuses symlinked lockfiles when bytes would change, but frozen installs now avoid rewriting an unchanged file entirely.

### **Install stats are rendered once in the default reporter** (61ed26e)
The append-only Rust reporter now buffers added/removed statistics and prints them once, matching the TypeScript CLI and avoiding duplicate stats blocks when the removed count is zero. It also flushes partial stats on run summary so missing events do not suppress output.

### **Fix broken lockfile errors to avoid leaking snippet content** (b62239d)
Parse failures for lockfiles no longer expose parser snippets from potentially unrelated files when the lockfile itself is a symlink. Diagnostics now rely on structured reason/location data, closing an information-leak edge case.

### **Latest-version selection respects minimum release age** (6fe0237)
`pnpm add <pkg>` and `pnpm update --latest` now route `latest` through the maturity-aware picker, so they pin a version that actually passes `minimumReleaseAge`. This keeps manifest updates consistent with the follow-up install and fixes a user-visible mismatch.

### **`pnpm run --sequential` returns, and regex script order is stable** (e7138af)
The `--sequential`/`-s` flag is restored for `pnpm run`, forcing workspace concurrency down to one. Regex-matched multi-script execution is also now sorted lexicographically, removing nondeterminism from script selection.

### **Git imports no longer panic on lockfile conversion** (7794d31)
Git-hosted dependencies now carry the package manifest through resolution so the lockfile builder can emit a valid named dependency entry. This addresses a crash in install flows that depend on git repositories.
