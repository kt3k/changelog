### **Support selecting and refreshing registry revisions** (bb09b50)
pnpm can now resolve explicit `<version>+rN` registry revisions across npm, JSR, aliases, and named registries, and `pnpm update --patches` refreshes artifacts without bumping package versions. The change also tightens frozen-install behavior and historical revision validation so revision-addressed packages stay immutable and reproducible.

### **Bound archive decoding memory usage** (369a9d6)
pnpm now decodes tarballs and zip entries with explicit memory ceilings instead of trusting archive metadata or registry claims. That closes off gzip-bomb style amplification during install while preserving installs that previously succeeded.

### **Pin the latest pnpm version from `pnpm init`** (c22eac2)
New projects are now scaffolded with the current pnpm release rather than whatever version happened to run `pnpm init`. That avoids freezing old pnpm versions into fresh repos and falls back safely when the registry lookup is unavailable or policy-rejected.

### **Enforce git prepare approvals on store reuse** (d3ebbed)
Prepared git dependencies reused from the shared store now still honor each project’s `allowBuilds` policy. This prevents one workspace’s approval from leaking into another and closes a warm-store bypass for prepared git packages.

### **Fix `pnpm config delete` trailing blank lines** (b87c7cc)
Deleting the last config entry no longer leaves behind an extra blank line, and insert/delete handling now preserves the document’s existing blank-line style more consistently. This is a correctness fix for workspace manifest editing.

### **Honor `ignorePackageManifest` and `pnpmHomeDir` in `@pnpm/napi`** (a10a6c3)
The NAPI install binding now matches pnpm’s real `fetch` semantics for `ignorePackageManifest`, and it finally respects `pnpmHomeDir` when choosing the default store path. That makes the native API behave like the CLI for these install options.

### **Install the workspace root under filtered installs** (1405c7c)
Filtered shared-lockfile installs now include the workspace root in lifecycle execution and pnpr requests without mutating its manifest. This fixes a long-standing mismatch between selection and materialization.

### **Validate unused patches during incremental installs** (6d1176f)
Patch validation now derives from the final pruned lockfile graph, so reused subtrees and unchanged workspace importers are checked correctly. That prevents incremental installs from missing patch coverage.

### **Deprecate `pnpmfile` `filterLog`** (95e23ff)
pnpm now detects `filterLog` once and warns that the Rust v12 CLI ignores the deprecated hook. It avoids adding per-event IPC overhead to the reporter hot path.

### **Stop recording Corepack integrity in `packageManager` pins** (e630a04)
Package-manager pins no longer store the tarball integrity as semver build metadata for Yarn Classic-style installs. The manifest now keeps only the version, which is the value pnpm can meaningfully rely on.

### **Preserve bundledDependencies on reused lockfile entries** (08a082f)
Lockfile reuse now carries synthesized `bundledDependencies` and libc shape information forward when rebuilding package metadata. That prevents unrelated entries from losing bundled dependency data during lockfile rewrites.

### **Sort dependency graphs in linear time** (d669c8b)
Workspace graph sequencing was rewritten to avoid rescanning every node for every topological chunk, cutting a major install/update bottleneck on very large dependency chains. This removes a pathological multi-second sort from large workspaces.

### **Accept `--production` as a `--prod` alias** (370dfd4)
The CLI now accepts `--production` wherever `--prod` is valid, which fixes the flag that pnpm itself reproduces for production-only `run` checks. This restores compatibility with an existing pnpm spelling and prevents argument-parser failures.
