### **Install, repeat-install, and dependency validation got a major unification pass** (7164fc7)
`pnpm run`, `pnpm exec`, and `pnpm restart` now forward install flags like `--lockfile-dir`, `--modules-dir`, `--store-dir`, `--offline`, and `--ignore-scripts` into the install they trigger under `verifyDepsBeforeRun: install`. The repeat-install and validation logic was also consolidated across v11 and v12, tightening filtered-install behavior and workspace-state handling.

### **`pnpm prune` now actually removes extraneous deps and respects workspace selection** (473ccce)
Prune was extended to work as a real maintenance command: it now removes extraneous direct dependencies even when the lockfile and manifest are already aligned, and it honors `--filter`, `--recursive`, and `sharedWorkspaceLockfile: false`. This also fixes cases where prune would short-circuit before cleanup ran.

### **`pnpm patch` and patch commit/remove now work in sharedWorkspaceLockfile: false workspaces** (f8ba6e1)
Patch workflows were reworked so patch resolution and `patchedDependencies` updates happen against the correct workspace root in dedicated-lockfile setups. `pnpm install` also now checks configured patches across all workspace projects before treating a patch as unused.

### **Workspace discovery and repeat-install fast paths were sped up** (95043cb)
Workspace project discovery was rewritten from repeated glob walks to a single-pass directory walker, cutting redundant filesystem traversal in large repos. The same changes also feed repeat-install logic, so both discovery and install freshness checks should be noticeably cheaper at scale.

### **Lockfile freshness now catches more stale local directory deps** (5584248)
Frozen installs now recurse through transitive local directory and injected dependencies, instead of only checking the immediate child snapshot. That closes a hole where stale nested directory deps could slip through and be installed silently.

### **`pnpm why` now reads the right lockfile per workspace project** (46aa513)
When `sharedWorkspaceLockfile: false`, recursive `pnpm why` now loads each selected project’s own lockfile and modules directory instead of assuming one shared lockfile at the invocation root. That fixes incorrect dependency reporting in split-lockfile workspaces.

### **`pnpm install` now succeeds with a symlinked `node_modules` root** (245e759)
Hoisting no longer rejects a symlinked `node_modules` directory just because the hoist root itself isn’t a real directory. Existing symlinked roots now work as long as they resolve to a valid directory, while deeper hoist targets still remain constrained.

### **`pnpm pack` now expands numeric brace ranges** (b237160)
The packlist brace expander now understands numeric sequences like `{1..10}`, including descending ranges, steps, and zero padding. That fixes both missing files in tarballs and ignore rules that failed to exclude numbered paths.

### **`pnpm deploy` outputs reproducible bookkeeping with `SOURCE_DATE_EPOCH`** (353379c)
Deploy now honors `SOURCE_DATE_EPOCH` when writing install bookkeeping files like `.modules.yaml` and `.pnpm-workspace-state-v1.json`. That makes repeated deploys of the same project stable enough for Docker layer caching and similar reproducible-build workflows.

### **`pnpr` packument rewrites now strip the server-only `dist.pnpr` overlay** (92b7467)
When a client round-trips a packument back through `PUT`, the server now removes the `dist.pnpr` overlay before immutability checks. That prevents valid partial unpublish/update flows from being rejected as if the extra field were a mutation.

### Other misc changes
- Fix setup on systems without registry write access, with fallback instructions instead of a hard failure.
- Make `pnpm licenses` handle empty results and lockfile scoping consistently.
- Surface tarball-verified `requiresBuild` metadata from pnpr and use it during install planning.
- Sync config-setting tables and workspace-manifest keys across pnpm v11/v12.
- Various test, CI, benchmark, and documentation updates.
