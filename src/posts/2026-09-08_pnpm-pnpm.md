**Cargo installs now reuse workspace metadata and support git-pinned crates** (e232574, 2f3ed22)
`pnpm install` can now vendor crates locked to a git revision, including `[patch.crates-io]` and git dependencies, so mixed Rust/npm workspaces can build those pins offline. The same area also got a workspace-discovery optimization that cuts repeated Cargo metadata calls in large monorepos by reusing manifest paths and canonicalized workspace roots.

**pnpr registries can be grouped by ecosystem and browsed via a directory endpoint** (c6cf52a, fb8625e)
Registry identity is now scoped by ecosystem and local name, with grouped config under `registries.npm`, `registries.cargo`, `registries.pypi`, or `registries.oci`. pnpr also adds a registry directory endpoint plus paginated `browse=true` search for hosted npm packages and Cargo crates, both respecting routing and access rules.

**Pipeline cache and hash handling got correctness fixes** (feca83e, 584b6c8)
Pipeline task keys now hash symlinked inputs by their link target instead of aborting on tracked symlinks, fixing cases where `pnpm pipeline` would fail before running. Registry metadata cache keys now include the full registry URL path and scheme, preventing different registries on the same host from sharing the wrong metadata.

**Package-manager and config behavior around installs got sharper** (6b84457, 005c6f3, ff88d94, bcf58f6)
Removal errors now name the specific `node_modules` entry that could not be deleted, which should make Windows/lock-related failures much easier to diagnose. `packageConfigs` now apply to per-project installs, boolean CLI flags accept explicit values like `--prod=false`, and deploy installs now load the source workspace's pnpmfile instead of the copied deployment copy.

### Other misc changes
- Hosted pipeline run records moved into the shared store so all replicas see the same history.
- `trustPolicyExcludePrune` was added and wired into workspace cleanup behavior.
- Windows atomic writes and cmd-shim/bin removal got lock-retry hardening.
- Dependency, release, CI, and documentation updates.
