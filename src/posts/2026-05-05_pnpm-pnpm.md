### **Restore npm-CLI-compatible `pnpm publish --json` output** (87b1c24)
`pnpm publish --json` once again emits structured per-package JSON on stdout, matching the contract downstream tools like `nx release publish` depended on. The fix also carries that shape through recursive publish and keeps the summary envelope intact where it already existed.

### **Prevent config commands from crashing on configDependencies** (16f5cd3)
`pnpm config`, `pnpm set`, and `pnpm get` now tolerate `configDependencies` install failures instead of aborting before they can write or read auth-related settings. Failures are downgraded to debug logs for those entry points only, so other commands still surface real install errors.

### **Fix env var and `.npmrc` loading for user-level config** (c969392)
`PNPM_CONFIG_*` is now accepted alongside lowercase `pnpm_config_*`, which matters on case-sensitive shells and for the v11 migration path. The config reader also consults `NPMRC_AUTH_FILE`/`USERCONFIG`-style env vars early enough to actually determine which user `.npmrc` gets loaded.

### **Preserve `pnpm-workspace.yaml` key order when updating** (0d791f3)
Workspace manifest writes now keep existing key order instead of re-sorting the whole file, while still inserting new keys sensibly when the file is already sorted. That reduces noisy churn in workspace config and preserves formatting like blank lines.

### **Keep recursive negative filters from pulling in the workspace root** (9018103)
`pnpm -r --filter '!pkg'` now correctly excludes the root by default, matching documented recursive behavior. This closes a regression where negative-only filters accidentally reintroduced the workspace root into the match set.

### **Allow user-level preferences in global `config.yaml`** (fcec623)
More user-scoped settings are now accepted from the global config file instead of being ignored as workspace-only values. That makes global config behave more like users expect for shell, trust, store, and resolution preferences.
