### **pnpm-registry replaces verdaccio and adds npm protocol endpoints** (d8a79a9)
The repo’s test harness now boots the Rust `pnpm-registry` server instead of verdaccio, and the server implements key npm registry flows: adduser/login, publish, dist-tag, and search. This is a major infrastructure shift that unblocks real registry behavior in tests and removes a brittle external dependency.

### **Repeat installs can now short-circuit to “Already up to date”** (c8c50ca)
`pacquet install` now checks workspace freshness up front and returns early when nothing has changed, instead of loading lockfile/resolver state and walking the full install pipeline. That should make repeated installs significantly faster and brings the fast path in line with pnpm’s `optimisticRepeatInstall` behavior.

### **Workspace installs now resolve every importer on fresh resolve** (ac299aa)
Fresh installs in workspaces now walk each project manifest, merge per-importer dependency graphs, and write one lockfile entry per workspace package. This fixes the bug where only the root workspace was being resolved, leaving sibling packages missing from both the lockfile and disk.

### **Workspace-linked bare semver deps now resolve correctly** (b7229f8)
The npm resolver now consults workspace packages for bare-semver dependencies when `linkWorkspacePackages` allows it, instead of always going straight to the registry. That fixes 404s for unpublished workspace packages and prevents silently linking the wrong registry package when names collide.

### **Lockfile manifest fields now preserve optional peers metadata** (cc4ff81)
`PackageVersion` now deserializes `optionalDependencies` and `peerDependenciesMeta`, which are required for downstream dependency extraction and peer handling. Without this, optional peers could be misinterpreted and auto-installed incorrectly.

### **Resolver verifier lookups are singleflighted** (7120ac0)
Concurrent verifier tasks now share one in-flight fetch per key instead of duplicating work in separate caches. This reduces wasted network/work during resolution and avoids race-driven cache stampedes.

### **Libc detection is now a dedicated Rust crate** (e52e4fc)
Graph hashing now uses a ported `detect-libc` implementation instead of ad hoc host-libc checks. The new fallback chain is more robust in minimal containers and should improve correctness where `getconf`/`ldd` aren’t available.

### **Workspace/package resolution got parity fixes for link and dep-path handling** (6b3ba4d)
Pacquet now short-circuits workspace `link:` entries before peer resolution and adds more faithful dep-path helpers. This prevents crashes on workspace-linked fixtures and fixes path parsing that previously produced invalid peer-bearing dep paths.

### **Optimistic repeat-install no-op path gets portable lockfile checks** (198c661)
The repeat-install fast path now requires `pnpm-lock.yaml` in the single-project case before treating the install as up to date. That preserves pnpm’s behavior of falling back to a real install when the lockfile is missing.

### **Trusted publisher evidence now requires provenance** (0721d64)
Resolver trust checks now only accept `TrustedPublisher` evidence when provenance is present on the version. That tightens the security bar for trusted publisher resolution and avoids treating incomplete metadata as sufficient evidence.
