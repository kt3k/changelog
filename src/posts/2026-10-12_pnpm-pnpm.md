### **Speed up Python dependency resolution with PEP 658 metadata** (0a286e7)
`pnpm install` now reads index pages and per-wheel metadata files in parallel, using published PEP 658 metadata when available instead of downloading whole wheels just to inspect requirements. That cuts unnecessary network traffic and makes Python resolution dramatically faster, especially for lockfile generation.

### **Add `pnpm profile` for registry account management** (3d3f8bb)
`pnpm profile` now supports viewing and updating registry profile settings, plus 2FA enable/disable flows against the registry user endpoint. This brings a long-missing npm-compatible account-management command into pnpm.

### **Add `pnpm token` for registry token management** (242d363)
pnpm now has first-class token management for listing, creating, and revoking registry auth tokens. It closes a notable CLI gap and lets users manage credentials without dropping to npm.

### **Introduce file-based store indexes for shared stores** (96dd753)
A new `storeIndexFormat: files` mode stores package index rows as individual files instead of SQLite `index.db`, which matters for shared or network-mounted stores where SQLite WAL locking is unsafe across machines. This is a substantial infrastructure change that avoids corruption in multi-host CI/cache setups.

### **Fix pipeline root selection in root-only workspaces** (9eda768)
`pnpm pipeline` now keeps the workspace root selected when the workspace only contains the root package or omits `packages`, matching recursive command behavior. That fixes a case where root changes previously produced misleading “nothing to run” behavior.

### **Fix lockfile tarball URL handling for scoped registries** (f01eab2)
pnpm now compares a package’s tarball URL against the registry its scope actually resolves to, rather than always the default registry. This prevents frozen installs from failing when a scoped registry URL was incorrectly preserved or omitted.

### **Fix native shims when the target is a hard link** (62e1a80)
The shim dispatcher now accepts a global target that resolves to the same file as the shim via hard link, instead of rejecting it as self-referential. This unblocks `pnpm setup`/global shim flows that were failing with a bogus “target points back at the shim” error.

### **Fix macOS hook workers from inheriting pnpm pipes** (e68c30a)
The pnpmfile worker now avoids inheriting the parent process’s pipes during macOS spawn races, preventing deadlocks where installability probes waited for EOF and the worker waited on open descriptors. This is a real stability fix for installs on macOS.

### **Fix Python backend hooks to inherit build PATH entries** (b3cde5e)
Backend hooks now get the build environment’s scripts directory on PATH, so tools installed as build requirements can actually be found during PEP 517 execution. That fixes backend builds that previously failed to locate their own helper binaries.

### **Fix auditing of runtime entries** (285a3d2)
Audit requests now skip runtime entries like `devEngines.runtime`, preventing them from being misinterpreted as package dependencies and flagged as invalid signatures. This removes a false-positive audit failure in v12.

### **Fix MinGW toolchain selection on Windows** (7225403)
The Rust toolchain installer now derives the Windows host ABI from the pnpm build target, so MinGW-built pnpm installs a compatible GNU toolchain instead of MSVC. That matters for Windows-native builds in MSYS2/MinGW environments.

### **Refactor workspace resolution into smaller phases** (70a168b)
The workspace dependency resolver was split into dedicated modules for options, importers, hoisting, and finish phases. This is a large internal refactor that makes the resolver more maintainable and easier to extend.

### Other misc changes
- Grouped package-map settings under new `nodePackageMap` config; old flags still supported.
- Store index path handling adjusted to use `index/` for the new layout.
- Config override and CLI plumbing updated for the new package-map mode.
- Dependency/workflow updates and test-only coverage additions.
