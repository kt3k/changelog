### **pnpr moves registries into the database** (24b88a9)
`pnpr` can now store and serve registry configuration from the metadata database instead of `pnpr.yaml`, with admin APIs and import/export tooling to manage revisions. This is a major architecture shift: config-file registry settings are now rejected, and the registry graph becomes revisioned state rather than deploy-time config.

### **dlx cache and policy handling are hardened** (758c633)
`pnpm dlx` now isolates its cache by active policy settings and no longer inherits workspace overrides/package extensions from a local `pnpm-workspace.yaml`. It also fixes negated `--allow-build` selectors so explicitly denied packages are blocked from build execution and approval flows.

### **Peer resolution is stabilized across reuse, cycles, and dedupe** (c1468d6)
A large resolver refactor makes retained peer contexts survive installs more reliably, including deduplicated peer dependents, cyclic provider graphs, and locked fallback reuse. This should reduce “same lockfile, different peers” churn and improve repeat-install determinism.

### **Workspace clean/purge/ci containment is fixed** (01ba3c1)
`pnpm clean`, `pnpm purge`, and `pnpm ci` now keep `modulesDir` and symlinked `node_modules` confined to the project root. That closes an unsafe-delete bug where external paths or symlinked directories could be removed outside the workspace.

### **Lockfile verification now respects registry changes** (144c52a)
Verification cache keys now include registry routing, so changing the default or scoped registry forces lockfile re-verification instead of reusing stale results. The fix also tightens pnpr revision verification when cached checks miss.

### **Install fetches no longer do hoisted work too early** (c17ab03)
Under `nodeLinker: hoisted`, `pnpm fetch` now defers hoisted patch/build work until the actual install phase. That avoids materializing or building hoisted dependencies during fetch, matching the intended split between cache population and install.

### **Workspace YAML env placeholders are handled more safely** (743855d)
Flow-style `pnpm-workspace.yaml` parsing now correctly rejects registry placeholders that must be expanded, while ignoring placeholders in certain config fields with warnings. The change also fixes restoration logic so environment placeholders survive parsing instead of being mangled or accidentally expanded.

### **Override selector specificity is corrected** (1311f2c)
When multiple override selectors match, pnpm now prefers the narrower version range instead of whichever entry happened to appear first. This makes override behavior deterministic and matches the intuitive “more specific wins” rule.

### **Diagnostics keep long paths and URLs unwrapped** (b389940)
Error reporting now preserves full diagnostic lines instead of wrapping them in terminal output and logs. That improves readability for long URLs and filesystem paths and prevents important context from being split across lines.

### **Other misc changes**
- Toolchain bumped to Rust 1.100.0, with follow-up pipeline cache fixes.
- `pnpr` storage/config refactors and documentation cleanup.
- NetBSD/release CI robustness fixes.
- CLI test/reporting tweaks, plus small internal refactors and release chores.
