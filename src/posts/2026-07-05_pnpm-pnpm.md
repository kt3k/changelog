### **Global runtime installs now work** (23996e9)
`pnpm runtime set <name> <version> -g` now goes through the global add path instead of erroring out, so Node/Deno/Bun runtimes can be installed into the global packages directory and linked into the global bin directory. The change also tightens runtime argument validation to avoid unsafe selector parsing.

### **CLI now accepts `--no-<flag>` for every boolean option** (1a3406d)
Pacquet’s clap-based parser now mirrors pnpm/nopt behavior by auto-generating hidden negations for boolean flags like `--no-frozen-lockfile` and `--no-dry-run`. This fixes a class of forwarded-command failures where valid pnpm invocations were previously rejected as unexpected arguments.

### **Fresh installs skip unsupported optional deps earlier** (2dabb31)
Optional dependencies for incompatible platforms were being prefetched before installability was computed on the fresh-lockfile path, which could waste downloads on packages that would never be linked. The installer now computes and threads skip information earlier, reducing unnecessary work and making fresh installs more platform-aware.

### **Top-level fallback commands now resolve like pnpm** (e0616d3)
Unknown top-level commands now fall through to the run/exec behavior pnpm users expect, enabling cases like `pnpm commitlint --edit ...` to resolve local binaries from `node_modules/.bin`. This closes a notable CLI compatibility gap between pacquet and the TypeScript implementation.

### Other misc changes
- Added tests for the new runtime/global-install path and boolean-negation parsing
- Refactored internal CLI config plumbing for global installs
- Updated installability/prefetching tests and supporting manifests
- Minor build/dependency metadata updates
