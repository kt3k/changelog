**POSIX shims no longer trust PATH for their shell helpers** (9c67641)
The generated POSIX bin shims now harden their header helper lookups so `readlink`, `dirname`, `sed`, and `uname` can’t be overridden by a dependency’s own binaries on `PATH`. That closes a shim hijack path where a package could influence which directory the shim resolves and execs from.

**Rust structs are now capped at eight fields** (9cd124f)
The repo enabled a new `too_many_struct_fields` lint and set `max_fields = 8`, then refactored oversized structs across pnpm/pnpr to group related state and pass grouped context through helpers. This is a sizable internal cleanup that also updates the style guide and CI assumptions for the new rule.

**pnpm now uses complexity-aware rustfmt** (2ea04e6)
The workspace switched to a pinned pnpm rustfmt fork with a cached wrapper used by local formatting, CI, pre-push checks, and editor integration. The formatter changes chain layout and destructuring behavior, so this affects how Rust code is rendered across the repo and in contributors’ workflows.

**Method-chain length is now linted in Rust code** (f607801)
A new style rule limits production method chains to nine calls, with tests exempt, and the Rust style guide now documents when to split chains. This also nudges a few internal helpers to satisfy the rule without changing external behavior.

### Other misc changes
- Dylint/perfectionist config updates and pinned revisions
- CI cache and workflow tweaks for formatting/lint tooling
- Documentation updates for contributor setup and Rust formatting
- Small internal refactors and test updates to match the style changes
