**Native global shims now replace context-aware dispatcher bins** (5514831)
pnpm’s global context-aware commands are now installed as native executables on every platform, so names like `node`, `deno`, `bun`, and `pnpm shim add` targets can receive environment variables that aren’t valid shell identifiers. The change also migrates older shims on the next global install/self-update and removes the old dispatcher path.

**`pnpm unpublish` now completes OTP challenges** (d52fc64)
Unpublish now recognizes registry 401s that are actually two-factor challenges and reuses the obtained OTP/web-auth session across the whole write sequence. That fixes logged-in unpublish for accounts with 2FA enforced instead of misreporting `ERR_PNPM_UNAUTHORIZED`.

**Linux now uses the system DNS resolver** (19ba4d4)
The network client switches away from Hickory DNS on Linux so pnpm respects the system resolver configuration instead of silently falling back to public DNS. This fixes installs in environments that block public resolvers or rely on local nameservers.

**Windows DNS lookups now avoid Firewall prompts** (64348e6)
Windows networking now takes the system `getaddrinfo` path instead of binding a UDP socket for each lookup, which prevents Defender Firewall from prompting on every self-update. The change also preserves NRPT and per-adapter DNS behavior.

**`pnpm add` now handles alias-less local, tarball, and URL specs** (8333a69)
The add command can now infer package names from local paths, tarballs, and direct URLs instead of treating them like registry names. This fixes a user-facing resolution failure that blocked common `pnpm add ./pkg`-style workflows.

**Interactive update prompts were rebuilt to match pnpm 11** (38e9b9c)
The old multi-select prompt was replaced with a checkbox UI that supports separators, proper headings, theming, and keyboard behavior closer to the TypeScript CLI. That makes `pnpm update --interactive` readable and usable again.

**`pnpm run`/`exec`/`rebuild` now load pnpmfile hooks** (50ca8c3)
Hook-driven config updates now run before script and execution commands spawn child processes, so settings like `extraEnv` and `extraBinPaths` reach those commands too. This brings the Rust CLI back in line with pnpm 11 and fixes a whole class of missing-hook behavior.

**Package metadata decoding now tolerates more registry shapes** (05308b6)
The registry parser learned to accept several manifest field shapes that npm and other registries emit differently, instead of skipping valid versions as undecodable. That prevents false “no version found for the latest tag” errors and improves error reporting when `latest` itself points at an unreadable manifest.

**Workspace installs got a large tail-latency reduction** (289ea59)
The resolver now shares the parsed `pnpm-lock.yaml` instead of deep-copying it before fresh resolutions, and builds the successor lockfile in parallel with other install work. This is a meaningful install-speed improvement for large workspaces.

**Resolver freshness checks and dedup cache work were parallelized** (72ae4cd)
Install tail work that scaled with workspace size was moved off the critical path: freshness gates now run in parallel, and dedup/cache scans avoid repeated O(n²) importer comparisons. This should noticeably reduce time spent after the main resolution phase on big monorepos.

### Other misc changes
- Dependency/tooling refreshes across Node.js, pnpm, GitHub Actions, and lockfiles.
- Release packaging for pacquet 12.3.0.
- Docs/style updates, including changeset writing guidance and help-text cleanup.
- Smaller CLI fixes around flags, config parsing, peer handling, WSL browser launch, and Windows file-lock retries.
