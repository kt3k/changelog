### **pnpr tightens web login and token issuance** (6d4a523)
`pnpr login` now prints the registry's `npm-notice` before the browser URL, which lets the CLI surface a one-time code for the user to type into the web flow. The same change also closes a session-token leakage path and makes passwordless tokens inherit the session/token expiry and CIDR limits.

### **pnpr binds hosted metadata to the correct store** (99a0f65)
Hosted storage now records a random `store_id` in `layout.json` and in the metadata database, and pnpr refuses to start or run GC/verify/export/migration when they disagree. That prevents one store's metadata from being applied to another store after partial restores or accidental reuse.

### **pnpr aligns the package owner model across registries** (c487c83)
Cargo, PyPI, and OCI now record explicit owners and default `publish` access to `$owners`, matching the safer npm behavior. This removes the old `$authenticated` fallback that let any signed-in user publish to someone else's package, crate, or image repository.

### **pnpr fixes hosted namespace naming and registry config** (9d75d82)
The hosted storage partition is standardized on `namespace` instead of a mix of org/catalog/organization names across config, SQL, transparency logs, HTTP routes, and docs. The refactor makes the storage model consistent and reduces the chance of mismatched configuration or diagnostics.

### **pnpr normalizes auth, SCIM, and rule storage before 1.0** (d964a35)
This splits several overloaded auth tables into dedicated SQL tables and replaces whole-document state blobs with more focused records ahead of the 1.0 freeze. It also updates SCIM, team roster, rule override, and token/user-store code to use the new schema.

### **pnpr tightens registry policy echoes and capability discovery** (eea5a8b)
Resolve and lockfile verification responses now must echo complete policy state, so clients can detect older or incomplete servers instead of silently accepting partial policy data. The same day also consolidates capability discovery on the v0 surface and updates both Rust and TypeScript consumers.

### **pnpr fixes peer-context reuse and real-hoist behavior** (ae5ed6ed)
Fast updates now re-check peer contexts before reusing locked subtrees, avoiding cases where a changed peer layout was incorrectly treated as safe to reuse. In parallel, the real-hoist walker and tests were adjusted so hoisted peer variants keep their own nested dependencies.

### **pnpr and pnpm gain several important resolver fixes** (f9bb312)
`pnpr` now resolves its own registry metadata and tarball reads through the local registry handlers, instead of misrouting them through upstream credentials. The broader resolver work also fixes stale libSQL retries, exact-version archive misses on replicas, git dependency fragment parsing, override path handling, and a PnP repeat-install check.

### **pnpr hardens publishing, login, and database validation** (349d316)
Config checks now validate database URLs, schemes, and pool limits more strictly for both metadata and identity backends. Release CI and packaging checks were updated alongside the runtime validation path, so invalid database settings are caught earlier.

### **pnpr and pnpm pick up a major lockfile/v13 round-trip fix** (945fb97)
Injected peer graphs now survive lockfile round trips more reliably, including v13 serialization and freshness checks. The lockfile writer/reader and dependency-graph tests were expanded to preserve peer/child classification across frozen and fresh installs.

### **pnpr adds v13 directory-input recording** (2c22bc3)
The v13 lockfile format now records hooked directory inputs, dependency metadata, and manifest source information. That makes repeat installs and freshness checks aware of directory-based package inputs instead of treating them as opaque snapshots.

### **pnpr defaults npm publish to owners** (fa24101)
A `packages:` entry without an explicit `publish` list now defaults to `$owners` for npm registries, closing the old any-authenticated-user publishing gap. The change also updates access rules, tests, and package-ownership handling across the server.

### **pnpr fixes token creation, stale streams, and OCI safety** (45075a0)
`POST /-/npm/v1/tokens` now honors npm 12's granular permissions and day-based expiries, and rejects unsupported restriction fields with a 400. Related server updates also harden stale libSQL retry behavior and OCI manifest/reference handling.

### **pnpr fixes archive/version reads on lagging replicas** (f2b10fc)
When a libSQL replica is behind, tarball, archive, and exact-version lookups now fall back to the primary instead of returning false 404s. That closes a race where a newly published package could appear missing from another instance until the replica caught up.
