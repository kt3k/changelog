### **Faster Node runtime resolution with cached release metadata** (509ff44)
Resolving pinned Node.js runtimes is now much faster: pnpm caches verified per-version release metadata and can skip the Node.js release index for exact runtime pins like `runtime:22.23.2`. That removes a big chunk of first-run network overhead when a project pins a runtime that’s already been seen.

### **pnpr no longer pays for unnecessary server round-trips** (f361560)
`pnpm install` now avoids pnpr server exchanges when the project is already up to date or the local lockfile verification cache is sufficient. This closes a performance gap where a configured server could make no-op installs slower than a direct local install.

### **Catalog entries are re-resolved when sibling projects would otherwise go stale** (e5ed810)
A workspace project that missed the install which moved a catalog entry will now follow the updated catalog on its next install instead of keeping an obsolete version. This fixes a consistency bug where one catalog entry could end up resolved to two versions across the workspace.

### **Global config now warns on kebab-case keys** (2d8c3e2)
Keys like `state-dir` in the global `config.yaml` are now reported instead of being silently dropped, with a hint to use the camelCase spelling. That makes config mistakes much easier to spot and explains why a setting wasn’t applied.

### **`pnpm cache path` added, and prune keeps lockfile verification logs** (49ea66c)
pnpm gained a `cache path` command for printing the metadata cache directory, which is useful for CI cache setup. `pnpm store prune` also stopped deleting `lockfile-verified.jsonl`, preserving verification history so future installs can skip re-checking unchanged lockfiles.

### **Third-party notices were added for Yarn-derived code** (23bdc61)
The published packages now include third-party notices covering the Yarn BSD-licensed code used by the hoisted layout algorithm and package-compatibility database. This is a compliance/documentation update for redistributed artifacts.

### Other misc changes
- Dependency bumps: clap, open, tokio
- CI benchmark workflow updated for new pnpr scenarios
- Internal test and packaging metadata updates
