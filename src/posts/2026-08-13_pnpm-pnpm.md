### **Canonical cycle breaking makes peer resolution deterministic** (9b80df8)
Dependency cycles are now broken at the same edge every time during peer resolution, based on package-id order rather than walk order. That removes lockfile nondeterminism across reordered importers or dependency traversal, and the change also improves peer-resolution speed and memory use on cycle-heavy workspaces.

### **Workspace importer order no longer affects resolution** (c547d28)
Workspace importers are now processed in project-id order, so reordering `packages` globs or other discovery order changes won’t reshuffle peer ownership, auto-installed peer placement, deprecation attribution, or back-edge bindings. This is a determinism fix for lockfiles and peer graphs that previously leaked caller order.

### **`pnpm update` now writes the resolved range back to `package.json`** (9ef6a0a)
`pnpm update` no longer stops at the lockfile: it rewrites the dependency specifier in `package.json` to the new compatible range it resolved, while preserving the original operator and keeping dist-tags like `latest` intact. That brings the manifest in sync with the update result and keeps frozen installs working.

### **Deleting an unset config entry is now a no-op** (4654257)
Removing a config key that wasn’t present no longer tries to delete a missing workspace or global config file, avoiding `ENOENT` for `pnpm config delete` on unset settings. It’s a small but user-facing correctness fix for config cleanup.
