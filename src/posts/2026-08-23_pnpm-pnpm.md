**Rust CLI parity jumps forward with missing commands, flags, and settings** (9fecf1b, 9720df2, d5219db, 6639800, 6a5ad3c)
The Rust CLI now covers several previously missing command groups and flags, plus the remaining pnpm settings the code recognized but ignored. This includes `pnpm get/set`, store status, recursive output/workspace flags, update notifier support, shell emulator behavior, and a broad config parity sweep that closes the default-settings gap.

**Install/update correctness gets a series of user-visible fixes** (a5effe4, 4f692ba, d8411f4, 1078247, 5f88187, 0b23eca)
Installs now report unmet peer dependencies after resolution, with `strictPeerDependencies` turning them into hard failures, and `dedupe` finally honors the same strict-peer behavior. Update handling was tightened so tag selectors save resolved versions, exact versions with build metadata resolve correctly, ignored dependencies stay out of outdated/interactive prompts, and transitive-only versioned updates fail instead of silently doing the wrong thing.

**PnP execution is now wired through scripts and exec** (ea1d9d9)
Plug'n'Play projects now preload `.pnp.cjs` for lifecycle scripts, `pnpm run`, and `pnpm exec`, and the generated loader exposes more of the public Yarn PnP API. That closes a major execution gap for PnP-enabled workspaces.

**Global shims and bin conflicts are handled more safely** (ff9ab71)
Project-aware shims are now preserved explicitly and can recover when matching global packages change, while conflicting global binaries are rejected up front. The CLI also suggests the right shim setup path after pinning a runtime, reducing surprising breakage around global installs.

**Workspace manifest edits now preserve inline YAML** (f468e3e)
Inline flow-style YAML blocks in `pnpm-workspace.yaml` are now edited in place instead of failing or corrupting the file. This fixes commands like `pnpm audit`, `pnpm link`, `pnpm approve-builds`, and catalog updates when the workspace file uses inline mappings or lists.
