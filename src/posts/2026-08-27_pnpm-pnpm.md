**Workspace task orchestration lands across the stack** (e7f3bcc)
`pnpm -r run` and `pnpm -r exec` now schedule per task instead of waiting on topological chunks, so independent work starts as soon as its own dependencies are ready. The new `tasks` section in `pnpm-workspace.yaml` also adds explicit task dependencies, cycle handling, dry-run/json graph output, and stricter bail/resume behavior.

**Shared build artifacts can now be pinned in the lockfile** (5dd1453)
Verified remote build artifacts are recorded in `pnpm-lock.yaml` by input key, owner, and consumer platform, so frozen installs can enforce the exact artifact selection without mutating the lockfile. This makes remote builds reproducible while still allowing `pnpm update --build-artifacts` to refresh the recorded pins intentionally.

**Remote build artifacts are persisted with signed origin metadata** (d6061d8)
Hydrated remote artifacts now keep enough signed provenance in the store to be reused later without contacting pnpr, while still being revalidated against trust, policy, platform, source integrity, lockfile pins, and builder details before reuse. That tightens artifact reuse without weakening the security model.

**`pnpm install --fix-lockfile` is now supported in Rust pnpm** (17bb3a1)
The Rust CLI can repair broken lockfile metadata while preserving the versions already represented by the lockfile. It adds tolerant repair-mode loading and the plumbing needed to regenerate metadata without turning the command into a normal full reinstall.

**Recursive scripts now honor per-task concurrency limits** (0f2ad88)
Workspace task settings can cap how many instances of a given task run at once, independent of overall workspace concurrency. That gives package authors finer control over hot spots like builds or tests without reducing parallelism everywhere else.

**`pnpm -r run` / `exec` now cancel in-flight work on bail** (cae85a2)
Recursive commands now track spawned children and terminate their process trees when a run bails, instead of leaving watch-style scripts alive indefinitely. This aligns Rust pnpm with the expected failure cleanup behavior from the TypeScript CLI.

**Pacquet now prefers the latest bin version in alias conflicts** (d819fc9)
When multiple versions of the same package compete to provide a bin, the resolver now compares versions after the usual precedence rules so the highest version wins. That fixes cases where an alias or tie on package name previously caused an older binary to be linked.

**`pnpm clean` now resolves the right modules directory per project** (ea4b11d)
The cleanup command no longer strips workspace-relative paths incorrectly and accidentally targets the workspace root’s `node_modules` from a member directory. It now derives the per-project modules leaf correctly before deleting anything.
