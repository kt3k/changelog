### **Pacquet gets workspace filtering flags** (faf8484)
Adds `--filter` and `--filter-prod` to the CLI and threads them into config as selector lists. This is the first pass at workspace project filtering, a foundational piece for scoped installs and other filtered commands.

### **Pacquet ports lockfile-only installs** (75e11a6)
`--lockfile-only` now works for both `install` and `add`, resolving and writing the lockfile without fetching tarballs or creating `node_modules`. That’s a useful workflow for CI and lockfile generation, and the new tests cover the no-download / no-link behavior.

### **Pacquet now honors network config flags** (74dd8ba)
Network settings such as concurrency, fetch timeout, user agent, and npmrc auth file are wired through the CLI and config layer instead of being hardcoded. This brings pacquet’s install networking much closer to pnpm’s configuration surface.

### **Resolution/version policy settings are ported** (aa3135b)
Adds support for pnpm’s resolution mode and release-age-related settings, including the `highest` and `lowest-direct` behaviors exercised in tests. This changes how dependency versions are selected, so it directly affects install results.

### **Project lifecycle scripts now run during install** (64ce69a)
`pacquet install` now runs workspace/root lifecycle scripts like `preinstall`, `install`, `postinstall`, `prepare`, and `postprepare`. That closes an important parity gap with pnpm and can affect package setup, build steps, and install-time side effects.

### **Trust scale recognizes staged publishes** (1e9ab29)
Staged publishes are now treated as the strongest trust signal, above trusted publishers and provenance. This avoids false downgrade failures and strengthens install-time trust verification for packages published with approval workflows.

### **Registry-mock is replaced with an in-repo registry** (49e6074)
The test suite switches from the external Verdaccio-based `@pnpm/registry-mock` dependency to an in-process registry bundled in the repo. That simplifies test infrastructure and aligns Rust and JS tests on the same fixture source.

### **pnpm-registry is renamed to pnpr** (c5d9d3a)
The registry server crate, binaries, env vars, paths, and workflows are renamed from `pnpm-registry` to `pnpr`. This is a repo-wide refactor that affects build, release, and test wiring, but not the registry behavior itself.

### Other misc changes
- Dependency bumps: tar, sysinfo, serde_json, getrandom, bcrypt, tower-http
- Fix pnpr workspace dependency version floor so release builds resolve
- Preserve tarball dependency integrity in the lockfile
- Windows sandbox test falls back to copy across drives
- Inject release version into `PACQUET_VERSION` for release workflow
- CI/pre-push optimization to skip expensive Rust checks unless pacquet/pnpr changes
- Release 11.5.0 housekeeping and generated changelog updates
