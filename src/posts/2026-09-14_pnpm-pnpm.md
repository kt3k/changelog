**Frozen installs now settle against the importer-reachable graph** (e2d0eae)
`pnpm install --frozen-lockfile` no longer keeps reimporting snapshots that no importer can reach, which had been causing repeated lifecycle script runs and broken “nothing to do” checks. That fixes unnecessary work in frozen installs and makes `verifyDepsBeforeRun`/`pnpm run` behavior consistent.

**Manifest drift is now checked against the lockfile, not a stale timestamp** (f38f11e)
The optimistic repeat-install path now detects single-project manifest edits by comparing against the lockfile it wrote, rather than trusting `lastValidatedTimestamp`. This closes a race where dependency edits could be missed and installs would incorrectly report “Already up to date.”

**`pn`, `pnpx`, and `pnx` now resolve the sibling pnpm binary** (7b9239f)
The alias scripts stopped searching `PATH` and now execute the pnpm installed alongside them, which avoids accidentally picking up another pnpm or failing when the install directory is not on `PATH`. The change also updates the standalone wrapper generation and related setup logic.

**Shell emulator now expands braced parameter forms** (a8ade49)
Scripts run under `shellEmulator` now handle `${VAR}` and common default/alternate-value forms instead of passing them through literally. This fixes real lifecycle-script cases where env-based substitutions were silently ignored.

**Workspace filters now support brace alternatives** (992401c)
Directory filters and recursive exec selectors now understand patterns like `./packages/pkg-{a,c}`. That brings Rust-side glob matching closer to micromatch behavior and fixes selection gaps for brace-based workspace targeting.

**`pnpm sbom` now publishes valid repository URLs** (80b6225)
SBOM generation now normalizes repository metadata into proper URLs, expanding npm shorthands and stripping credentials before publication. That makes CycloneDX/SPDX output acceptable to consumers that reject raw shorthand or credentialed URLs.

**Python frozen lockfiles can replay across compatible targets** (55434d2)
The Python installer now reuses `pylock.toml` on any target that still satisfies the locked requirements, instead of requiring an identical marker environment and wheel-tag order. This prevents harmless environment changes, like a kernel update, from forcing unnecessary re-resolution.

**Hoisted installs reuse cached directory clones more safely and faster** (a68132f)
Deps-restorer now shares more cached CAS path data, reuses directory-clone caches for eligible hoisted snapshots on macOS, and avoids stale reuse for mutable sources like `file:` and git-hosted tarballs. The result is less memory overhead and fewer repeated file imports during hoisted installs.

**`pnpr` search no longer fails on large upstreams** (0b8a1cd)
Upstream search is now budgeted by fetch/download limits instead of rejecting broad queries with 400s. When an upstream is too large to scan fully, pnpr truncates what it downloads and treats the remainder as an approximate total instead of failing the request.

- cmd-shim moved into the pnpm monorepo for easier maintenance and packaging (224aed7)
- Node resolver now fails on transport errors while reading musl assets instead of silently dropping them (b60172e)
- `pnpm --version` now reports why a pinned pnpm can’t be installed/recorded on read-only filesystems, then prints the running version (8aea95b)
- `pnpm self-update` now recognizes both `pnpm` and `@pnpm/exe` installs (2cd878b)
- Optional peer hoisting settles in one pass after lockfile changes (4cf6010)
- Peer-dependency specifiers are now validated in pnpm v12 before resolution (713959c)
- Windows purging now removes directory links correctly (ec0023b)
- FreeBSD now uses the Unix default store directory instead of panicking (fcce4e8)

- `--ignore-workspace` now works correctly from nested projects (59777c4)
