### **Patch workflow lands in pacquet CLI (003bb9a)**
Adds the full patch workflow: `patch`, `patch-commit`, `patch-remove`, and supporting state/config plumbing. The implementation also hardens file handling and preserves patched dependency metadata, making the patch flow usable end-to-end instead of a stub.

### **`set-script` is now available in pacquet CLI (8fec992)**
Ports pnpm's script-setting command and adds the `ss` alias. It rewrites `package.json` scripts in place, rejects unsafe prototype-pollution keys, and includes coverage for the no-args case.

### **`import` command added for external lockfiles (05dc494)**
Introduces `pacquet import` to generate a `pnpm-lock.yaml` from an external lockfile, with support for routing through pnpr. The command also backs up any existing lockfile first, which reduces the risk of clobbering local state during import.

### **`dedupe` command added to pacquet CLI (6b962c9)**
Adds a lockfile deduplication command and wires it into the CLI dispatch. This is a meaningful new maintenance command for keeping dependency graphs flatter and lockfiles cleaner.

### **pnpr now defaults to port 7677 (76461e0)**
Changes pnpr's default listen port from 4873 to 7677 in the config, CLI, and docs. The new default avoids collision with verdaccio's standard port and is easier to remember as “PNPR” on a keypad.

### **pnpr requires bearer auth and drops request-time Basic auth (b1839d4)**
pnpr now expects bearer tokens for resolver requests instead of revalidating Basic credentials on every request. That removes a bcrypt-heavy hot path, which should materially improve authenticated request latency and benchmark results.

### **Bundled dependencies now include their full transitive closure (4ec0049)**
Fixes `git-fetcher` packlist generation so bundled packages bring along their own dependencies and optional dependencies too. This closes a correctness gap where published bundle contents could previously omit transitive hoisted deps.

### **pnpr publishes a Docker image on release (e2dab00)**
Adds a release workflow that builds and pushes a multi-arch pnpr Docker image to GHCR after npm publication. The image is based on the static release binaries, so the container matches what ships to npm without rebuilding Rust in Docker.

### **CI is reshaped around merge queues and faster test throughput (bf77ed2, e3f2be0, 689c42b, fe28cc6, e42c2f2)**
The day’s CI work makes required checks run correctly on `merge_group`, avoids duplicate push runs for merge-queue branches, and moves TS CI to a more stable check model. It also shards Windows TS tests and decouples pnpr builds so Linux jobs no longer wait on slower Windows work.

### **Benchmark comments now include the commit SHA (e583b04)**
Makes the integrated benchmark report self-identifying by showing the short commit hash directly in the comment. This is a small but useful traceability improvement when reviewing benchmark history later.

### Other misc changes
- Dependency bumps and lockfile updates.
- Windows-only test gating to silence Unix-only warnings.
- pnpr default listen source refactor to reuse the config constant.
- pnpm e2e metadata cache isolation per test.
