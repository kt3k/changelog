### **Fresh installs now write lockfiles and honor install preferences** (8695496, 1386b59, 5881b57)
Pacquet’s default install flow was extended to behave much more like pnpm: fresh installs now generate `pnpm-lock.yaml` and `<vsd>/lock.yaml`, and the dispatch now respects `preferFrozenLockfile` plus the global virtual store setting. That fixes several wrong-path cases where installs would re-resolve unexpectedly or materialize packages in the project-local store layout even when GVS was enabled.

### **Overrides, catalogs, workspace protocol, and patch resolution get ported** (400b21a, 22d6742, b2a95fa, 71dfccc, 667e587, 69f8ea8, 213136d, 0dd1ec4)
A large chunk of pnpm’s dependency-resolution surface landed in pacquet: workspace protocol rewriting, patch-hash tracking, catalog plumbing, catalog-backed overrides, block-exotic-subdeps enforcement, abbreviated metadata fetching, and a new `--ignore-manifest-check` escape hatch. Together these changes close a lot of compatibility gaps in how pacquet resolves, rewrites, and validates dependency graphs.

### **Install CLI gains missing pnpm flags and config overrides** (86bf5db, 881a865, f279d77)
The CLI now accepts `--config.<key>=<value>` tokens and forwards install flags correctly through the pnpm-to-pacquet delegation path, instead of dropping user intent on the floor. A release workflow fix also patches the embedded `--version` literal so published binaries report the right version.

### **Registry and store-dir race fixes harden installs** (9eb632b, a5a2c24, f9a0abe)
Pacquet now tolerates non-string dependency entries in historical registry metadata, avoiding a false packument failure on older npm data. Separately, the store verifier is synchronized with writers to prevent destructive races, and new stress tests cover the cross-process CAS cases that previously could surface as ENOENT during installs.

### **Other misc changes**
- Benchmarking stacks consolidated into one shared orchestrator and fixtures layout.
- Release/versioning and dependency bumps across workspace packages and workflows.
- Docs and parity-scope wording updates.
- Small CI/test harness and compatibility-test maintenance.
