### **Streaming tarball serving fixes cold-cache stalls** (c4acfad)
pnpr now streams upstream tarballs to the client while teeing them into cache and hashing them, instead of buffering the whole file before verification. That removes the head-of-line delay on cold fetches and makes the proxy behave like a true streaming server.

### **Cold-store installs on pnpr get their speed back** (a6f04d4)
This refactors the proxy serve path to avoid redundant re-hashing and packument parsing on cache hits, restoring cold-store install performance through pnpr. The benchmark harness was also expanded to measure the cold pnpr-cache case explicitly, so the regression is now covered.

### **`pnpm repo` lands in pacquet-cli** (da9f834)
A new `repo` command opens a package's repository URL in the browser, with local manifest lookup, registry lookup, dist-tag/semver version resolution, and support for common git URL formats. It also adds structured reporter handling for browser-open failures and broad test coverage.

### **`pnpm bin` is now implemented** (cc04eb1)
The CLI can now print the executable directory for local and global installs, matching pnpm's path resolution rules. Global mode also creates and validates the bin directory before printing it, which matters for setup and PATH-related workflows.

### **`--filter` now promotes recursive mode globally** (d22f277)
A bare `--filter` or `--filter-prod` now flips commands into recursive mode even without `-r/--recursive`, matching pnpm's CLI parsing behavior. This is an important prerequisite for commands like release automation that rely on filtered recursive execution.

### **Recursive `run` and `exec` now honor filters** (4cd45a3)
The recursive workspace runners were updated to actually narrow execution to the selected projects instead of processing every workspace package. That brings `run`/`exec` in line with pnpm's selector semantics and fixes a major correctness gap for filtered workspace commands.

### **Web auth flow is ported to pacquet** (6fadd7d)
The `@pnpm/network.web-auth` flow was brought over as a new crate, including token polling, OTP challenge handling, browser prompting, QR code display, and timeout handling. This is foundational auth infrastructure for login/publish-style commands and a substantial new capability.
