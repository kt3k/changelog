### **pnpm-agent is replaced by pnpr** (2b788d5)
The experimental TypeScript `pnpm-agent` server was removed and its install-accelerator role taken over by `pnpr`, which speaks the same protocol. The TypeScript client stays in place and is adapted for pnpr, so the repo’s e2e path now exercises the Rust server instead of the old experimental one.

### **pnpr now honors `--lockfile-only`** (f429f93)
The pnpr-backed install path gained a resolve-only mode: it writes `pnpm-lock.yaml` but skips tarball fetches and linking when `--lockfile-only` or `lockfileOnly` is set. The client also ignores any file/index stream lines from older servers so the store remains untouched even if pnpr is behind.

### **pnpr offloads lockfile verification to the server** (32c07bf)
Lockfile verification is now sent to pnpr with the client’s full policy, so the server can reject stale or policy-violating lockfiles before resolving. That removes redundant local work and keeps the pnpr path aligned with the same `ERR_PNPM_*` diagnostics the local gate would have produced.

### **Lockfile tarball URLs are now bound to registry metadata** (6d17b66)
The verifier now checks that an explicit tarball URL in the lockfile matches the registry metadata for that `name@version`, and fails closed if it can’t confirm the binding. This closes a tampering gap where a trusted version could be paired with attacker-chosen bytes.

### **Pacquet gets the CLI `run`/`exec`/`dlx` surface** (622c056)
Initial Rust implementations of `run`, `exec`, and `dlx` landed in pacquet’s CLI. That’s a substantial expansion of the Rust command surface, not just plumbing, and it brings the headless CLI closer to parity with pnpm.

### **Optional peer resolution now preserves locked contexts** (1c73e83)
Writable re-resolves now prefer peer contexts already recorded in the lockfile instead of collapsing them into a single compatible context. This avoids rewriting unrelated lockfile entries and fixes cases where preserved peer layouts matter for install correctness.

### **Pacquet retry policy now covers metadata fetches** (8bc25f3)
Registry metadata requests now share the same config-driven retry policy as tarball downloads. That makes transient 408/429/5xx failures much less likely to abort resolution prematurely and keeps pacquet aligned with pnpm’s fetch-retries behavior.

### **Lockfile emission is now canonicalized** (eec417b)
Pacquet now sorts lockfile maps when serializing, so repeated installs of the same resolution produce byte-identical `pnpm-lock.yaml` files. This removes noisy diffs on no-op reinstalls and brings output ordering in line with pnpm.

### **Windows shutdown no longer trips over open network sockets** (60a1eec)
`@pnpm/network.fetch` now exposes a dispatcher teardown path, and pnpm calls it on exit so active and cached undici dispatchers are destroyed before process shutdown. That avoids a Node.js crash seen on Windows after network activity.
