### **Keep deprecation metadata when a resolution doesn't change** (e240d17)
Re-resolving a package to the same version now preserves an existing `deprecated` marker in the lockfile even if the registry serves inconsistent metadata. That prevents identical dependency graphs from producing different lockfiles and avoids silently dropping deprecation info.

### **Resolve hoisted peers like transitive deps under `resolutionMode`** (bed8010)
Hoisted peer dependencies are now resolved with the subdependency pick rules instead of importer-level ones. This fixes cases where `lowest-direct` or time-based resolution chose the wrong peer version for an auto-installed peer.

### **Cache peer-cycle verdicts only where they’re valid** (fef7544)
Peer resolution now caches results for cycle-truncated walks using a key that captures the consulted packages and relevant ancestor-chain shape. On heavily cyclic graphs, this cuts repeated work substantially and brings a notable memory and speed improvement.

### **Shared package IDs reduce peer-walk memory** (260fb13)
The resolver now shares package-id strings across occurrences instead of copying them for every realized node. This trims peak memory during large peer walks, which matter a lot in cyclic workspaces where the same package can appear millions of times.

### **Validate `packageExtensions` up front** (26f45df)
Malformed `packageExtensions` entries are now rejected as config is read, including non-string dependency ranges and invalid `peerDependenciesMeta.optional` values. That turns a later resolver crash into an immediate, actionable config error.

### **Cataloged add/update now honor the requested version** (d96974d)
When a catalog entry already resolves past a wanted version, `pnpm add` and `pnpm update` now move the catalog resolution to the requested version instead of silently doing nothing. This fixes a confusing no-op for catalog-managed dependencies.

### **Apply `packageExtensions` to freshness checks** (5f77477)
Freshness validation now uses manifests after `packageExtensions` have been applied, so `--frozen-lockfile` no longer flags peers added by extensions as if they were removed from the workspace package.

### **Fix injected-deps sync identity and bin cleanup** (7891f89, 286d7ea, 7bee7da)
The injected-deps syncer now identifies files by device plus inode, avoiding collisions across filesystems, and it also unlinks bin shims that scripts remove from `package.json`. It additionally orders removals before parent replacements to avoid ENOTDIR failures during sync.
