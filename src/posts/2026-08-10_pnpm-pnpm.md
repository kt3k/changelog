### **Fast lockfile updates now compose across multiple drifts** (25e3fe9)
pnpm install can now absorb several compatible changes in one in-place rewrite instead of falling back to a full re-resolution. That means combinations like manifest edits plus ignored-optional changes, patches, or settings drift now stay on the fast path, which is a major install-time win.

### **Moving dependencies between groups no longer forces a re-resolve** (4063779)
Changing a dependency from `dependencies` to `devDependencies` or `optionalDependencies` now updates the importer record and optional flags directly. This keeps the resolved version intact while making the lockfile reflect the new manifest group, instead of rebuilding the whole graph.

### **Range changes now reuse the right locked version** (996297c)
When a dependency range widens, the fast update now picks the highest already-locked version that satisfies the new range, matching full resolution behavior. This fixes cases where pnpm would otherwise keep an older version around and leave an unnecessary duplicate in the tree.

### **Removing workspace projects now prunes stale importer entries** (d0ed0dd)
Deleting a workspace package now removes its importer from the lockfile instead of leaving a dead root behind. That prevents the removed project's dependencies from staying reachable and makes incremental installs converge on the same lockfile the normal resolver would write.

### **Peer-suffix handling is now version-precise** (b11f8f8)
Fast updates no longer trigger a full re-resolve just because another package shares the same dependency name. The lockfile update now checks the exact `name@version` that was removed or moved, so unrelated peer suffixes are left alone.

### **Resolver fixes stop nondeterminism and memory blowups** (b7231ee, 76e4ab8)
One fix removes a nondeterministic dependency-ownership race in the pacquet resolver so repeated walks can't flip already-recorded children to a worse resolution. Another keeps missing-peer range intersections bounded, avoiding the combinatorial explosion that could otherwise exhaust memory on large duplicate peer sets.

### **Git dependency failures are now actionable** (7a95ab8)
Git fetch errors now say which package failed and redact credentials from the repository URL. If the lockfile is pinned to SSH but the specifier didn't ask for it, pnpm also tells you how to re-record the dependency over HTTPS and why `--force` won't help.

### **Audit fix no longer adds needless minimum-age exceptions** (9f71dda)
`pnpm audit --fix` now checks publish times before adding `minimumReleaseAgeExclude` entries. That avoids widening the exception list for patched versions that were already old enough to install.

### **Other misc changes**
- Fast update now handles removed workspace projects more efficiently and can skip resolution for `pnpm remove`.
- Time-based lockfiles now round-trip their `time` section and can use the fast update path.
- `pnpm deploy` now selects the workspace root correctly.
- Filtered workspace installs keep importer-level workspace links shallow.
- Hoisted link destinations are resolved on the main thread.
- Forwarded catalogs in pnpr are now validated and keyed correctly.
- pnpmfile worker requests are now bounded.
- Git-lockfile integrity handling and git fetch diagnostics were tightened.
- Cargo/tooling/dependency bumps and test-only updates.
