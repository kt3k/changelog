**Unify pinned pnpm version switching across entry points** (3f4e9fc)
Commands, `pnpm --version`, `self-update`, unknown-flag invocations, and spawned installs now all use the same pin decision logic and record the same `packageManager`/`devEngines.packageManager` outcome. This closes edge cases where config loading, `--config.*` flags, or unreadable settings could make different entry points behave inconsistently.

**Packlist/file-selection behavior is now shared and parity-tested** (c89785b)
`pnpm pack`, `publish`, `deploy`, directory/git fetches, patching, and injected-copy writers now route through a common file-selection implementation. That fixes long-standing mismatches around symlinks, bin-field normalization, and corpus-level parity with `npm-packlist`.

**Lockfile freshness now reads `file:` dependency manifests through hooks** (b0e25ed)
The lockfile check now applies resolver hooks to `file:` directory dependencies instead of reading them with only partial transforms. That fixes false stale-lockfile errors after install and avoids unnecessary re-resolution when optional deps are removed by `ignoredOptionalDependencies`.

**Retry mid-body zip download failures for Node runtime fetches** (975f4f8)
Binary zip downloads now use retry logic for body-read failures as well as header-time failures, so a dropped connection no longer kills the install with a bare `terminated` error. Failures that still exhaust retries now include the URL, making them easier to diagnose.

**Refresh privately hoisted bins after dependency builds** (1ff9d3f)
When a package build replaces a script shim with a native executable, pnpm now refreshes the privately hoisted `.bin` links so dependents see the built binary instead of a stale placeholder. This fixes rebuild/install flows where transitive dependents kept invoking the old shim.

**Store prune no longer deletes configured data** (d18d263)
Prune is narrowed to metadata cache directories and stops removing configured stores and global data that happen to live under `cacheDir`. This prevents accidental data loss during store cleanup.

**Workspace bins relink correctly with dedicated lockfiles** (cdb69ca)
With `sharedWorkspaceLockfile: false`, installs now notice when a sibling workspace package renames a command and relink dependents accordingly. That closes a freshness gap where the dependent’s `.bin` could stay stale because the rename wasn’t represented in the sibling’s lockfile.

**Overlayfs fallback added for importer moves** (9039e2b)
When overlayfs refuses to move a package directory aside with `EXDEV`, the importer now falls back to copying a backup and completing the overwrite in place. This avoids prune/import failures in layered Docker filesystems.

**Unpublish error messaging now names matching ranges** (303a5cd)
`pnpm unpublish pkg@1.0.0` now emits a dedicated confirmation message when the range matches every published version instead of reusing the “specific version” wording. That makes the `--force` requirement clearer and the error less confusing.
