### **Self-update now ignores project-controlled config for downloads** (d47ab91)
`pnpm self-update` no longer lets the active workspace steer how pnpm itself is fetched. The download now goes through the trusted bootstrap config, so a repo’s `.npmrc`, `pnpm-workspace.yaml`, or default `.pnpmfile` can’t redirect the fetch, weaken trust checks, or alter the release-age policy for the tool being updated.

### **`update --latest` now preserves runtime/git/tarball specs** (d1161a1)
`pnpm update --latest` now leaves dependencies that the npm registry doesn’t own in the form they were declared, instead of looking up their names on the registry and rewriting them to unrelated versions. It also stops rewriting `package.json` when nothing actually changes, reducing noisy manifest churn.

### **pnpr installs now forward resolution policy violations** (d876901)
The pnpr install path now carries `resolutionPolicyViolations` through instead of dropping the field behind an unsafe cast. That fixes a crash that could happen after packages were already linked when `minimumReleaseAge` policy checks ran.

### **Release selection in the PR workflow is now explicit** (8c3bbab)
The release PR workflow can now choose which product set to release on each run instead of flushing every pending intent at once. This decouples the pnpm v11 TypeScript CLI cadence from the Rust/pacquet alpha track and avoids unnecessary daily v11 release churn.

### **GitHub Actions setup now persists environment state correctly** (4737386)
Setup commands now write PNPM_HOME and PATH updates to GitHub Actions environment files, so later workflow steps can use global pnpm commands reliably. The TypeScript and pacquet setup behavior was also aligned.
