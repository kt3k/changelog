### **Native `pnpm pkg` command lands** (d7da112)
`pnpm pkg` is now implemented natively with `get`, `set`, `delete`, and `fix` subcommands, plus workspace-aware filtering via `-r` and `--filter`. It also extends safe nested property-path mutation helpers, which matters because package.json editing no longer depends on the old fallback path.

### **Native `pnpm stage` command for npm staged publishing** (508e6d8)
Adds a new `pnpm stage` command with `publish`, `list`, `view`, `approve`, `reject`, and `download` flows for npm staged publishing. This is a substantial release workflow addition, replacing a missing command with first-class CLI support.

### **Native `pnpm repo` command** (22cb743)
Introduces `pnpm repo` to open a package or current project repository URL directly, including preservation of repository subdirectory metadata. That fixes registry packages in monorepos where the repo URL alone was not enough to open the right location.

### **Lockfile verification gets a new opt-out and lower memory use** (212315d)
Adds `trustLockfile`, letting installs skip the `minimumReleaseAge` / `trustPolicy: no-downgrade` verification pass when the lockfile is already trusted. The same change trims the verifier cache so large workspaces are much less likely to OOM during install.

### **Fresh-lockfile installs move to the virtual-store pipeline** (c5a1d08)
Refactors pacquet's fresh-lockfile install path to use the same phased `CreateVirtualStore` / symlink / bin-link pipeline as frozen-lockfile installs. This is a meaningful performance refactor that should close much of the gap on no-lockfile installs.

### **Dependency resolution caches repeated wanted deps** (e7820bf)
Memoizes repeated `resolve()` calls and child-spec extraction during dependency tree walks. That reduces redundant resolver work on revisited packages and is a concrete performance win for large dependency graphs.

### **Git/tarball and config-dep resolution correctness fixes** (e0bd879, 155af87)
Fixes an index/alias pairing bug that could drop git and tarball dependencies from manifest updates, and separately prunes the env lockfile when updating config deps so stale optional subdependencies are removed. Both are correctness fixes that prevent silent dependency drift.

### **Pacquet and store-dir compatibility fixes** (3209c25, 43e06bb, 8c68c20)
Aligns pacquet's store path handling with pnpm by appending `STORE_VERSION`, and makes `PackageMetadata` accept string `libc` values. Pacquet also stops writing synthetic transitive peer entries into importer lockfiles, which keeps generated lockfiles closer to pnpm's expected shape.

### **`dlx` bin-name fallback and catalog upgrade preservation** (3d14385, ae42a7a)
`dlx` now falls back to the alias when a slot is missing `package.json`, avoiding intermittent bin-name failures in CI. The catalog upgrade path also preserves `catalog:` references in manifests instead of rewriting them to resolved versions.

### Other misc changes
- Dependency and toolchain bumps, including Node.js and GitHub Actions updates.
- CI/benchmark workflow tweaks for Bencher permissions, thresholds, and release checks.
- Clippy/lint cleanup and assorted test-only updates.
