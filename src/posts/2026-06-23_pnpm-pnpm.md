### **Release workflow now fails fast on non-tag dispatches** (dd79bdc)
The release workflow now validates that it runs from a `v*.*.*` tag before any publish steps start. That prevents branch-triggered manual runs from getting partway through publishing and then failing because the exe artifacts were never built.

### **Lockfile verification now surfaces registry fetch errors directly** (852d537)
pnpm no longer misreports registry metadata fetch failures as `ERR_PNPM_TARBALL_URL_MISMATCH` during lockfile verification. Transport/auth failures now bubble up as the registry's own error, which makes private-registry and network problems much easier to diagnose and avoids conflating them with tampering-style mismatches.

### **`pnpm patch` preserves the package alias for git-hosted deps** (0a154b1)
When patching a single git-hosted version, pnpm now returns the parsed dependency instead of the options object, so the package name (`alias`) is retained. This fixes a regression that could drop the package name and leak unrelated fields into the patched result.

### **`pnpm dlx` shortens its cache path on Windows** (ec7cf70)
`dlx` now uses shorter base36 segments for its prepare directory and a shorter cache key hash, reducing the chance of blowing past Windows `MAX_PATH`. That should prevent deep lifecycle script paths from failing with `spawn cmd.exe ENOENT` in long dependency trees.
