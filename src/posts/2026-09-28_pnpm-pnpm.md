### **Pinned-version CLIs now receive unknown options first** (ed9bd63)
pnpm now forwards commands with options it doesn’t recognize to the pinned pnpm version instead of rejecting them up front. That fixes cases like `pnpm install --auto-dedupe` in repos that pin another pnpm, where the newer frontend would fail even though the pinned version supports the flag.

### **Time-based resolution falls back to a mature version** (bb13fb9)
When `resolutionMode: time-based` can’t find a transitive dependency older than the cutoff, pnpm now falls back to the lowest version that still satisfies `minimumReleaseAge` instead of jumping straight to an immature pick. This makes time-based resolution behave more predictably under strict age gates and avoids surprising installs.

### **Windows Ctrl+C no longer leaves script shells wedged** (8d51a39)
pnpm now force-ends a Windows `cmd.exe` batch shim if it lingers after Ctrl+C, instead of letting the terminal get stuck on the “Terminate batch job?” prompt. This fixes a nasty interactive hang where later keystrokes would keep going to the dead script shell.

### **Install now preserves executable bits from local directory deps** (36c0976)
`file:` directory dependencies and injected workspace packages keep the permissions from their source project instead of being rematerialized with store-derived modes. That fixes executable files silently losing their `+x` bit during install.

### **Release installs stop misclassifying a touched lockfile** (5e5da5)
`verifyDepsBeforeRun` now treats a filtered install’s current lockfile correctly even when `pnpm-lock.yaml` has a newer mtime but unchanged contents. This prevents `pnpm run` from unnecessarily reinstalling workspace projects after a filtered install.

### **Global virtual store installs are faster and more correct** (f94d533)
Workspaces with `sharedWorkspaceLockfile: false` now install projects concurrently with shared metadata and cache state, reducing CPU and memory use. The fix also separates each project’s hidden virtual-store data properly, avoiding cross-project relinking and related flakiness.

### **Peer-dedupe now renames surviving variants consistently** (373c7f3)
After `dedupe_peer_dependents` collapses peer variants, pnpm now rewrites any peer suffixes that still name a merged-away variant. That keeps lockfile keys aligned with the actual surviving graph and fixes `pnpm dedupe --check` churn.

### **Hashed peer suffixes now converge with explicit suffixes** (ebffb9c)
pnpm now resolves the same peer set whether a lockfile key uses a hashed suffix or an explicit peer suffix. That removes a source of lockfile flip-flopping where dedupe could alternate between two equivalent key spellings.

### **Injected workspace peers dedupe after peer variants merge** (6048dfe)
Injected workspace dependencies now dedupe after peer-dependent variants are merged, so injected copies don’t get left behind as peer-suffixed file copies. This fixes a case where pnpm kept duplicate importers instead of collapsing them to the intended workspace link.

### **Frozen installs accept injected peers resolved from workspace links** (968f688)
The lockfile freshness check now accepts injected dependencies whose peers resolve to workspace links. That avoids falsely rejecting a freshly generated lockfile just because the resolved peer is represented as `link:` instead of a registry version.

### **Recursive installs no longer skip everything at filesystem root** (53ec8f4)
pnpm fixed the path filtering logic that could exclude every importer when the repository root was `/` or a drive root. Recursive installs now correctly work even when the workspace lives at the filesystem root.

### **`pnpm add` / global update honors `--latest` beyond saved ranges** (cfbf081)
Global update resolution now consults the latest dist-tag even when the installed manifest carries a saved range, so `--latest` can actually move packages forward. This fixes a long-standing mismatch where an available update could look unchanged.
