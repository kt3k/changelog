**`pnpm stage approve` can now batch-approve staged packages interactively** (ea10c04)
The release command now accepts multiple stage IDs or no ID at all, in which case it lists staged versions in a checkbox prompt and approves them in workspace dependency order with a single OTP session. This removes the old one-package-at-a-time workflow and makes large release approvals much less error-prone.

**`--frozen-lockfile` is less brittle around package-manager pins** (fc0278a, c54dba4)
pnpm now records package-manager pins even on the install fast path, and it no longer fails just because the lockfile contains a pinned package-manager entry that this pnpm version would not install from. That fixes a class of false `ERR_PNPM_FROZEN_LOCKFILE_WITH_OUTDATED_LOCKFILE` failures while keeping real mismatches rejected.

**Merged branch lockfiles now prune removed dependencies correctly** (ccff620)
When `--merge-git-branch-lockfiles` is used with `--frozen-lockfile`, dependencies that no longer appear in the manifest are now dropped instead of being resurrected by the merge. This closes a correctness hole that could otherwise leave stale deps in the merged lockfile and trip frozen installs.

**Hoisted injected `file:` peer variants stay separate** (2f703cb)
Under the hoisted linker, peer-resolved variants of injected directory dependencies no longer collapse onto the first-seen copy. That preserves distinct peer resolutions for different workspace members, which matters for Bit-style injected roots with conflicting peer requirements.

**Bit root components now link siblings from their snapshot when needed** (34120fd)
For isolated installs, root-component members without a materialized `package.json` now use their own lockfile snapshot to determine sibling links instead of falling back to an all-member clique. That narrows injected sibling symlinks to the dependencies each member actually declares and avoids over-linking.

**The Rust release build splits the NAPI addon onto its own runners** (05129e1)
The release workflow no longer compiles the CLI and NAPI addon back-to-back in one matrix leg. Separating them avoids recompiling the shared dependency graph twice under different Cargo profiles, reducing release build time.

**pnpm update/self-update messaging no longer points users at Corepack** (4c07aba)
Update prompts and self-update flows now direct users to pnpm’s standalone install path instead of telling them to use `corepack use`. That aligns the guidance with pnpm’s own distribution model and avoids sending users through the wrong tool.

**Bundled release bins are kept packable again** (c181e90, cef4816)
The release packaging path now forces shell shims instead of symlinked executables in `dist/node_modules/.bin`, and adds verification to catch symlinks in the packaged output. This fixes tarball creation failures for the bundled CLI/exe artifacts.

**Release-note generation works when run as a script** (4aa13c1)
`pn make-release-description` now initializes its entry point after the module’s constants and accepts an explicit repo root argument. That fixes the temporal-dead-zone crash that broke scripted release-description generation.
