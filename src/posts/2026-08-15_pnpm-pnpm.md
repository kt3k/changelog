### **Corepack can run pnpm 12 again** (e97b44f)
pnpm now ships the `bin/pnpm.mjs` and `bin/pnpx.mjs` entry points Corepack expects, so `corepack use pnpm@next-12` no longer fails with `MODULE_NOT_FOUND`. This unblocks pnpm 12 for Corepack users and preserves the native binary bootstrap path for the published package.

### **pnpm learns how to install other package managers** (1c179fb)
pnpm's engine installer is generalized beyond pnpm itself, so it can resolve, verify, and install npm, Yarn, and Bun versions too. That unlocks project-level package-manager pinning, smarter `pnpm dlx` behavior, and new shim management for commands like `yarn`.

### **Project manifests can no longer move machine state** (ccff081)
A project's `pnpm-workspace.yaml` can no longer redirect pnpm's machine-level directories and credentials locations like `configDir`, `pnpmHomeDir`, `stateDir`, or `workspaceDir`. This closes a class of config bugs where project settings could silently override where pnpm stores auth, binaries, and other host-specific state.

### Other misc changes
- Release/changelog updates for pnpm 11.22.0 and pacquet 12.0.0-rc.6 (93fcba4)
- CI/release workflow tweaks for wrapper and Corepack coverage (e97b44f)
- Config command follow-ups to reject invalid project-level settings and clean up deletes (ccff081)
