### **package.yaml editing and preservation lands** (81eea50)
pnpm can now read and save `package.yaml` through `PackageManifest`, including comment preservation, key order retention, and atomic/no-op writes. The new support also wires `pkg`, `version`, `set-script`, and `link` to YAML-aware manifest discovery, which broadens the CLI surface that can target `package.yaml`.

### **Store prune now reclaims CAS files too** (c8c80cc)
`pnpm store prune` now removes unreferenced content-addressable files and package-index entries, not just virtual store slots. That closes a long-standing storage leak and makes pruning actually recover disk space after dependencies are removed.

### **Install summary now reports resolved versions for hoisted installs** (a767aeb)
The hoisted linker’s install summary now shows the version each dependency resolved to, and reports both removals and replacements consistently. That fixes cases where the summary previously showed only the `package.json` range or nothing at all.

### **SBOM output now classifies licenses correctly** (b97ba04)
`pnpm sbom` now distinguishes SPDX IDs, valid SPDX expressions, and free-form license strings before emitting CycloneDX. This avoids invalid SBOMs for values like `UNLICENSED` and rejects malformed expressions instead of misclassifying them.

### **`pnpm install --prod` stops downloading dev-only tarballs** (aa479f9)
Production installs still resolve the full graph, but they now avoid fetching registry packages that are only reachable through dev dependencies. This keeps lockfile generation intact while reducing unnecessary downloads, including in hoisted mode.

### **Git-hosted dependencies respect explicit build denial** (f922cba)
When `allowBuilds` explicitly denies a git dependency, pnpm now installs its source without preparing it. The change separates denied builds from undecided ones so approvals still trigger preparation later, instead of accidentally reusing prepared output.

### **Windows global-virtual-store repairs now wait out delete-pending entries** (f395e02)
Installs sharing a global virtual store no longer fail on Windows with `Access is denied` when another process has just unlinked the same slot. pnpm now retries inspection and deletion through the transient delete-pending window.

### **Global virtual store installs relink when `allowBuilds` changes** (f87a462)
A repeat install now notices when the recorded `allowBuilds` set differs from the current one and relinks the affected global virtual store slot. This fixes stale build-state reuse when a package flips between allowed and disallowed.

### **`pnpm change check` now validates pending intents early** (f7d862d)
Change validation now builds the pending release plan before reporting success, so unknown or ambiguous package references fail immediately instead of later in release tooling. That makes `pnpm change check` a more reliable guardrail for release PRs.

### **`pnpm audit --fix=update` now handles npm aliases** (85152e3)
Audit fix-up logic now unwraps npm aliases before checking pin state and looking up vulnerabilities, so aliased dependencies can be updated correctly. The fix also covers `=`-pinned versions.

### **`pnpm install` now honors explicit denials for git builds** (f922cba)
Denied git dependencies now stay unprepared and keep their source files, while approved ones still run preparation. The cache keys and fetch paths were adjusted so denied and allowed builds do not collide.

### **Windows path handling and cache canonicalization fixed in pipeline** (66a91e4)
`pnpm pipeline --watch` now handles Windows path separators correctly when naming agents, and pipeline caching canonicalizes paths before keying them. That prevents duplicate cache entries and broken checkout names for the same directory on Windows.

### **Setup scripts now normalize native Windows paths** (34bfc56)
The `pn`, `pnpx`, `pnx`, and pnpm placeholder shell scripts now apply the same drive-letter/UNC guard as the setup writers. That keeps Windows paths working without mangling Unix paths that happen to contain literal backslashes.

### **Install now waits for concurrent symlink/link repairs** (e27cc45)
pnpm now waits out Windows refusals when a concurrent installer still holds a link it is trying to inspect or replace. This prevents spurious failures when two installs race on the same symlink target.

### **`--force` repeat installs repair modified files again** (070e3b2)
Forced repeat installs no longer take the optimistic shortcut that skips re-importing packages. That ensures modified installed files are restored and frozen-store conflicts are still reported correctly.

### **Explicitly denied symlink conflicts are retried correctly** (8d220e5)
When a symlink conflict disappears mid-repair, pnpm now reissues the create instead of treating the vanished conflict as a hard error. This closes a race where concurrent installers could fail over a path that was already fixed.

### **Excluded workspace links are still materialized when needed** (49f773c)
With `excludeLinksFromLockfile` enabled, workspace dependencies declared with plain version ranges are now still linked into `node_modules` when `linkWorkspacePackages` applies. The lockfile stays clean, but the installed tree no longer loses those workspace targets.

### **Hoisted linker install summaries now show version changes** (a767aeb)
The hoisted linker now reports what version was installed, restored, or removed, instead of relying on package.json diffing. That gives users a real summary even when the hoisted layout does not create direct symlinks.
