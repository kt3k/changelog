### **Preserve Node.js env vars in global runtime shims** (22d0067)
`pnpm runtime set node --global` now uses a native Unix dispatcher for `node` instead of a POSIX shell shim, so environment variables with names that shells would drop are preserved when launching Node.js. The change also records the managed runtime path beside the executable and updates the global shim detection/refresh logic accordingly.

### **Speed up dependency resolution for workspace links** (76afc44)
Workspace `link:` targets are now re-anchored in lockfile-relative space instead of rebuilding absolute paths on every edge. That trims repeated path normalization work in large workspaces and should reduce resolver overhead noticeably.

### **Parse the wanted lockfile while discovering projects** (a67fcee)
Installs can now prefetch and parse `pnpm-lock.yaml` on a background thread during workspace discovery when the run is guaranteed to need it. This overlaps a previously serial YAML parse with other startup work, improving install latency in large repos.

### **Render large lockfile sections in parallel** (073e9d8)
The YAML emitter now fans out sorting and rendering for large `importers`, `packages`, and `snapshots` sections once they cross a size threshold. Output stays byte-for-byte the same, but generating big lockfiles should be much faster.

### **Fix zero-context patch insertions** (621f45c)
Pure insertions in unified diffs with zero context are now applied at the correct line instead of one line early. The fix is backed by expanded coverage for file boundaries, empty files, CRLF, missing final newlines, and multi-hunk insertion cases.

### **Keep filtered recursive scripts in the foreground** (c56db8f)
Filtered or serial `pnpm run`/`pnpm exec` tasks that are not actually running concurrently now stay in the terminal's foreground process group. That avoids interactive scripts getting stopped by `SIGTTIN` when they read from stdin.

### **Default explicit release-age cutoffs to strict mode** (4010b0e)
When `minimumReleaseAge` is explicitly configured, strict enforcement now turns on by default instead of silently falling back to immature versions. This aligns resolver behavior with the documented setting and preserves the built-in 1440-minute default as non-strict.

### **Regenerate npm Windows shims for pacquet installs** (43dc110)
Global npm installs on Windows now re-run the wrapper installer after the bin rewrite so PowerShell shims point at `pnpm.exe`. The postinstall path also invokes `npm rebuild` with lifecycle scripts disabled to refresh npm's bin map without recursion.

### **Preserve bundled node-gyp in standalone setup** (8a8130f)
Standalone release archives now keep their bundled `node-gyp` payload during `setup`. The fix makes the standalone package declare the right files and passes the existing package-file setting through directory fetches.

### **Restore extensionless pnpm upgrades on POSIX** (a3de3b2)
The self-update path restores the `pnpm` executable target without a file extension on POSIX systems, so older pnpm 12.1 installs can upgrade cleanly to newer 12.x releases. This also keeps the native wrapper target selection consistent across platforms.
