### **Reuse moved `node_modules` trees** (616b043)
`pnpm install`, `pnpm run`, and `pnpm exec` can now accept a `node_modules` directory that was moved or copied with its project. The first run after relocation revalidates the tree, rebases stored project paths in memory, and then records the new location.

### **Catalogs now support `file:` and `link:` entries** (8cdc670)
Catalog entries in `pnpm-workspace.yaml` can now point at local paths via `file:` and `link:`. The resolver re-anchors those paths from the workspace file’s directory, which fixes relative local catalog entries for consuming projects.

### **`pnpm install` now respects standalone projects outside the workspace** (34d8f1f)
If a directory has its own manifest but is excluded by workspace patterns, pnpm now treats it as its own project instead of installing the whole workspace. This also keeps directories without their own manifest inside the workspace search, preserving the old behavior for source subdirectories.

### **`pnpm exec` finds project bins from subdirectories** (00edab9)
Running `pnpm exec` from a nested directory no longer loses access to the project’s binaries just because `./node_modules/.bin` was resolved relative to the subdirectory. pnpm now adds the project bin directory as an absolute PATH entry when needed.

### **Fix signal handling for `pnpm exec` / scripts** (c4f8779, 2af480a, c0b619c)
Several signal-handling bugs were fixed so Ctrl+C and non-terminal signals reach the actual script process group instead of getting duplicated, dropped, or cut short. This matters for containers, service managers, and scripts that need time to shut down cleanly.

### **`pnpm publish` now allows detached HEAD in CI** (ed8bfec)
Publishing from a detached HEAD is now allowed when the CI setting permits it. pnpm still performs the usual clean-tree and Git sanity checks, but it no longer blocks valid CI release flows just because HEAD is unattached.

### **Workspace YAML edits preserve scalar anchors** (241ef84)
Editing `pnpm-workspace.yaml` now keeps scalar anchors and aliases intact instead of losing them during manifest rewrites. That avoids breaking YAML constructs used across catalogs and workspace settings when pnpm updates the file.

### **`pnpm update` stops copying hook-injected deps into manifests** (a183ef2)
Dependencies introduced by `packageExtensions`, `readPackage` hooks, or overrides are no longer written back into `package.json` during update flows. The update logic now keeps the hook/override specifier as the source of truth, which avoids persisting transient or policy-driven dependencies.

### **Recursive `pnpm run` now runs matched scripts in parallel** (e9be2b9)
When a recursive run matches multiple scripts in the same package via a regex selector, pnpm now starts them concurrently instead of serializing them. That brings the Rust path in line with existing pnpm behavior and better uses `workspaceConcurrency`.

### **Root engine checks run earlier** (fca1c76)
With `engineStrict` enabled, pnpm now validates the root manifest’s Node engine before building command state. That rejects incompatible runtimes sooner and keeps version-manager selection behavior consistent.

### Other misc changes
- Windows test coverage expanded for recursive-exec, recursive-run, hoisted-node-linker, and global-virtual-store suites.
- Catalog, overrides, publish, cache, setup, and minimum-release-age bug fixes and test coverage.
- `@pnpm/npm-lifecycle` was moved into the monorepo and renamed to `@pnpm/exec.npm-lifecycle`.
- Documentation/comment/test-only cleanups and dependency bumps.
