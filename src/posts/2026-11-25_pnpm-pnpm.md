### **Tarballs now follow node-tar’s rules or fail** (fd8b681)
pnpm now reads package tarballs the same way npm/node-tar do, closing a class of install mismatches where pnpm and other tools could unpack different file sets from the same archive. This removes support for several ambiguous header shapes and makes publish/install scanning safer and more consistent.

### **Downloaded runtimes now carry license metadata** (511b73f)
pnpm now writes the declared MIT license into the manifests it creates for downloaded Node.js, Deno, and Bun runtimes, so `pnpm licenses list` and other license tooling can see them. The change also improves how cached runtime metadata is reused, especially for offline installs.

### **HTTP registry tarball downloads can use explicit user credentials** (ab6906a)
Package tarball fetches now honor credentials for HTTP registries declared in the user’s global config or `.npmrc`, restoring support for HTTP-only registries without a separate tarball setting. The auth logic was tightened to track trusted HTTP registries and avoid leaking credentials across redirects or workspace-controlled settings.

### **pnpm view/info now treat fully unpublished packages as missing** (60474fc)
Requests for a package that is fully unpublished now surface as `ERR_PNPM_PACKAGE_NOT_FOUND` instead of a metadata decode failure. That fixes `pnpm view`/`pnpm info` for unpublished packages and keeps workflows like Changesets from aborting on a recoverable registry response.

### **Fresh install summaries only show what changed** (d559537)
A project with no previous install no longer gets a full dependency list in the summary output; it now reports only the dependencies that were actually added or changed. This brings single-project installs in line with workspace behavior and makes first-run summaries much less noisy.

### **Global virtual store dependents are now checkout-scoped** (20a4bde)
Injected workspace dependencies in the global virtual store now include the lockfile directory in their identity, so dependents don’t accidentally reuse a copy from another checkout. This fixes peer-resolution bleed-through between workspaces while preserving sharing for unrelated packages.

### **Package policy version matching now normalizes exact SemVer input** (a793061)
pnpm now normalizes exact versions in policy selectors after SemVer parsing, preserving prerelease identifiers while dropping build metadata to match npm’s recorded version form. That keeps exclusions, trust checks, release-age checks, and related policy logic from drifting on equivalent version spellings.

### **Registry-route state now avoids repeated frozen/filtered reinstalls** (3e79a42)
pnpm now distinguishes the registry routes used to validate an install from the routes used to resolve the lockfile, which avoids getting stuck in repeated reinstall checks after registry changes. The fix covers frozen installs and filtered installs before `run`/`exec` commands.

### Other misc changes
- Added docs for `overrides` syntax and selector parsing.
- Rejected override selectors with multiple parent delimiters.
- Fixed local dependency path handling when names contain parentheses.
- Fixed concurrent CAS blob repair to preserve completed bytes.
- Narrowed Rust core-crate test selection for faster testing.
- Bumped dependencies, Node.js, pnpm, and GitHub Actions pins.
- Improved license/policy/config plumbing and related test coverage.
