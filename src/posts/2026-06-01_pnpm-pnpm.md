### **Pacquet gains pnpmfile hooks support** (5c669d7)
Pacquet now discovers `.pnpmfile.mjs`/`.pnpmfile.cjs` and runs project hooks during dependency management, bringing it in line with pnpm’s `readPackage`/`filterLog` behavior. This is a major extensibility step that lets repositories customize resolution and manifest handling without forking the installer.

### **Lockfile reuse avoids re-resolving unchanged subtrees** (73a294e)
Non-frozen installs now reuse prior lockfile resolutions and transitive subtrees when dependencies are still satisfied, instead of re-hitting the registry for everything. That should make repeat installs faster and more resilient when the registry is unavailable for parts of the graph.

### **Pacquet implements `outdated`** (ae6e077)
A new `outdated` command reports direct dependencies whose published versions have moved ahead of the lockfile, and exits non-zero when anything is stale. This widens pacquet’s CLI coverage and gives users a way to audit dependency drift without performing an install.

### **Pacquet ports `remove`/`uninstall`** (12b7201)
The CLI and package-manager layers now support removing dependencies from both `node_modules` and `package.json`, including pnpm-style aliases and save-target flags. This fills another core package-management gap and makes pacquet much more usable for day-to-day dependency editing.

### **`update` now respects workspace ignore rules** (0b49084)
`pacquet update` now honors `updateConfig.ignoreDependencies` when no explicit package selectors are provided, matching pnpm’s behavior. That matters because it preserves pinned dependencies during broad updates while still allowing explicit overrides.

### **Pacquet ports the `update` command** (0a4d665)
The update workflow now supports compatible bumps, `--latest`, and interactive selection, moving pacquet beyond install/add/remove into full dependency maintenance. It also wires update semantics through the resolver and package-manager layers, which is a substantial CLI and engine expansion.

### **Remote tarball integrity is preserved on re-resolution** (6f382f4)
When a remote tarball dependency is re-resolved without being re-fetched, pacquet now carries forward the previously recorded integrity if the tarball URL is unchanged. This fixes a lockfile regression that could otherwise break later installs with missing-integrity errors.

### **Workspace state writes are now atomic** (37669c2)
Pacquet now writes workspace state through a temp file and rename, instead of directly overwriting the cache file. That closes a race where concurrent readers could observe a torn file and crash.

### **`pnpm publish` normalizes string `repository` fields** (33921c8)
Publishing now converts a string `repository` entry into the object form registries expect, matching npm’s normalization. This avoids registry-side failures for packages that still use the shorthand string format.

### **`pnpm audit` prunes traversal work earlier** (719cc21)
The audit path enumerator now stops walking branches once all reachable vulnerabilities have already saturated the per-finding path cap, and it avoids redoing some reachability work. This is a performance win for large lockfiles with repeated or cyclic structures.

### **Headless lifecycle scripts get a user agent** (118e9be)
Lifecycle scripts run in headless installs now receive a user-agent value. That helps scripts and tooling distinguish pnpm/pacquet-driven execution from plain node processes.

### **Concurrent add-user overwrite in pnpr is fixed** (71eea4d)
The pnpr auth flow now avoids overwriting a returning user during concurrent add-user verification. The refactor also deduplicates the shared verification path, tightening correctness around a race-prone login flow.

### Other misc changes
- Dependency bumps and workspace manifest updates
- CI/test harness tweaks for hooks and command coverage
- Small internal refactors and helper extraction
- New/expanded tests across updated resolver and CLI paths
