### **Node.js runtime downloads are now signature-verified** (3d50680)
pnpm now verifies the detached OpenPGP signature of `SHASUMS256.txt` before trusting Node.js runtime hashes. This closes the mirror-tampering gap for `devEngines.runtime` / `useNodeVersion`, where pnpm downloads and executes a Node binary for lifecycle and script runs.

### **Package-manager bootstrap metadata is hardened** (822beb5)
Package-manager auto-switch and env-lockfile handling now use trusted user/CLI registry and network settings instead of repository-controlled `.npmrc` values. pnpm also rejects malformed package-manager env-lockfile records so bootstrap execution can’t be steered through untrusted registry metadata.

### **Package-manager binaries are verified before execution** (5f2bb9f)
pnpm now checks npm registry signatures before spawning the Rust install engine or a downloaded pnpm version. That means repository-controlled inputs can no longer point pnpm at an arbitrary native binary without passing signature verification first.

### **Untrusted registry/env expansion is blocked** (1017c36)
Environment placeholder expansion is now trust-aware for registry/proxy destinations and credential values. Repository-controlled config can no longer expand `${...}` into request targets or registry auth settings, reducing the chance of untrusted config redirecting network traffic.

### **Reserved bin names are rejected** (230df57)
Package `bin` entries named `""`, `"."`, `".."`, and scoped variants like `@scope/..` are now filtered out. This prevents global bin operations from resolving those names to the bin directory itself or its parent and deleting unrelated files.

### **Pacquet gains configDependencies support** (ea204b0)
The Rust install path now supports `configDependencies` end-to-end, including pre-install resolution, env lockfile recording, and `updateConfig` hooks before the main install. This is a substantial feature parity step that lets pacquet handle workspace-level config dependencies like pnpm does.

### **Overrides are applied during fresh pacquet resolution** (d188316)
pacquet now applies `pnpm.overrides` during fresh-lockfile resolution and records catalog-resolved override values in the lockfile. It also avoids reusing stale lockfile subtrees when overrides change, fixing an important correctness gap.

### **Pacquet writes patchedDependencies into lockfiles** (8c9edf2)
Fresh pacquet lockfiles now include the top-level `patchedDependencies` block, matching pnpm’s lockfile shape. This removes a divergence that previously made `--lockfile-only` output inconsistent with normal installs.

### **Pacquet records pnpmfile checksums** (b730835)
Lockfile generation now emits `pnpmfileChecksum` when a project exports pnpm hooks. That aligns pacquet’s lockfile metadata with pnpm byte-for-byte and improves lockfile round-tripping.

### **Pacquet lockfiles now match runtime dependency formatting** (a06adee)
Runtime dependency entries now serialize more like pnpm, including stripping the `node@` prefix and preserving the expected `runtime:<ver>` format. This fixes lockfile round-tripping for `node@runtime:<ver>` dependencies.

### **Peer dependency context handling is aligned** (b1a6f4d)
Pacquet’s peer-resolution logic was updated to better match pnpm’s treatment of same-package providers, peer diamonds, and aliased providers. This should reduce incorrect peer tree shaping in complex dependency graphs.

### Other misc changes
- Security-related release gates and embedded signing-key update scripts
- Test coverage updates across lockfile, resolver, and global-bin paths
- Small Rust/TypeScript plumbing and dependency manifest adjustments
