### **pnpm install gets a real `--dry-run` preview** (c112b61)
`pnpm install` now supports an npm-style dry run that resolves dependencies and reports what would change without writing a lockfile, `node_modules`, or workspace state. This is a significant UX addition for safely previewing installs before making changes.

### **Local file dependency changes are detected again** (6d35338)
The optimistic repeat-install fast path now treats projects with `file:` or local-path/tarball dependencies as outdated, so edits inside those dependencies stop being missed. This fixes a real correctness regression where installs could incorrectly claim "Already up to date" after local dependency content changed.

### **Lockfile-only changes no longer get skipped on repeat install** (61969fb)
`checkDepsStatus` now notices modified wanted lockfiles even when manifests are unchanged, including git-branch lockfiles and merge-conflict cases. That closes a hole where checkout/restores of just `pnpm-lock.yaml` could incorrectly short-circuit the install.

### **pacquet now runs dependency build scripts on fresh-lockfile installs** (d36b6f8)
The Rust installer now invokes build modules on the fresh-lockfile path, matching pnpm behavior for `add` and non-frozen installs. Without this, approved lifecycle scripts never ran and blocked build scripts were silently ignored.

### **pacquet adds `--ignore-scripts` for installs** (7cd5594)
Pacquet now exposes the same escape hatch pnpm users expect when build scripts would otherwise fail under `strictDepBuilds`. It suppresses dependency and project lifecycle scripts while still materializing packages, making installs possible without approving every build.

### **Ecosystem E2E harness now exercises pnpm and pacquet** (70f1343)
A new scheduled cross-product test harness installs and builds real JS frameworks across both CLIs and both virtual-store layouts. This is a high-value regression net for parity gaps and global-virtual-store breakage.
