**pnpm now reports unknown workspace settings and can fail fast on pinned projects** (2988490)
`pnpm-workspace.yaml` settings that this version doesn’t recognize are now classified more precisely, instead of being lumped into a generic “move this to workspace config” warning. In projects pinned to a pnpm version that already satisfies the running binary, unrecognized workspace settings become a hard error, which helps catch typos and version-mismatch config drift.

**`pnpm config get/list` now expose the settings pnpm actually uses** (cae239c)
Config output now shows resolved registries, catalogs, `registry`, `@scope:registry`, and the effective `update`/`audit` settings under the documented names instead of raw internal keys or `undefined`. This makes config inspection match runtime behavior and removes a long-standing source of confusion when debugging registry and workspace config.

**Workspace discovery again includes parent-relative package globs** (a634b1c)
Projects declared above the workspace root with patterns like `../shared` or `../../docs/*` are discovered again instead of being silently dropped. That fixes broken `--filter`/recursive listings and prevents frozen installs from failing when the lockfile already contains those importer paths.

**`pnpm install <pkg>` now behaves like `pnpm add <pkg>`** (aac6b38)
Install commands with package names are rewritten so the package is parsed by `add`’s grammar instead of erroring as an unexpected positional. This restores the expected shorthand behavior for users who type `pnpm i some-package`.

**Updates now preserve prerelease range operators** (9e49bbf)
When updating prerelease dependencies, pnpm keeps the existing range style, so `^3.0.0-rc.0` stays a caret range after the version bumps. That keeps manifests stable and avoids surprising rewrites when updating prerelease packages.

**`self-update` now bumps simple package-manager ranges in place** (bd2d0b7)
`pnpm self-update` now rewrites simple `^`/`~` `devEngines.packageManager.version` ranges when the new version still satisfies them, matching other update flows. Complex ranges remain pinned as before.

**`modules.yaml` can be read again even with very long dependency keys** (1e5732c)
The `.modules.yaml` reader now tries JSON first and only falls back to YAML for older manifests. That avoids YAML’s simple-key length limit and fixes reads for manifests containing long dependency paths.

**`pnpm remove` now prunes undecided `allowBuilds` entries** (bb4eecf)
When removing a package from a shared-workspace-lockfile repo, pnpm now cleans up `allowBuilds` placeholders that were still marked “set this to true or false.” Intentional `true`/`false` decisions are preserved.

### Other misc changes

- `preferSymlinkedExecutables` support landed in pacquet and related CLI plumbing
- Misc cleanup for tarball header handling, hooks cache isolation, and workspace manifest writing
