### **POSIX shims now preserve Windows-style paths** (f9c86ff)
Switching the shim header from `echo` to `printf` prevents backslashes in Windows-form paths from being mangled before normalization. This fixes broken POSIX cmd shims on some shells/systems and ensures reinstalling can replace stale shims correctly.

### **`pnpm deploy` now writes cleaner registry specifiers** (7aa4734)
Deploy output now keeps plain versions in the deployed `package.json` for registry dependencies with peers, while preserving resolved peer bindings in the lockfile. It also keeps npm alias targets intact and applies the same normalization in both the Rust and TypeScript deploy paths.

### **Python installs no longer fail on unparsable `Requires-Python`** (417601d)
A malformed `Requires-Python` value is now treated like no interpreter constraint instead of aborting resolution, matching pip’s behavior. This unblocks packages like `openpyxl` 3.0.x whose metadata contains an invalid trailing comma.

### **`pnpm add <git repo>` now names manifest-less repos by owner** (f87ae88)
Git dependencies that ship no `package.json` are now synthesized as `@owner/repo` instead of just `repo`, avoiding collisions between repositories with the same name. That makes alias-less git adds more robust and keeps the dependency key tied to the source identity.

### **`pnpm install <pkg>` now accepts `--prod` and `--dev`** (4e60888)
Package installs invoked through `install`-as-`add` can now take the same dependency-group filters as plain `install`, including `--prod=false`. This removes a parser mismatch that previously rejected valid install spellings with a package argument.

### **`update --no-save` now preserves override-applied specifiers** (251a9ee)
When `pnpm update --no-save` rewrites the lockfile, it now applies overrides to the importer snapshot before serializing specifiers. That prevents the next frozen install from rejecting a lockfile that was just written.

### **Peer walking stops at linked workspace packages** (3c0f092)
Peer inspection no longer walks past `link:` edges into shared linked workspace packages, avoiding repeated re-traversal of the same projects. This fixes a major workspace performance regression in both installs and `pnpm peers check`.
