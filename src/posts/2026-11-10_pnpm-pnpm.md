### **Bundle node-gyp with patched undici** (8813abc)
pnpm now overrides node-gyp 12’s undici dependency to undici 7 so bundled node-gyp picks up the CVE-2026-84947 fix. This affects both the TypeScript and Rust CLIs, since they share the same lockfile and bundled node-gyp.

### **pnpr now reclaims abandoned publish staging files** (009dd02)
pnpr sweeps stale upload staging files at startup, periodically while serving, and during cache GC instead of waiting for a fixed 24-hour window. That reduces orphaned disk usage after crashes or cancelled publishes and makes recovery more deterministic.

### **Malformed JSON now returns 400 instead of 502 in pnpr** (e4db65a)
Request-body parsing now treats client-supplied malformed JSON as a bad request across user, token, publish, staged publish, packument, and audit endpoints. This removes misleading 502s and keeps upstream/stored JSON corruption separate from client input errors.

### **pnpr GC dry runs stop counting shared OCI blobs as removable** (a3d6cbf)
Dry-run OCI collection now excludes blobs still kept by another repository in the same namespace before reporting removals. That makes `pnpr gc --dry-run` match what a real collection can actually reclaim.

### **pnpr startup errors are now actionable** (2b441c3)
Startup validation now rejects missing database drivers and insecure token transport earlier, and connection failures include the target plus redacted cause details. It also preserves the last driver failure on timeout so operators get a usable root cause instead of a generic startup error.

### **Cargo owner operations now fail explicitly** (064790d)
pnpr now returns a clear unsupported-operation Cargo error for GET, PUT, and DELETE on the owners endpoint. That avoids ambiguous behavior and documents the current limitation instead of implying owner management is implemented.

### **Hosted Python wheels now serve core metadata correctly** (81ab79e)
pnpr stores validated wheel core metadata as a separate sidecar blob and serves it through the Python Simple API without re-parsing every wheel on each request. This improves correctness and avoids extra work on file and page requests, while ensuring metadata access disappears when the file is deleted.

### **PostgreSQL and MySQL auth backends are built by default** (673ff67)
The pnpr crate now enables the PostgreSQL and MySQL backend features by default, matching what the release workflow, Docker image, and installs are expected to support. That fixes startup failures for `postgres://` and `mysql://` configs in published binaries.

### **pnpr can configure upstream tarball size limits** (39e73ae)
A new `maxTarballSize` setting lets operators cap how large an upstream tarball pnpr will fetch before rejecting it with 502. The default remains 100 MiB, but now it’s configurable for packages with legitimately larger binaries.

### **libSQL auth no longer breaks after idle or restart** (f082201)
pnpr’s libSQL pool now handles stale Hrana streams by avoiding reuse of dead batons and refreshing connections as needed. That fixes 500/503 failures after a quiet period or after the remote database restarts.

### **PostgreSQL/MySQL metadata writes now queue instead of failing** (3bd6d80)
Concurrent metadata writes now wait on the database’s write lock instead of racing into serialization errors or deadlocks. This removes a major source of 500s during concurrent publishes and OCI blob uploads on PostgreSQL and MySQL.

### **Legacy git build flags are rechecked consistently** (b90d235)
Store-status logic now interprets legacy git build metadata the same way installation already does, instead of flagging ambiguous rows incorrectly. The change also reuses the manifest reader path so CLI versions stay aligned.

### **Lockfile v13 regains stable blank-line and multi-line formatting** (72436fc)
The v13 lockfile writer now restores blank lines between top-level sections and writes dependency, peer, and catalog maps across multiple lines. This improves diff context and reverses the earlier compact formatting change.

### **Version-selector overrides now apply to catalog dependencies** (35d6bb6)
Overrides like `pkg@^2.0.0` now resolve against `catalog:` specifiers before matching ranges, so catalog-backed dependencies are overridden the same way as regular ones. That closes a correctness gap in both the Rust and TypeScript codepaths.

### **Lockfile v13 drops blank lines between entries** (b4226bc)
The next-format lockfile emitter stops inserting blank lines between entries, relying on each entry’s closing line for diff context instead. This is a format simplification rather than a behavior change.
