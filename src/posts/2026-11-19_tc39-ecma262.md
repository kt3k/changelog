### **New abstract operations for option handling** (fbfdb76)
ECMA-262 now defines `GetBooleanOption`, `GetStringOption`, and `ValidateStringOption` as shared abstract operations. They centralize the common patterns for reading option objects, applying defaults, and rejecting invalid values, and are already used to simplify several existing algorithms.

### **Option parsing in multiple APIs now goes through the new helpers** (fbfdb76)
Several algorithms were rewritten to use the new validation ops instead of open-coded property reads and ad hoc checks, including `Symbol.toPrimitive`, `String.prototype.normalize`, and the base64 decode/encode option handling. This reduces duplicated spec text and makes the behavior around defaults and invalid option values more consistent.

### **Synthetic module evaluation now initializes `PrivateEnvironment`** (d4569d5)
During module evaluation, the new module execution context now explicitly sets `PrivateEnvironment` to `null`. That fills a missing initialization step in the execution-context setup for synthetic modules.

### **Editorial fixes for regular-expression static semantics** (af42440)
The `BodyText` and `FlagText` static semantics clauses were clarified to say “ECMAScript source text” and to use “matched by” wording. This is a wording cleanup only, but it makes the prose more precise.

### **Template string note corrected for invalid escapes** (2fa3089)
A note about template literal TV behavior now correctly says `undefined` is returned when `_escapes_` is `~cooked~`, not `~raw~`. This fixes an editorial error in the description of invalid escape handling.

### **Project editor credits expanded** (74c33d4)
The front-matter credits were updated to recognize early project editors, and Allen Wirfs-Brock’s entry was adjusted to cover both the 5th and 6th editions. Purely editorial, but it improves the historical record.

### **Other misc changes**
- CI and formatting updated to include `*/*.emu` files in checks and `npm run format`.
- Alias-abbreviation checking now scans multiple spec files instead of only `spec.html`.
- Minor editorial typo/auto-link cleanup in spec text.
