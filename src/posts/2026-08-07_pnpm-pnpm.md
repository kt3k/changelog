**Fast-path lockfile updates now avoid unnecessary re-resolves** (654af93, fa6a7b2)
Catalog version changes and removed dependencies can now be applied directly to the lockfile when the graph allows it, instead of falling back to full resolution. That cuts registry work for common install edits and prunes dead lockfile state more aggressively.

**Lockfile verification now respects offline mode** (745924b)
Verification of npm metadata no longer reaches the registry when offline; it uses cached metadata and returns `ERR_PNPM_NO_OFFLINE_META` if the cache is cold. This keeps frozen/offline installs consistent with offline resolution.

**Windows symlink and removal handling is more robust** (3bbefa9)
Installs now fall back to NTFS junctions when symlink creation lacks privilege on Windows, instead of failing with os error 1314. The same fix also removes package links correctly during `clean` and `deploy`, avoiding os error 5 on link deletion.

**Loose minimumReleaseAge picks are persisted to workspace config** (7e189d6)
When a resolve allows immature versions in loose mode, pnpm now records the chosen exclusions in `pnpm-workspace.yaml`. That prevents later frozen installs from failing verification on the same lockfile.

**Global path commands stay machine-readable in pnpm 12** (997ba59)
`pnpm root -g`, `bin -g`, and related commands now send warnings to stderr so stdout remains a clean path value. pnpm 12 also gains support for `root -g` and `prefix -g`, matching the behavior users expect from global path queries.

**Headless installs react properly to removed packages** (2d7efe3)
When a lockfile-only update removes dependencies, the later headless install now recomputes hoisting and clears stale pending builds. This fixes cases where packages stayed unhoisted or forever pending after removals.
