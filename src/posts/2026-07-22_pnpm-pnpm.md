### **Recursive install-family commands now work with dedicated lockfiles** (b67b1a9)
`pnpm install`, `add`, `update`, and `remove` no longer fail in workspaces configured with `sharedWorkspaceLockfile: false` when run recursively or with filters. The new dispatch path can now choose between single-project, shared-lockfile, and per-project execution, so selected projects are processed independently instead of being blocked.

### **Recursive rebuild now honors workspace selection** (ea75ed7)
`pnpm rebuild` now routes recursive runs through workspace project selection for both shared and dedicated lockfile setups. That brings its behavior in line with other workspace commands and preserves concurrency/topology handling instead of rebuilding an unselected state.

### **Unlink now follows the install pipeline** (d9db22f)
`pnpm unlink` now strips matching `link:` overrides and then reinstalls through the same selection-aware install pipeline used elsewhere. This fixes recursive and per-project lockfile cases, and ensures the removed links are re-resolved from the registry.

### **First release now publishes the manifest version verbatim** (3d28129)
New packages are now released at the version written in their manifest instead of being bumped past it on debut. That avoids silently skipping a package’s intended band-floor release and fixes version/status checks so unpublished packages can first ship at their exact manifest version.

### **`pnpm view` accepts `--registry`** (66ae0f0)
`pnpm view` now honors the `--registry` flag instead of rejecting it as an unknown argument. This also makes the recursive-publish registry probe hermetic and matches the TypeScript CLI’s behavior.
