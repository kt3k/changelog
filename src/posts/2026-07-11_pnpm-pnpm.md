### **pnpr access control goes native and stricter** (3acb421)
`pnpr`’s registry access config now uses native token parsing with reserved `$` built-ins, rejecting Verdaccio-style aliases and typo-prone forms at load time. It also changes access/team lists to token-based parsing and moves teams to registry-scoped `teams:` maps, making policy behavior more explicit and preventing silent misconfigurations.

### **readPackage hooks now get the resolved directory** (3e01bc5)
The NAPI hook bridge now forwards an optional `resolvedDir` for directory/file-based dependency resolutions, and keeps it unset for registry resolutions. That lets hooks distinguish workspace/local package instances more reliably, while the public type signatures and tests were updated to match.

### **Peer hoisting now respects declared ranges** (252f15e)
Peer auto-installation no longer grabs an arbitrary higher preferred version if it doesn’t satisfy the peer’s semver range. This fixes cases where one workspace project could silently inherit an incompatible major from another, and also aligns lockfile-based re-resolves with fresh installs when hoisted peer providers are already present.

### **Peer resolution deadlocks from await cycles are fixed** (3c6718b)
A peer-dependency cycle that spans resolution passes could previously hang installs forever. The resolver now breaks those cross-pass cycles correctly, preventing deadlocks in cases where a project dependency and a hoisted or tree-positioned peer provider depend on each other.

### **CLI gaps that broke release workflows are closed** (54efed0)
Pacquet’s CLI argument handling was expanded to accept flags in positions the release scripts actually use, including deploy/pack/publish flows and flag relocation behavior. This fixes the release pipeline’s real-world invocation patterns instead of failing on clap parsing before the subcommand runs.

### **Unscoped pnpm wrapper now resolves its native trust root correctly** (bcb8b5a)
The self-update/native-binary trust lookup now handles the unscoped `pnpm` wrapper’s virtual-store layout correctly. That avoids falling back to the wrapper’s own slot and ensures the sibling-slot native binary is trusted from the intended root.

### **Same-name injected deps now serialize as plain file refs** (7da1dfc)
When an injected workspace dependency’s alias matches the package name, lockfiles now write a plain `file:` reference instead of an alias-prefixed form. That keeps lockfile output cleaner and avoids unnecessary alias noise while preserving the old behavior for true renames.

### **Top-level `--if-present` is accepted and root scaffolding is fixed** (b2b1cf6)
The CLI now accepts `--if-present` before the script name the way pnpm users expect, which unblocks workspace CI flows that relied on that spelling. It also stops workspace installs from scaffolding a root manifest in the affected path.

### Other misc changes
- pnpm version bump to v12.0.0-alpha.8, plus another internal update
- Full CLI rename/rebrand to `pnpm` across release tooling, workflows, and binaries (including `pacquet` artifact path updates)
- Release/changelog/package metadata cleanup for 11.12.0
