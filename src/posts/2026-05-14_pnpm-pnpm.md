### **Pacquet gains hoisted installs end to end** (2c8f8ad)
The install pipeline now branches on `nodeLinker=hoisted`, threading hoisted dependency-graph output, per-package CAS paths, and per-snapshot package roots through virtual-store creation and module building. This is the core plumbing needed to materialize hoisted `node_modules` trees and run lifecycle scripts correctly in that mode.

### **Offline and prefer-offline flags are now wired in** (6290080)
`pacquet install` now accepts `--offline` and `--prefer-offline`, with config parsing and CLI overrides merged before state initialization. The implementation enforces offline behavior for tarball fetch misses today, setting up the resolver-side metadata gating that mirrors pnpm more closely later.

### **Optional dependency siblings now get linked into slots** (ceec335)
`create_symlink_layout` was expanded to merge regular and optional dependencies, skip self-links, and ignore skipped snapshots. This fixes missing platform-specific sibling binaries in package slots, which previously broke resolution for packages that rely on optional dependency variants.

### **pnpm v11 combined lockfiles now parse correctly** (da65e62)
The lockfile loader now strips pnpm v11’s leading env-only YAML document and treats empty main documents as absent lockfiles. That unblocks frozen installs against repos using the newer multi-document lockfile format.

### **minimumReleaseAge no longer slips through cached abbreviated metadata** (e526f89)
The npm resolver now upgrades abbreviated cached metadata to full metadata when release-age checks need `time` fields, including on 304 responses and in offline/prefer-offline cache paths. It also persists the upgraded metadata, preventing repeated bypasses of the maturity check on later installs.

### **Hoisted bin precedence and top-level relinking are implemented** (fb221c6)
Bin linking now distinguishes direct versus hoisted origins so direct binaries win deterministically, and top-level bins get re-linked after build for hoisted installs. That closes a major gap in command resolution for the hoisted linker.

### **Workspace hoisting is now supported** (6db0430)
The hoisted linker now handles multi-importer workspace lockfiles instead of rejecting them outright. The change shares one hoist plan across the workspace, enabling dedupe across projects and per-importer module tree materialization.

### **Build phase support for hoisted installs is restored** (6018359)
`BuildModules` now understands hoisted package roots and gathers ancestor bin paths so lifecycle scripts can resolve binaries from parent `node_modules/.bin` locations. Without this, hoisted installs could link dependencies but still fail during package build scripts.

### **Network requests strip Azure DevOps-breaking sec-fetch headers** (18a464f)
pnpm’s fetch layer now removes `sec-fetch-*` headers before dispatching requests, avoiding Azure DevOps Artifacts 400 responses on uncached upstream packages. This is a user-facing networking fix for registry compatibility.

### **Named catalog upgrades preserve the original catalog group** (8c06d1a)
Interactive `--latest` upgrades now keep packages in their original named catalog instead of rewriting them to the default catalog. This prevents upgrades from landing in the wrong catalog and changing package.json semantics unexpectedly.

### **Optimistic installs now handle lockfile conflicts** (180aee9)
The dependency status path was fixed to correctly detect and surface lockfile conflicts during optimistic install flows. This removes a correctness hole in the install conflict handling path.

### **Published-at timestamps survive fast-path resolution** (c2c2890)
Time-based resolution now preserves `publishedAt` values when packages are resolved through the fast path. That keeps minimum-release-age behavior consistent across resolution paths.

### **Hoisting knobs are wired through config and graph building** (1ad6ffd)
`hoistingLimits` and `externalDependencies` are now plumbed from workspace config into the hoisted dependency graph and installer. This exposes more of the hoist behavior needed for programmatic or advanced workspace setups.

### **Pacquet repository plumbing is fully integrated** (763ddf1, 4a89b06, 1575076, a4f3c6d, 9844cdf, d2b64b6, e8fc343)
The imported pacquet repo was moved into the monorepo root, its workflows retargeted and hardened, release flows converted to manual triggers where needed, and CI/security scanning tightened. A Windows test-shell fix also prevents a silent no-op in the test matrix.
