### **Persist registry users and tokens to disk** (0cefccf)
pnpm's registry auth is no longer purely in-memory: users are stored in a verdaccio-shaped htpasswd file with bcrypt hashes, and tokens are backed by SQLite with hashed secrets plus metadata for the upcoming token API. That makes add-user/token flows survive restarts and brings the mock registry much closer to real-world behavior.

### **Fail closed on tarball integrity mismatches** (aa6149d)
pnpm install now treats a lockfile tarball-integrity mismatch as a hard error by default instead of silently re-resolving and overwriting the recorded hash. A new `--update-checksums` escape hatch exists for intentionally refreshing lockfile integrity values, but force/update flows do not bypass the check.

### **Preserve default publish access for scoped packages** (c94b4f8)
Publishing now distinguishes between an explicit access value and an absent one, so scoped packages without `publishConfig.access` no longer get forced to public. This fixes a release-time behavior bug that could accidentally publish scoped packages with the wrong access level.

### **Other misc changes**
- Reuse `node_modules/.pnpm/lock.yaml` when `pnpm-lock.yaml` is missing and still satisfies the manifest; keep frozen installs failing in that case (a33c4bf)
- Release `11.4.0` and clean up released changesets (72d997c)
- Dependency/catalog lockfile updates and workspace package bumps (b73908f)
