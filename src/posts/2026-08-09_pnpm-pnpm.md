**Global bins can now follow the project they run in** (8a453e3)
Globally installed executables can be linked as context-aware shims that dispatch based on the current project, with the new `globalShims` setting controlling which package names opt in. This enables project-pinned runtimes to be honored for global tools, while preserving direct shims for everything else.

**Managed runtime shim startup gets faster** (1cc8018)
The libc detector now reads only the ELF header, program headers, and interpreter path from `/proc/self/exe` instead of slurping the whole executable. That trims warm startup overhead for project-aware runtime dispatch without changing the fallback behavior for malformed or unsupported ELF files.

**POSIX shims now preserve signal deaths again** (a2c6d26)
The shell shim now `exec`s targets without an interpreter instead of waiting on them, so a SIGKILL or other signal reaches callers as a real signal status rather than a misleading `128+N` exit code. That matters for CI and supervisors that distinguish signal termination from ordinary exits.

**`pnpm setup` stops emitting module-type warnings** (4a5a10d)
The standalone manifest written beside the executable now includes `"type": "module"`, which prevents Node.js from warning about reparsing `dist/worker.js` as CommonJS on every spawn. This removes a noisy startup warning from the standalone install path.
