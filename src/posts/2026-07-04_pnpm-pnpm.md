### **pnpm now prints a bare version and accepts `-v`** (2b5e9bc)
`pnpm --version` and `pnpm -v` now match pnpm's long-standing behavior by printing just the version string, without clap's `pnpm 12.0.0-alpha.0` prefix. That preserves scripts and tooling that parse the output and fixes the short flag mismatch.

### **New `pnpm peers` command checks peer dependency issues** (ebb4096)
A new CLI command walks the lockfile to report unmet or conflicting peer dependencies, including `peerDependencyRules` handling and deterministic output. It exits with status 1 when issues are found, so it can be used directly in CI and mirrors the TypeScript CLI behavior.

### **Targeted updates now re-resolve like a fresh install** (dcabb78)
`pnpm up <pkg>` no longer lets lockfile-derived preferred versions leak into the targeted package's resolution, which could bump unrelated dependencies or produce results that differed from a clean install. This also adds a warning when `pnpm update <dep>@<version>` is used for a purely transitive dependency, since that version can't be pinned there.

### **Offline resolver caching cuts repeated metadata parsing** (11a7fdd)
When resolving from the on-disk cache in `--offline` or `--prefer-offline` mode, package metadata is now cached in memory too. That avoids re-reading and re-parsing the same packument once per dependent, which is a meaningful speedup on large workspaces.

### **Non-abbreviated registry metadata is normalized before caching** (99982b9)
For registries that ignore npm's abbreviated metadata request and always return the full packument, pnpm now strips the response down to the abbreviated field set before caching it. This reduces memory use and speeds later resolutions without changing resolver output.

### **Included-deps changes no longer wipe a project's `node_modules`** (84cf84c)
Switching between `--prod`, full installs, or `--no-optional` no longer triggers a destructive purge of the root project's `node_modules` just because the recorded `included` set changed. Instead, pnpm relinks the newly-included packages and prunes only the direct deps that should no longer be present.

### **Release workflow and pack/app packaging were hardened** (b7908f9, 276d634, 2f389d6, e36ae78)
The Rust release flow now stages wrapper package publishing separately to avoid npm trusted-publisher conflicts, and the pack-app config was moved so its paths stay inside the packed project. The release PR workflow also refreshes embedded signing keys automatically, and generated native packages now declare the MIT license correctly.

### **`patch` paths now resolve from the lockfile directory** (ce5d5a5)
Relative `patchedDependencies` entries are now resolved against the lockfile directory when hashing and applying patches. That fixes installs started from subdirectories that previously looked for patch files in the wrong place.

### **Hook logging is forwarded to the default reporter** (fdfe172)
`preResolution` hook `info`/`warn` output now flows through pnpm's hook channel instead of disappearing from the default reporter. The Rust hook runtime and reporter state were updated to carry and render those events consistently.
