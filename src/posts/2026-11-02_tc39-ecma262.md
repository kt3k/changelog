### **Dynamic code brand checks reach eval and Function** (2af59ff)
The spec now lets hosts inspect non-string inputs to `eval` and the Function constructors via a new `HostGetCodeForEval` hook, and passes richer context into `HostEnsureCanCompileStrings`. This enables host-defined code branding/translation behavior and updates the eval/function-creation pipeline accordingly.

### **Eval compilation type is now an enum** (4ad14cf)
`PerformEval` and `HostEnsureCanCompileStrings` now use explicit compilation-type enum values (`direct-eval`, `indirect-eval`, `function`) instead of booleans. That makes the control flow and host hook contract clearer, while also aligning the spec text and tooling ignores with the new signatures.

### **Typed array initialization from iterable/array-like consolidated** (ddf5b5c)
The spec merges the separate list and array-like initialization paths into a single `InitializeTypedArrayFromElements` operation. This simplifies the typed array construction rules while preserving the iterable-vs-array-like behavior.
