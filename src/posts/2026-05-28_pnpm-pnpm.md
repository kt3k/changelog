### **Hoisted installs gain fresh-lockfile support and hoisting limits** (a39a83d)
`nodeLinker: hoisted` now works on fresh installs, removing the previous hard refusal on the no-lockfile path. The new `hoistingLimits` setting adds Yarn-like control over how far packages are hoisted: `none`, `workspaces`, or `dependencies`.

### **pacquet ports `dedupeInjectedDeps`** (ddf4ec4)
Injected workspace deps now dedupe back to `link:` when the target package is effectively a subset, matching pnpm's behavior end to end. The setting is configurable, and the port rewires resolver, lockfile, and install flows to handle injected workspace packages consistently.

### **pacquet ports `dedupeDirectDeps`** (bf3cc86)
Workspace direct dependencies can now be deduped against the root package when they resolve to the same target, with an opt-out via `dedupeDirectDeps: false`. This changes install layout behavior and avoids creating unnecessary per-project `node_modules/` trees.

### **`packageExtensions` arrives in pacquet** (2cca6ab)
Pacquet can now read and apply `packageExtensions` from workspace config, merging extra dependency metadata into matching manifests at resolution time. That unlocks a major pnpm compatibility knob for fixing package metadata without patching upstream packages.

### **`injectWorkspacePackages` is now supported** (a0eb2ad)
Workspace deps can be injected as `file:` copies instead of `link:` symlinks, including per-dependency overrides via `dependenciesMeta`. This is a substantial install-layout change and required resolver, lockfile, and freshness handling updates.

### **`peersSuffixMaxLength` is wired through** (4b60515)
Pacquet now honors the peer-suffix length cap from workspace config, env vars, and lockfile settings instead of hardcoding the default. This affects how peer dependency paths are rendered and persisted, so it can change lockfile output.

### **`preferWorkspacePackages` is now respected** (7c9a6c2)
Resolution can now prefer a local workspace package over a newer registry candidate when the setting is enabled. That changes package selection during installs and brings another pnpm workspace knob into pacquet.

### **`excludeLinksFromLockfile` lands** (82e31d6)
Pacquet now omits or remaps certain `link:` dependencies when writing the lockfile, matching pnpm's lockfile semantics more closely. This is a lockfile-shape change that matters for reproducibility and cross-platform consistency.

### **`dedupePeers` support is added** (7ecaf3d)
Peer suffix generation now supports pnpm's `dedupePeers` behavior, collapsing nested peer-path identifiers when enabled. That changes depPath rendering and lockfile output for projects with deep peer graphs.

### **pnpm-registry gets request logging, ping, auth, policy, and publish hardening** (a9011ad, eb48bfd, 8c2d53b, a593082, 87136ed)
The private registry gained structured request logging, a `/-/ping` health endpoint, user/token/profile endpoints, YAML-driven package ACL enforcement, and tarball integrity verification on publish. Together these are major parity and correctness improvements for running a real registry.

### **`pnpm dist-tag` gets web-2FA compatibility** (b1fa2d5)
Dist-tag writes now use the browser-based npm 2FA flow correctly when `--otp` is absent, instead of failing against npmjs.org. The fetch layer also avoids sending metadata `Accept` headers on write requests, fixing a registry compatibility bug.

### **Cyclic aliased peer installs no longer hang** (39101f5)
A peer-resolution bug that could stall aliased installs at 0% CPU is fixed. This closes a nasty deadlock-style failure mode in dependency resolution.

### **Excluded npm packages are revalidated instead of trusting stale mtime cache** (6235428)
The npm resolver no longer trusts the published-by mtime fast path for fully excluded packages, preventing stale metadata from pinning older versions. This is a targeted correctness fix with real fallout for version selection.

### **Workspace glob negation is fixed** (2a0032e)
`pnpm-workspace.yaml` can now handle negated package globs like `!**/tools/*` without failing parsing. That restores support for a workspace pattern form users commonly rely on for exclusions.

### **Tarball SHA verification is enforced on publish** (87136ed)
The registry now hashes uploaded tarballs and checks them against the declared integrity before accepting a publish. That closes a silent-corruption class of bugs and hardens package publishing correctness.
