### **Selector-aware overrides now support dependency types and wildcards** (08cc4f3)
pnpm v12 `overrides` can now target `:prod`, `:optional`, and `:peer`, and match package names with `*` wildcards on both the parent and target sides. That makes override rules much more precise, especially in mixed dependency graphs, and the release also tightens some override edge cases around non-range values and optional dependency removal.

### **Hosted tar registries now store published versions as zstd-compressed tar blobs** (5fb5fba)
For registries configured with `tarballs: tar`, pnpr now stores each published version as a `.tar.zst` instead of a `.tgz`, and serves either zstd bytes or a decoded tar depending on the client. This is a storage and delivery behavior change, and pnpr now rejects router configs that would incorrectly mix `.tgz` serving with hosted tar sources.

### **`update --latest` now refreshes matching package subtrees** (6214277)
When using package selectors, `pnpm update --latest` now re-resolves the locked dependencies beneath selected direct dependencies instead of leaving compatible children pinned forever. That fixes stale transitive updates while preserving the old behavior for excluded packages and peers.

### **`get-pnpm` can install without modifying PATH** (c0f945b)
`get-pnpm` gained `--no-modify-path` and `PNPM_NO_MODIFY_PATH`, letting users install pnpm into `PNPM_HOME` without changing shell config or the Windows registry. It also refuses to proceed on pnpm versions older than 12.16.0 before making any changes.

### **Install-time link restoration now works through symlinked `node_modules`** (aedf221)
`pnpm install` no longer writes broken direct-dependency or hoist links when the project’s `node_modules` is itself a symlink to another directory. The fix makes link targets resolve from the real path, which prevents installs from succeeding while leaving dangling links behind.

### **Workspace state files now use readable file modes** (64588da)
`node_modules/.pnpm-workspace-state-v1.json` is now created with normal umask-derived permissions instead of being owner-only. That matters in container workflows where one user installs and another user later runs scripts, because the old mode could make pnpm think dependencies were stale and reinstall them.

### **Project files now inherit the umask instead of being forced to 0600** (491b003)
pnpm’s atomic writers for project files now create new files with the current umask-derived permissions, fixing cases like `pnpm-workspace.yaml`, deploy outputs, patch files, and restored lockfiles becoming unreadable to other users. Existing files keep their current mode when rewritten, so the fix restores expected sharing without broadening permissions unexpectedly.

### **Security patch: deepmerge prototype poisoning is blocked** (63c0b8e)
pnpm now patches `deepmerge@4.3.1` locally to reject `__proto__` keys during merges, closing a prototype-poisoning issue in the bundled dependency. The audit policy is updated to acknowledge the upstream gap while keeping the vulnerable package usable through the patch.
