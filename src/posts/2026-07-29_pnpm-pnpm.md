### **Resolver hoist discovery goes linear** (91fb663)
A large multi-importer peer-hoist pass no longer clones the workspace tree and reruns a full peer pass per importer and round. The new shared discovery engine makes from-scratch resolution of big workspaces dramatically faster and far less memory-hungry.

### **`pnpm login` web auth now works without a TTY** (b9e7b8d)
The non-interactive guard moved out of the web-login path and into the classic username/password fallback, so terminal-less automation can complete browser-based login flows. This removes a CI/agent workaround while preserving the TTY requirement for credential prompts.

### **Installs reuse locked versions after compatible range edits** (627476d)
Compatible direct dependency and catalog range changes can now skip a full re-resolution when the locked version still satisfies the new specifier. That speeds up routine version-range edits and keeps the lockfile/specifier state consistent without paying resolver cost.

### **Lockfile parser accepts very large files** (54abb6a)
Lockfile parsing now raises serde-saphyr’s structural budgets based on the lockfile’s size, avoiding false rejections on legitimately huge files. This fixes large-workspace installs that previously died after hitting the default node limit.

### **NAPI repeat installs respect in-memory manifest changes** (0ae2001)
The optimistic repeat-install shortcut is now disabled for NAPI install flows, because callers can change manifests in memory without touching `package.json`. That ensures repeat installs still see newly requested dependencies instead of incorrectly reporting the install as up to date.

### **Deprecated-package warnings are deduped and aligned** (6eed03f)
Pacquet now reports deprecated packages only on first insertion into the resolved-package map, matching pnpm’s existing behavior and avoiding duplicate or misleading warnings at different depths. The reporter also gets recursive-install context so direct-dependency warnings use the workspace-relative form.

### **Package-manager release/publish tooling is repaired** (02f8807)
Release automation now uses the released pnpm 11.18.0 CLI for publishing, avoiding the `publishConfig.name` mismatch that broke the pacquet wrapper publish. The workflow updates also switch all pnpm/setup consumers to the revision that can install v11 from GitHub releases.
